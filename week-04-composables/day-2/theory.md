# Занятие 1. Проектирование композабла

## Разминка (10 мин): `JSON` и `localStorage`

Что выведет каждая строка?

```js
localStorage.setItem('count', 5)
typeof localStorage.getItem('count')            // 1

localStorage.setItem('list', ['a', 'b'])
localStorage.getItem('list')                    // 2

localStorage.setItem('list', JSON.stringify(['a', 'b']))
JSON.parse(localStorage.getItem('list'))        // 3

localStorage.getItem('nothing')                 // 4
JSON.parse(localStorage.getItem('nothing'))     // 5
```

<details>
<summary>Ответ</summary>

1. `'string'` — `localStorage` хранит **только строки**, число `5` превратилось в `'5'`.
2. `'a,b'` — массив превратился в строку через запятую, и обратно в массив его уже не вернуть.
3. `['a', 'b']` — правильный способ: `JSON.stringify` при записи, `JSON.parse` при чтении.
4. `null` — ключа нет.
5. `null` — `JSON.parse(null)` не падает, а возвращает `null`. Удобно: «нет данных» и «сохранён `null`» выглядят одинаково.

</details>

## Часть 1. Что должен уметь `useLocalStorage`

Прежде чем писать код, опиши, **как** композаблом будут пользоваться. Это хорошая привычка: сначала интерфейс, потом реализация.

```js
const theme = useLocalStorage('theme', 'light')

theme.value              // 'light' (или то, что сохранено раньше)
theme.value = 'dark'     // сразу сохранилось

const items = useLocalStorage('shopping', [])
items.value.push({ id: 1, text: 'Хлеб' })   // тоже сохранилось!
```

Требования:
1. возвращает **`ref`**, с которым работаешь как обычно;
2. при создании **читает** сохранённое значение по ключу, а если его нет — берёт значение по умолчанию;
3. при **любом** изменении — сохраняет, включая изменения **внутри** массива или объекта;
4. не падает, если в хранилище **испорченные** данные.

### Почему именно `ref`

Если композабл возвращает обычный `ref`, то **всё**, что ты уже умеешь, продолжает работать: `v-model`, `v-for`, `computed`, передача в props. Компонент даже не знает, что данные сохраняются. Он просто работает с `ref`, а композабл «за кулисами» следит и сохраняет.

Это хороший признак удачного композабла: его можно подставить вместо `ref([])` одной строкой, и остальной код не меняется.

## Часть 2. Две половины композабла

### Половина 1: прочитать при старте

Выполняется **один раз**, при вызове композабла:

```
getItem(key) ──► null?  ──да──► взять defaultValue
                  │
                  нет
                  ▼
              JSON.parse ──► получилось? ──нет──► взять defaultValue
                                │
                                да
                                ▼
                         начальное значение ref
```

Вспомни `parseJSONSafe` из дня 5 недели 0: она делает ровно вторую часть схемы. Её можно импортировать или скопировать в `utils/`.

### Половина 2: записывать при изменении

Сохранение — **действие** в ответ на изменение данных. Какой инструмент для этого? Вспомни главное правило дня 4 недели 2: «`computed` — вычисли, `watch` — последи и сделай».

```
ref изменился ──► watch ──► JSON.stringify ──► setItem(key, ...)
```

### Вместе

Скелет композабла:

```js
import { ref, watch } from 'vue'

export function useLocalStorage(key, defaultValue) {
  // половина 1: начальное значение
  const state = ref(/* прочитать или defaultValue */)

  // половина 2: сохранять при изменении
  watch(state, /* ... */)

  return state
}
```

Заполнить пропуски — и есть задача дня. Подсказки по нарастающей — в [hints.md](hints.md).

> Обрати внимание: композабл возвращает **сам `ref`**, а не объект `{ state }`. Это тоже допустимо, когда возвращается одно значение. Тогда пишут `const theme = useLocalStorage(...)`, без деструктуризации.

## Часть 3. Подводные камни

### ⚠️ Без `deep: true` изменения внутри массива не сохранятся

```js
watch(state, save)            // ✗ сработает только на state.value = новыйМассив
watch(state, save, { deep: true })  // ✓ сработает и на state.value.push(...)
```

Вспомни день 4 недели 2: `ref` с объектом или массивом без `deep` наблюдается только на **замену**. А в списке покупок ты пишешь `push`, `filter`, меняешь `item.bought` — это изменения **внутри**.

Проверь это сама: сделай без `deep`, добавь покупку и перезагрузи страницу. Пропала? Теперь добавь `deep`.

### ⚠️ `getItem` вернул строку, а не то, что сохраняли

Если забыть `JSON.parse` при чтении, вместо массива будет строка `'[{"id":1,...}]'`. `v-for` по строке переберёт **символы**, и на странице появится по одному символу в строке. Странный вид списка — почти всегда забытый `JSON.parse`.

### ⚠️ Испорченные данные

```js
localStorage.setItem('shopping', '{abc')   // кто-то вручную испортил в DevTools
```

Без защиты `JSON.parse` выбросит ошибку при создании компонента, и **вся страница не отрисуется**. С `parseJSONSafe` — тихо возьмётся значение по умолчанию. Это мини-задача дня: испорть значение во вкладке Application и проверь.

### ⚠️ Ключи разных данных не должны совпадать

```js
const habits = useLocalStorage('items', [])
const shopping = useLocalStorage('items', [])   // ✗ перезапишут друг друга
```

Давай ключам **понятные и уникальные** имена: `'habit-tracker:habits'`, `'shop:cart'`. Префикс с названием проекта помогает: на `localhost` у всех твоих учебных проектов **общий** `localStorage`.

### ⚠️ Что нельзя хранить

- пароли, токены, личные данные — `localStorage` читает любой код на странице и любой, кто откроет DevTools;
- очень большие данные — лимит около 5 МБ на сайт;
- функции, `Date`, `undefined` — `JSON.stringify` их теряет (день 5 недели 0). Даты храни строкой `'2026-11-05'` — так и сделано в модели привычки.

### Синхронизация вкладок (бонус)

Если открыть страницу в двух вкладках и поменять данные в одной, вторая об этом не узнает: у неё свой `ref`. Браузер умеет сообщать об изменении `localStorage` **из другой вкладки** событием `storage` на `window`:

```js
window.addEventListener('storage', (event) => {
  if (event.key === key) {
    // event.newValue — новая строка; разобрать и положить в state
  }
})
```

А что «включили» на `window` — нужно «выключить» при удалении компонента. Помнишь правило парности из дня 5 недели 2? Значит, в композабле понадобятся `onMounted` / `onUnmounted` (или хотя бы `onUnmounted`).

## Часть 4. 📜 Как это в Options API

### Без композабла: `watch` + `created`

В чистом Options API ту же логику пишут прямо в компоненте:

```js
export default {
  data() {
    return {
      items: [],
    }
  },
  created() {
    const saved = localStorage.getItem('shop:items')
    if (saved) {
      try {
        this.items = JSON.parse(saved)
      } catch {
        // испорченные данные — оставляем []
      }
    }
  },
  watch: {
    items: {
      handler(value) {
        localStorage.setItem('shop:items', JSON.stringify(value))
      },
      deep: true,           // ⚠️ в Options API нужен обязательно
    },
  },
}
```

Работает, но если сохранять нужно в **трёх** компонентах, этот код придётся копировать трижды. Именно эту проблему и решает композабл.

### С композаблом: через `setup()`

Вчерашний приём — композабл можно подключить и в Options API-компонент:

```js
import { useLocalStorage } from '../composables/useLocalStorage.js'

export default {
  setup() {
    const items = useLocalStorage('shop:items', [])
    return { items }
  },
  computed: {
    left() {
      return this.items.filter((i) => !i.bought).length
    },
  },
}
```

`this.items` — уже распакованное значение `ref`: без `.value`, как в шаблоне.

### В рабочем коде

Если в рабочем проекте ищешь, где данные сохраняются в браузере, поищи в коде `localStorage` (Ctrl + Shift + F в VS Code). Найдёшь либо такой `watch` + `created`, либо композабл, либо готовый `useStorage` из библиотеки **VueUse** — её будешь проходить на неделе 8. VueUse — это большая коллекция готовых композаблов, включая ровно тот, что ты сегодня написала сама.

## Шпаргалка

| Тема | Запомнить |
|---|---|
| `localStorage` | только строки; `null`, если ключа нет |
| Запись | `setItem(key, JSON.stringify(value))` |
| Чтение | безопасный `JSON.parse`, иначе — значение по умолчанию |
| Половина 1 | прочитать один раз при создании → начальное значение `ref` |
| Половина 2 | `watch` → сохранить при изменении |
| `deep: true` | обязательно: иначе `push` и изменения полей не сохранятся |
| Возвращает | сам `ref` — подставляется вместо `ref([])` одной строкой |
| Ключи | уникальные, с префиксом проекта: `'shop:items'` |
| Не хранить | пароли, токены; `Date` — строкой |
| Вкладки | событие `storage` на `window` + уборка в `onUnmounted` |
| 📜 Options API | `created` + `watch` с `deep: true`; или композабл через `setup()` |
| VueUse | готовый `useStorage` (неделя 8) |
