# Занятие 1. План и форма

## Разминка (5 мин): `crypto.randomUUID`, `find` и `findIndex`

```js
crypto.randomUUID()   // '9b1deb4d-3b7d-4bad-9bdd-2b0d7b3dcb6d' — каждый раз новый

const habits = [{ id: 'a', title: 'Зарядка' }, { id: 'b', title: 'Чтение' }]

habits.find((h) => h.id === 'b')        // ?
habits.findIndex((h) => h.id === 'b')   // ?
habits.find((h) => h.id === 'z')        // ?
habits.findIndex((h) => h.id === 'z')   // ?
```

<details>
<summary>Ответ</summary>

- `find` → `{ id: 'b', title: 'Чтение' }` — **сам объект** (ссылка на него, не копия!);
- `findIndex` → `1` — **номер** в массиве;
- не нашёл: `find` → `undefined`, `findIndex` → `-1`.

`find` нужен, чтобы **поменять** привычку (раз это ссылка, изменение отразится в массиве). `findIndex` — когда нужен номер, например для `splice`.

`crypto.randomUUID()` работает на `localhost` и на сайтах с `https`. На обычном `http://` с другим адресом его может не быть, но для учебного проекта это неважно.

</details>

## Часть 1. Схема компонентов

Вспомни рецепт из дня 5 недели 3: прямоугольники → где данные → стрелки.

```
App.vue                       ← массив habits (хозяин данных)
├── HabitForm                 ← свои поля title, category
│     └─► emit('add', { title, category })
└── HabitList                 ← props: habits
      └── HabitItem × N       ← props: habit
```

| Данные | Где живут | Почему |
|---|---|---|
| массив привычек | `App.vue` | нужен форме (добавляет) и списку (показывает) |
| текст в полях формы | `HabitForm` | нужен только форме, пока не нажали «Добавить» |

Завтра появятся отметка «сделано», удаление и редактирование. Все они будут **событиями** из `HabitItem` вверх, а меняет массив по-прежнему только `App.vue`. Помнишь правило: у данных один хозяин.

> На неделе 6 массив переедет из `App.vue` в Pinia-стор, и тогда события «через этажи» станут не нужны. А пока — честные props и events: так лучше понятно, как устроена связь компонентов.

## Часть 2. `HabitForm`

### Что внутри

- два поля: название и категория;
- `<form @submit.prevent>` — Enter и кнопка работают одинаково (день 2 недели 2);
- пустое название не отправлять: `trim()` и ранний `return`;
- после отправки — очистить поля.

### Категория: поле или список

Для начала проще `<select>` из 3–4 вариантов (день 3 недели 2):

```vue
<script setup>
const categories = ['Здоровье', 'Учёба', 'Дом', 'Другое']
</script>

<template>
  <select v-model="category">
    <option v-for="c in categories" :key="c" :value="c">{{ c }}</option>
  </select>
</template>
```

⚠️ Начальное значение `category` должно совпадать с одним из вариантов, иначе `select` покажется пустым (ловушка дня 3 недели 2).

На неделе 6 категории станут динамическими (из стора) — пока список можно захардкодить.

### Что отправлять родителю

Форма **не создаёт** привычку целиком: она не знает про `id`, `doneDates` и `createdAt`. Она только сообщает, **что ввёл пользователь**:

```js
emit('add', { title: title.value, category: category.value })
```

А полную привычку по модели собирает хозяин данных — `App.vue`. Так форма остаётся простой и переиспользуемой: её же можно будет использовать для **редактирования** завтра.

### Переиспользуй базовые компоненты

Если на неделе 3 получились хорошие `BaseInput` и `BaseButton` — скопируй их в `habit-tracker/app/src/components/` и используй. Это первая выгода от компонентов: написала один раз — пользуешься везде.

# Занятие 2. Список и сборка

## Часть 3. `HabitList` и `HabitItem`

### `HabitList`

- prop `habits` — массив (`type: Array`, `required: true`);
- `v-for` по `HabitItem` с `:key="habit.id"`;
- если массив пустой — сообщение «Добавь первую привычку» (`v-if` / `v-else`, день 1 недели 2).

Где лучше показать сообщение «пусто»: в `HabitList` или в `App.vue`? Оба варианта нормальные. Если в `HabitList`, то `App` проще; если в `App`, то `HabitList` — «чистый» список. Выбери сама и будь последовательна.

### `HabitItem`

- prop `habit` — объект (`type: Object`, `required: true`);
- показывает название и категорию;
- завтра здесь появятся кнопки, поэтому заранее подумай: какой аргумент нужен родителю, чтобы найти привычку? (`id`, конечно.)

### ⚠️ Передавать объект или поля по отдельности

Вчерашняя развилка из дня 2 недели 3:

```vue
<HabitItem :habit="habit" />                                   <!-- одним объектом -->
<HabitItem :title="habit.title" :category="habit.category" />  <!-- полями -->
```

Для `HabitItem` удобнее **объектом**: полей много, и завтра понадобятся `id` и `doneDates`. Главное — не менять этот объект внутри `HabitItem` (правило дня 2 недели 3).

## Часть 4. Создание привычки в `App.vue`

```js
const habits = ref([])

function addHabit({ title, category }) {   // деструктуризация в параметрах
  habits.value.push({
    id: /* уникальный id */,
    title,
    category,
    doneDates: [],
    createdAt: /* сегодняшняя дата-строка */,
  })
}
```

```vue
<HabitForm @add="addHabit" />
<HabitList :habits="habits" />
```

- `@add="addHabit"` — по имени, поэтому данные из `emit` придут в первый аргумент (день 3 недели 3);
- `{ title, category }` — сокращённая запись объекта (день 2 недели 0), как в твоей `toJSON`;
- пропуски `id` и `createdAt` заполни сама: инструменты — в разминке и в `utils/date.js` со вчерашнего дня.

### ⚠️ Пока данные пропадают при перезагрузке

Сейчас массив живёт только в памяти. Обновишь страницу — привычки исчезнут. Это нормально: завтра подключим `useLocalStorage`.

### Показ даты создания (мини-задача)

```js
new Date('2026-11-05').toLocaleDateString('ru-RU', { day: 'numeric', month: 'long' })
```

⚠️ Тонкость: `new Date('2026-11-05')` (строка без времени) JavaScript считает **полуночью по UTC**. В Москве это 03:00 — день правильный. Но в часовых поясах **западнее** Гринвича получится **вчера**. Надёжнее разобрать строку самой:

```js
const [y, m, d] = '2026-11-05'.split('-').map(Number)
new Date(y, m - 1, d)    // ⚠️ m - 1 — месяцы с нуля!
```

Эту функцию тоже стоит положить в `utils/date.js` — например, `fromDateKey(key)`.

## Часть 5. 📜 Как это в Options API

Сегодняшние компоненты в Options API выглядели бы так (для сравнения, не для проекта):

```vue
<!-- HabitForm на Options API -->
<script>
export default {
  emits: ['add'],
  data() {
    return {
      title: '',
      category: 'Здоровье',
      categories: ['Здоровье', 'Учёба', 'Дом', 'Другое'],
    }
  },
  methods: {
    submit() {
      const title = this.title.trim()
      if (!title) return
      this.$emit('add', { title, category: this.category })
      this.title = ''
    },
  },
}
</script>
```

```vue
<!-- App на Options API -->
<script>
import HabitForm from './components/HabitForm.vue'
import HabitList from './components/HabitList.vue'
import { todayKey } from './utils/date.js'

export default {
  components: { HabitForm, HabitList },   // ⚠️ регистрация обязательна
  data() {
    return { habits: [] }
  },
  methods: {
    addHabit({ title, category }) {
      this.habits.push({
        id: crypto.randomUUID(),
        title,
        category,
        doneDates: [],
        createdAt: todayKey(),
      })
    },
  },
}
</script>
```

Сравни с тем, что получилось у тебя: логика та же, отличаются «полочки», `this.` и регистрация компонентов. Если в рабочем проекте встретишь похожую форму на Options API, ты теперь узнаешь каждую строку.

## Шпаргалка

| Тема | Запомнить |
|---|---|
| `crypto.randomUUID()` | уникальный id-строка |
| `find` | сам объект (ссылка) или `undefined` |
| `findIndex` | номер или `-1` |
| Хозяин массива | `App.vue` (до недели 6) |
| Форма отправляет | только введённое: `{ title, category }` |
| Полную привычку собирает | хозяин данных |
| `HabitItem` | prop `habit` объектом; не менять его внутри |
| Пустой список | сообщение через `v-if` / `v-else` |
| `new Date('2026-11-05')` | UTC-полночь — надёжнее `new Date(y, m - 1, d)` |
| Коммит | после каждого законченного шага |
| 📜 Options API | `emits`, `data`, `methods`, `this.$emit`, `components: {...}` |
