# Занятие 1. Отметка и удаление

## Разминка (5 мин): `includes`, `filter`, `map`, `some`

```js
const dates = ['2026-11-03', '2026-11-04']
const today = '2026-11-05'

dates.includes(today)                          // 1
[...dates, today]                              // 2
dates.filter((d) => d !== '2026-11-04')        // 3
['2026-11-04', today].some((d) => dates.includes(d))  // 4
```

<details>
<summary>Ответ</summary>

1. `false` — сегодня ещё не отмечено.
2. `['2026-11-03', '2026-11-04', '2026-11-05']` — новый массив с сегодняшней датой.
3. `['2026-11-03']` — новый массив без 4-го числа.
4. `true` — хотя бы одна дата из списка есть в `dates`.

Первые три строки — это почти весь код «сделано сегодня»: проверить, добавить, убрать.

</details>

## Часть 1. События из `HabitItem`

У строки привычки появляются три действия. Как и раньше, `HabitItem` **не меняет** привычку сам, а сообщает родителю:

| Действие | Событие | Данные |
|---|---|---|
| отметить / снять «сделано сегодня» | `toggle` | `id` |
| удалить | `remove` | `id` |
| сохранить изменения | `update` | `id` и `{ title, category }` |

```
App.vue  ◄── toggle(id) ── HabitList ◄── toggle ── HabitItem
```

⚠️ Помни из дня 3 недели 3: события **не всплывают** через компоненты. `HabitList` должен поймать событие от `HabitItem` и отправить своё событие выше. Либо (так проще) отправлять сразу с `id`:

```vue
<!-- HabitList.vue -->
<HabitItem
  v-for="habit in habits"
  :key="habit.id"
  :habit="habit"
  @toggle="emit('toggle', habit.id)"
  @remove="emit('remove', habit.id)"
/>
```

Так `HabitItem` может отправлять `emit('toggle')` без аргументов: `id` знает список.

> Цепочка «внук → сын → отец» — то самое неудобство, которое на неделе 6 уберёт Pinia: компонент сможет сам вызвать `store.toggle(id)`.

## Часть 2. «Сделано сегодня»

### Проверка — `computed` в `HabitItem`

```js
const props = defineProps({ habit: { type: Object, required: true } })
const isDoneToday = computed(() => props.habit.doneDates.includes(todayKey()))
```

Это **вычисляемое** значение, поэтому `computed` (неделя 1). В шаблоне — галочка или зачёркивание через `:class`.

### Переключение — функция в `App.vue`

Логика: «если сегодня есть в `doneDates` — убрать, если нет — добавить». В разминке ты уже видела оба действия. Найти привычку по `id` — `find` из вчерашней разминки.

### ⚠️ `todayKey()` в `computed` не обновится в полночь

`todayKey()` — не реактивная зависимость (как `Date.now()` в дне 4 недели 1). Если приложение открыто через полночь, `isDoneToday` не пересчитается сам. Для учебного проекта это нормально: обновила страницу утром — всё правильно.

### ⚠️ Чекбокс и `:checked`

```vue
<input type="checkbox" :checked="isDoneToday" @change="emit('toggle')">
```

Здесь **не** `v-model`: значение не принадлежит `HabitItem`. `:checked` показывает состояние, `@change` сообщает родителю. Это ровно `TodoItem` из дня 3 недели 3.

## Часть 3. Удаление с подтверждением

### Простой вариант: `confirm`

```js
function onRemove() {
  if (confirm(`Удалить привычку «${props.habit.title}»?`)) {
    emit('remove')
  }
}
```

`confirm` — встроенное окно браузера с «ОК» и «Отмена». Возвращает `true` или `false`. Некрасиво, зато одна строка.

### Красивый вариант: свой `BaseModal`

С недели 3 у тебя есть `BaseModal` со слотами и `v-model:open`. Окно подтверждения на нём — хорошая проверка, что компонент получился переиспользуемым.

### Удаление в `App.vue`

`filter` по `id` — как в списке покупок (день 2 недели 2).

# Занятие 2. Редактирование и сохранение

## Часть 4. Редактирование на месте

### Режим редактирования — локальное состояние

«Сейчас редактируется» нужно только самой строке, поэтому живёт в `HabitItem` (правило «где живут данные»):

```js
const isEditing = ref(false)
```

```vue
<template v-if="!isEditing">
  <span>{{ habit.title }}</span>
  <button @click="startEdit">✎</button>
</template>
<template v-else>
  <!-- поля редактирования и «Сохранить» / «Отмена» -->
</template>
```

`<template v-if>` / `<template v-else>` — группы без лишней обёртки (день 1 недели 2).

### ⚠️ Редактируй копию, а не prop

```js
// ✗ v-model прямо на prop — меняет данные родителя в обход события
<input v-model="habit.title">

// ✓ локальные копии полей
const draftTitle = ref('')
const draftCategory = ref('')

function startEdit() {
  draftTitle.value = props.habit.title
  draftCategory.value = props.habit.category
  isEditing.value = true
}
```

Зачем копии:
- правило «не менять props» (день 2 недели 3);
- **«Отмена»** должна вернуть всё как было. Если бы ты редактировала сам объект, отменять было бы нечего: изменения уже применились.

«Сохранить» — `emit('update', { title, category })` и выйти из режима. «Отмена» — просто выйти из режима: копии выбросятся.

### Обновление в `App.vue`

Найти привычку по `id` и обновить поля. `Object.assign(habit, changes)` — помнишь, он меняет **первый** аргумент? Здесь это ровно то, что нужно: меняем объект в массиве, Vue это видит.

### Можно переиспользовать `HabitForm`

Если вчерашняя `HabitForm` принимает начальные значения через props и отправляет `{ title, category }`, её можно показать **внутри** `HabitItem` в режиме редактирования. Это продвинутый вариант — попробуй, если хватит сил.

## Часть 5. Сохранение через `useLocalStorage`

Самое приятное: одна строка.

```js
// было
const habits = ref([])

// стало
const habits = useLocalStorage('habit-tracker:habits', [])
```

Если композабл сделан правильно (день 2), **больше ничего менять не нужно**: `push`, `filter`, изменение `doneDates` и `Object.assign` — всё будет сохраняться. Это и есть проверка качества твоего композабла.

### Проверь

1. Добавь две привычки, отметь одну.
2. Обнови страницу — всё на месте?
3. Отредактируй название и обнови — сохранилось?
4. Открой DevTools → Application → Local Storage: видна ли там JSON-строка?

Если `push` сохраняется, а изменение `doneDates` — нет, проверь `deep: true` в композабле.

### ⚠️ Ключ с префиксом

`'habit-tracker:habits'`, а не `'habits'`: на `localhost` у всех твоих учебных проектов общий `localStorage` (день 2).

# Занятие 3. 📜 Options API и итоги недели

## Часть 6. 📜 Проект в Options API: где была бы боль

Представь, что `App.vue` трекера написан на Options API:

```js
export default {
  components: { HabitForm, HabitList },
  data() {
    return { habits: [] }
  },
  created() {
    // прочитать из localStorage
  },
  watch: {
    habits: {
      handler(value) { /* сохранить */ },
      deep: true,
    },
  },
  methods: {
    addHabit(data) { /* ... */ },
    toggleHabit(id) { /* ... */ },
    removeHabit(id) { /* ... */ },
    updateHabit(id, changes) { /* ... */ },
  },
}
```

Логика «сохранения» разбросана: часть в `created`, часть в `watch`. А логика «управления привычками» — в `methods`. Если завтра понадобится то же самое в другом компоненте, придётся копировать или делать миксин (день 1).

В Composition API сохранение — **одна строка** с композаблом, а управление привычками тоже можно вынести в свой композабл `useHabits()`. На неделе 6 эту роль возьмёт Pinia-стор.

Это и есть главный ответ на вопрос «зачем придумали Composition API»: чтобы логику одной задачи можно было держать вместе и переиспользовать.

### `HabitItem` с редактированием на Options API

```js
export default {
  props: { habit: { type: Object, required: true } },
  emits: ['toggle', 'remove', 'update'],
  data() {
    return {
      isEditing: false,
      draftTitle: '',
      draftCategory: '',
    }
  },
  computed: {
    isDoneToday() {
      return this.habit.doneDates.includes(todayKey())
    },
  },
  methods: {
    startEdit() {
      this.draftTitle = this.habit.title
      this.draftCategory = this.habit.category
      this.isEditing = true
    },
    save() {
      this.$emit('update', { title: this.draftTitle, category: this.draftCategory })
      this.isEditing = false
    },
  },
}
```

Если на работе встретишь компонент «просмотр / редактирование» — скорее всего, он устроен именно так: флаг `isEditing` и черновые копии в `data()`.
