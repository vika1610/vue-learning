# Занятие 1. Даты и модель данных

## Часть 1. Объект `Date`

Сегодня разминка — это половина занятия: даты будут в проекте везде, а в них много ловушек.

### Создание

```js
new Date()                       // сейчас
new Date(2026, 10, 5)            // ⚠️ 5 НОЯБРЯ 2026, а не октября!
new Date('2026-11-05')           // из строки
new Date(1762300800000)          // из числа миллисекунд
```

### ⚠️⚠️ Месяцы — с нуля

```js
new Date(2026, 0, 1)    // 1 января
new Date(2026, 11, 31)  // 31 декабря
new Date(2026, 12, 1)   // ⚠️ 1 января 2027 — «13-й» месяц перенёсся
```

Январь — `0`, декабрь — `11`. При чтении — то же: `date.getMonth()` для ноября вернёт `10`. Это **самая частая** ошибка с датами в JavaScript.

### Части даты

```js
const d = new Date(2026, 10, 5, 14, 30)

d.getFullYear()   // 2026
d.getMonth()      // 10 — ноябрь (с нуля!)
d.getDate()       // 5  — число месяца
d.getDay()        // 4  — день недели: 0 — воскресенье, 1 — понедельник… 4 — четверг
d.getHours()      // 14
```

⚠️ `getDate()` — число месяца, а `getDay()` — **день недели**. Имена похожие, перепутать легко.

### Сложение дней

```js
const d = new Date(2026, 10, 30)
d.setDate(d.getDate() + 1)    // 1 декабря — месяц перенёсся сам
```

`setDate` сам разбирается с концом месяца и года. ⚠️ Но он **меняет** исходный объект (как `sort` — массив). Если исходная дата ещё нужна, сначала сделай копию: `new Date(d)`.

### Сравнение

```js
const a = new Date(2026, 10, 5)
const b = new Date(2026, 10, 5)

a === b                    // ⚠️ false — два разных объекта (ссылки!)
a.getTime() === b.getTime() // true — сравниваем числа миллисекунд
a < b                      // false — сравнение < и > работает
```

### ⚠️⚠️ Часовые пояса и `toISOString`

```js
// в Москве (UTC+3), 5 ноября, 23:30
const d = new Date(2026, 10, 5, 23, 30)

d.toISOString()               // '2026-11-05T20:30:00.000Z' — время в UTC
d.toISOString().slice(0, 10)  // '2026-11-05' ✓ здесь повезло

// а в 01:30 ночи 6 ноября:
const late = new Date(2026, 10, 6, 1, 30)
late.toISOString().slice(0, 10)   // ⚠️ '2026-11-05' — ВЧЕРА!
```

`toISOString` переводит время в **UTC** (Гринвич). Для Москвы это минус 3 часа. Поэтому с полуночи до 03:00 «сегодня» по `toISOString` — это ещё **вчера**. Для трекера привычек это значит: отметка в час ночи запишется не в тот день.

### Дата в местном времени

```js
date.toLocaleDateString('ru-RU')                                // '05.11.2026'
date.toLocaleDateString('ru-RU', { day: 'numeric', month: 'long' }) // '5 ноября'
date.toLocaleDateString('ru-RU', { weekday: 'short' })          // 'чт'
```

Для **показа** человеку — `toLocaleDateString`, как `toLocaleString` для цен в неделе 0. А для **хранения** нужен формат попроще — следующая часть.

## Часть 2. Даты-строки `ГГГГ-ММ-ДД`

В проекте даты выполнения хранятся строками вида `'2026-11-05'`. Почему не объектами `Date`?

| | `Date` | Строка `'2026-11-05'` |
|---|---|---|
| Равенство | `a === b` → `false` ⚠️ | `'2026-11-05' === '2026-11-05'` → `true` ✓ |
| Поиск в массиве | `includes` не работает (ссылки) | `doneDates.includes(today)` ✓ |
| Сохранение в JSON | превращается в строку UTC ⚠️ | остаётся как есть ✓ |
| Сортировка | нужна функция сравнения | обычная строковая сортировка даёт хронологический порядок ✓ |
| Время | хранит часы и минуты — лишнее | только день — то, что нужно |

Строка `ГГГГ-ММ-ДД` сортируется правильно, потому что год, потом месяц, потом день, с ведущими нулями: `'2026-02-01' < '2026-11-05'`.

Это ответ на вопрос недели «Как хранить дату выполнения, чтобы удобно считать серию дней?».

### Функция `todayKey()`

Нужно получить такую строку для **сегодня в местном времени** (не через `toISOString`!). Это задание практики. Что понадобится:
- год, месяц, число — через `getFullYear`, `getMonth` (не забудь `+ 1`!), `getDate`;
- ведущий ноль — `padStart(2, '0')`, как в Pomodoro.

Удобно сделать две функции: `toDateKey(date)` — для любой даты, и `todayKey()` — для сегодня. Первая понадобится на неделе 6 для подсчёта серии.

### Это утилита, а не композабл

В `todayKey` нет `ref`, `watch` и хуков — это **обычная функция**. Её место — `src/utils/date.js`, и имя — без `use` (вчерашнее правило).

## Часть 3. Модель данных привычки

**Модель данных** — описание того, как выглядит одна «сущность» приложения. Сначала модель, потом экраны и код.

Из [SPEC.md](../../habit-tracker/SPEC.md):

```js
{
  id: '3b241101-e2bb-4255-8caf-4136c566a962',  // crypto.randomUUID()
  title: 'Читать 20 минут',
  category: 'Здоровье',
  doneDates: ['2026-11-03', '2026-11-04'],
  createdAt: '2026-11-01',
}
```

### Как пользоваться моделью

С этой моделью почти каждая функция трекера — **один метод массива** из недели 0:

| Вопрос | Код |
|---|---|
| Выполнена ли сегодня? | `habit.doneDates.includes(todayKey())` |
| Сколько раз выполнена всего? | `habit.doneDates.length` |
| Найти привычку по id | `habits.find((h) => h.id === id)` |
| Привычки одной категории | `habits.filter((h) => h.category === 'Здоровье')` |
| Список категорий | `[...new Set(habits.map((h) => h.category))]` |
| Сколько выполнено сегодня | `habits.filter((h) => h.doneDates.includes(today)).length` |

Хорошая модель делает код простым. Если для простого вопроса нужен сложный код — возможно, модель стоит поменять.

### ⚠️ Не храни то, что можно вычислить

Соблазн добавить в модель `doneToday: true` или `streak: 5`. Не надо: это **вычисляется** из `doneDates`. Если хранить отдельно, рано или поздно `doneToday` и `doneDates` «разъедутся». Это то же правило, что «вычисленное — в `computed`» из недели 1.

## Часть 6. 📜 Как это в Options API

Сегодняшние темы — даты и структура проекта — **не зависят** от стиля компонентов. `utils/date.js` с обычными функциями одинаково используется и в `<script setup>`, и в Options API:

```js
// Composition API
import { todayKey } from '../utils/date.js'
const today = todayKey()
```

```js
// Options API
import { todayKey } from '../utils/date.js'

export default {
  computed: {
    today() {
      return todayKey()
    },
  },
}
```

⚠️ В Options API импортированная функция **не видна** в шаблоне сама по себе (вспомни константу `prices` из дня 5 недели 1). Чтобы вызвать `todayKey()` прямо в шаблоне, её нужно «пробросить» через `computed`, `methods` или `setup()`. В `<script setup>` импорт сразу доступен в шаблоне.

Проект трекера пишем на `<script setup>`. Но если захочешь потренироваться, любой его компонент можно переписать на Options API — так ты увидишь разницу на настоящем коде.

## Шпаргалка

| Тема | Запомнить |
|---|---|
| Месяцы в `Date` | с нуля: январь — `0`, декабрь — `11` |
| `getDate()` / `getDay()` | число месяца / день недели (0 — воскресенье) |
| `setDate(d + 1)` | прибавить день; меняет объект |
| Сравнение `Date` | `getTime()`, не `===` |

| Хранение даты | строка `'ГГГГ-ММ-ДД'` в местном времени |
| `todayKey()` | утилита в `utils/date.js`, не композабл |
| Модель | сначала модель, потом экраны и код |
| Не хранить | то, что вычисляется (`doneToday`, `streak`) |
| Наброски | экран → что видно → что можно сделать → компоненты |
| Проект | `habit-tracker/app`; коммит после каждого шага |
