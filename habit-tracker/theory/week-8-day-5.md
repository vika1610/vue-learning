## Часть 2. Что такое Nuxt

**Nuxt** — фреймворк **поверх Vue**. Если Vue — двигатель, то Nuxt — готовая машина вокруг него.

Всё, что ты настраивала руками, в Nuxt есть «из коробки»:

| Ты делала сама | В Nuxt |
|---|---|
| `createRouter` + таблица маршрутов | **маршрутизация по файлам**: файл `pages/habits/[id].vue` — это сразу маршрут `/habits/:id` |
| `app.use(createPinia())` в `main.js` | модуль Pinia подключается одной строкой в настройках |
| `import` каждого компонента | **автоимпорт**: компоненты из `components/` и композаблы из `composables/` доступны без `import` |
| `useFetch` своими руками | встроенные `useFetch` и `useAsyncData` |
| `main.js`, `index.html`, `App.vue` | Nuxt создаёт их за тебя |
| только фронтенд | можно писать и **серверную часть** — API — в папке `server/` |

### Маршрутизация по файлам

```
pages/
├── index.vue          → /
├── habits/
│   ├── index.vue      → /habits
│   └── [id].vue       → /habits/:id
└── stats.vue          → /stats
```

Квадратные скобки `[id]` — параметр, как `:id` в роутере. Внутри страницы — тот же `useRoute()` и `route.params.id`. Ты уже всё это знаешь — Nuxt просто убирает ручную настройку.

> Кстати, Vue Router 5, который стоит в `vue-exercises`, тоже умеет маршрутизацию по файлам — это та же идея, пришедшая из Nuxt.

## Часть 3. Серверный рендеринг простыми словами

Главное отличие Nuxt — он умеет **серверный рендеринг** (SSR).

### Как работает твой трекер (SPA)

```
браузер просит страницу  ──►  сервер отдаёт почти пустой index.html + JS
                              ──► браузер скачивает JS
                              ──► Vue рисует страницу
```

Пока JavaScript не загрузился — пустой экран. И поисковики (Яндекс, Google) видят почти пустую страницу.

### Как работает Nuxt (SSR)

```
браузер просит страницу  ──►  сервер ЗАПУСКАЕТ Vue, рисует готовый HTML с данными
                              ──► браузер сразу показывает страницу
                              ──► потом «оживляет» её JavaScript (гидратация)
```

Пользователь сразу видит содержимое, а поисковики — полноценную страницу.

### Когда что

| Подходит SPA (как трекер) | Подходит Nuxt / SSR |
|---|---|
| личные кабинеты, админки, приложения за логином | сайты, которые должны находить поисковики: блоги, магазины, новости |
| поиск не важен | важна скорость первого показа |
| простой хостинг статических файлов | нужен сервер (или «статическая генерация» — HTML заранее для каждой страницы) |

### ⚠️ Особенности SSR

Код компонента выполняется **и на сервере, и в браузере**. А на сервере нет `window`, `document` и **`localStorage`**! Твой `useLocalStorage` в Nuxt пришлось бы вызывать только на стороне браузера (например, в `onMounted`). Это главная непривычная вещь при переходе на Nuxt.

## Часть 4. Nuxt и твой опыт

Хорошая новость: **почти всё**, что ты изучила, работает в Nuxt без изменений — компоненты, `<script setup>`, `ref`, `computed`, props, события, слоты, композаблы, Pinia, TypeScript, Vitest.

Nuxt — естественный следующий шаг. Но **не обязательный**: многие рабочие проекты (особенно личные кабинеты и внутренние системы) — это обычный Vue + Vite, как твой трекер. Посмотри, что используется у тебя на работе.

📜 Nuxt поддерживает и Options API, но вся его документация и экосистема — на Composition API.

### Попробовать (по желанию)

```bash
npm create nuxt@latest my-nuxt-app
```

Перенеси одну-две страницы трекера и посмотри, как исчезают `router/index.ts` и импорты компонентов.

Из плана — «Что дальше»: Nuxt, глубже TypeScript, второй проект с бэкендом, чтение чужого кода. Подробнее:

| Направление | Зачем | С чего начать |
|---|---|---|
| **Второй проект с бэкендом** | данные на сервере, вход, синхронизация между устройствами | **Supabase** или **Firebase**: база данных и авторизация без своего сервера. Например, трекер привычек с аккаунтами |
| **Nuxt** | SSR, сайты для поисковиков, полный стек | nuxt.com → «Get Started»; перенести трекер |
| **TypeScript глубже** | дженерики, сужение, типизация API | Handbook на typescriptlang.org; переписать `useFetch<T>` с типизированным ответом |
| **Тесты глубже** | тесты страниц с роутером и стором, e2e-тесты | Vitest Browser Mode или Playwright |
| **Чтение чужого кода** | быстрее разбираться в рабочем проекте | открытые проекты на GitHub, исходники VueUse — короткие и понятные композаблы |
