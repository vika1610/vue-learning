# Занятие 1. Стор привычек

## Разминка (10 мин): работа с датами

Повтор дня 3 недели 4. Используя свои `toDateKey` и `fromDateKey` из `utils/date.js`:

1. Как получить строку **вчерашней** даты?
2. Сколько дней прошло с `'2026-11-01'` по `'2026-11-05'` включительно?

<details>
<summary>Ответ</summary>

1. ```js
   const d = new Date()
   d.setDate(d.getDate() - 1)   // setDate сам разберётся с концом месяца
   toDateKey(d)
   ```
2. **5** дней. Разница в миллисекундах: `fromDateKey('2026-11-05') - fromDateKey('2026-11-01')` → 4 дня × 24 × 60 × 60 × 1000 мс. Делим на `86400000` (мс в сутках) — получаем 4, плюс 1, потому что «включительно».

   ⚠️ При переходе на летнее/зимнее время в сутках бывает 23 или 25 часов. В России перевода часов нет, но надёжнее округлять: `Math.round(diff / 86400000)`.

Обе вещи понадобятся завтра: «вчера» — для серии дней, «сколько дней с создания» — для процента выполнения.

</details>

## Часть 2. Из композабла — в стор

На неделе 5 ты сделала `useHabits` — композабл с состоянием **вне** функции. Это уже «самодельный стор». Превратить его в настоящий — почти механическая работа:

```js
// было: composables/useHabits.js
const habits = useLocalStorage('habit-tracker:habits', [])

export function useHabits() {
  function addHabit(data) { /* ... */ }
  // ...
  return { habits, addHabit /* , ... */ }
}
```

```js
// стало: stores/habits.js
import { defineStore } from 'pinia'
import { computed } from 'vue'
import { useLocalStorage } from '../composables/useLocalStorage.js'

export const useHabitsStore = defineStore('habits', () => {
  const habits = useLocalStorage('habit-tracker:habits', [])   // ← теперь ВНУТРИ

  function addHabit(data) { /* ... */ }
  // ...

  return { habits, addHabit /* , ... */ }
})
```

Отличия:
- `defineStore('habits', () => {...})` вместо `export function useHabits()`;
- состояние — **внутри** функции: Pinia сама гарантирует, что функция выполнится один раз на всё приложение;
- имя — `useHabitsStore`.

Это setup-стор — потому что он ровно повторяет твой композабл. Если хочешь потренировать options-стор для работы — можно и его, но тогда сохранение придётся делать через `$subscribe` (вчерашний день).

### ⚠️ `useLocalStorage` внутри стора

Если в твоём `useLocalStorage` есть `onMounted` / `onUnmounted` (синхронизация вкладок), внутри стора хуки не к чему привязать — Vue предупредит. Варианты:
- убрать синхронизацию вкладок из этого композабла;
- или сохранять в сторе через `watch(habits, ..., { deep: true })` + начальное значение через `parseJSONSafe`, как в корзине вчера.

## Часть 3. Геттеры

### `todayList` — привычки с флагом «сделано сегодня»

Странице «Сегодня» нужен список, где у каждой привычки известно, выполнена ли она сегодня. Удобно отдать это готовым геттером:

```js
const todayList = computed(() => {
  const today = todayKey()
  return habits.value.map((h) => ({
    ...h,                                     // все поля привычки
    doneToday: h.doneDates.includes(today),   // + вычисленный флаг
  }))
})
```

- `map` с `{ ...h, doneToday }` — новый объект с **дополнительным** полем (spread, день 3 недели 0). Исходная привычка не меняется;
- `doneToday` — **вычисляется**, а не хранится. Помнишь правило из модели данных: «не храни то, что можно вычислить»? Здесь мы вычисляем его в геттере — и всё честно.

⚠️ `todayList` — это **копии** для показа. Если изменить `todayList[0].title`, исходная привычка не изменится. Менять — только через действия.

### Ещё полезные геттеры

| Геттер | Что вернёт |
|---|---|
| `doneTodayCount` | сколько выполнено сегодня |
| `total` | сколько привычек всего |
| `getById` | функция `(id) => habit` — для страницы привычки |

`getById` — геттер с параметром (вчерашний конспект, часть 2): возвращает функцию.

### `streak` — завтра

В SPEC для этого дня указан и геттер `streak`. Сегодня можно сделать **заготовку** — функцию, которая пока возвращает `0`, — а алгоритм подсчёта серии подробно разберём завтра.

# Занятие 2. Компоненты на сторе

## Часть 4. Убираем цепочки событий

Помнишь, как `HabitItem` сообщал о клике через `HabitList` до `App`? Теперь любой компонент может **сам** вызвать действие стора:

```vue
<!-- HabitItem.vue -->
<script setup>
import { useHabitsStore } from '../stores/habits.js'

const props = defineProps({ habit: { type: Object, required: true } })
const store = useHabitsStore()
</script>

<template>
  <input type="checkbox" :checked="habit.doneToday" @change="store.toggleToday(habit.id)">
</template>
```

`HabitList` больше не ловит и не пересылает события — ему достаточно показать список.

### ⚠️ Но не всё нужно переводить на стор

Хорошие **базовые** компоненты (`BaseButton`, `BaseInput`, `BaseModal`) и **простые** компоненты-«кирпичики» лучше оставить на props и событиях. Они не должны знать про конкретный стор — тогда их можно переиспользовать где угодно.

Правило:
- **страницы** и «умные» компоненты, которые знают про приложение, — работают со стором;
- **базовые** компоненты — props и события.

`HabitItem` — где-то посередине. Оба варианта нормальные: можно, чтобы он сам вызывал стор, а можно оставить события и вызывать стор на странице. Выбери и будь последовательна.

### Страницы

```js
// TodayPage.vue
const store = useHabitsStore()
const { todayList, doneTodayCount, total } = storeToRefs(store)
```

```vue
<p>Выполнено {{ doneTodayCount }} из {{ total }}</p>
<HabitItem v-for="habit in todayList" :key="habit.id" :habit="habit" />
```

Помни про `storeToRefs` для state и геттеров и про то, что действия берутся из стора напрямую (день 2).

## Часть 6. 📜 Как это в Options API

Если бы компоненты трекера были на Options API:

```js
import { mapState, mapActions } from 'pinia'
import { useHabitsStore } from '../stores/habits.js'

export default {
  computed: {
    ...mapState(useHabitsStore, ['todayList', 'doneTodayCount', 'total']),
  },
  methods: {
    ...mapActions(useHabitsStore, ['toggleToday', 'removeHabit']),
  },
}
```

```vue
<HabitItem v-for="h in todayList" :key="h.id" :habit="h" @toggle="toggleToday(h.id)" />
```

Стор при этом **тот же самый** — setup-стор отлично работает с `mapState` и `mapActions`. Стиль стора и стиль компонентов не обязаны совпадать.
