# Занятие 1. Git и GitHub

## Часть 1. Что такое git

**Git** — система контроля версий. Она хранит **историю** всех изменений проекта: кто, когда и что поменял. Можно посмотреть любое прошлое состояние и вернуться к нему.

Каждый **коммит** — это «снимок» проекта с описанием: «Трекер: тёмная тема». Ты делала коммиты с недели 4 — теперь разберёмся, что за ними стоит.

```
коммит 1 ── коммит 2 ── коммит 3 ── коммит 4   ← история
"создан    "форма"     "стор"      "тёмная
проект"                            тема"
```

### Три места, где живут изменения

```
рабочая папка  ──git add──►  подготовлено (staging)  ──git commit──►  история
(твои файлы)                  (что войдёт в коммит)                   (снимки)
```

- **рабочая папка** — файлы, как ты их видишь в VS Code;
- **подготовлено** — изменения, которые ты отметила для ближайшего коммита;
- **история** — все сделанные коммиты.

Зачем промежуточный шаг: можно поменять пять файлов, а в коммит положить только три, связанных одной задачей.

## Часть 2. Главные команды

| Команда | Что делает |
|---|---|
| `git status` | что изменено, что подготовлено — **запускай постоянно** |
| `git add файл` | подготовить файл к коммиту |
| `git add .` | подготовить **всё** в текущей папке |
| `git commit -m "сообщение"` | сделать коммит |
| `git log --oneline` | история коротко |
| `git diff` | что именно поменялось в файлах (ещё не подготовлено) |
| `git restore файл` | ⚠️ отменить изменения в файле (вернуть как в последнем коммите) |
| `git push` | отправить коммиты на GitHub |
| `git pull` | забрать изменения с GitHub |

> В VS Code есть вкладка **Source Control** (значок ветки слева): там всё то же самое кнопками. Удобно смотреть изменения в файлах. Но команды в терминале полезно знать — они одинаковы везде.

### Хорошее сообщение коммита

```
✓ Трекер: серия дней и тесты для calcStreak
✓ Исправлена ошибка: отметка в час ночи попадала во вчерашний день
✗ правки
✗ fix
✗ asdfgh
```

Сообщение отвечает на вопрос «что сделано». Через месяц по истории должно быть понятно, как развивался проект. Работодатель, открыв твой GitHub, тоже смотрит на историю коммитов.

### `.gitignore` — что не коммитить

В репозитории уже есть `.gitignore`: `node_modules/`, `dist/`… (неделя 3, день 1). Проверь, что `node_modules` никогда не попадает в коммит: `git status` не должен его показывать.

### ⚠️ Секреты не коммитят

Пароли, токены, ключи API **никогда** не должны попасть в git. Даже если удалить их следующим коммитом, они останутся в **истории**. В трекере секретов нет, но привычка важна.

### Ветки (обзор)

**Ветка** — отдельная линия истории: можно делать новую функцию, не трогая основную. На работе почти всегда работают в ветках и объединяют их через Pull Request. Для учебного проекта хватит одной ветки `main`.

## Часть 3. GitHub

**GitHub** — сайт для хранения git-репозиториев в интернете. Это и резервная копия, и **портфолио**: работодатель может открыть твой код.

### Залить репозиторий

Подробная инструкция для твоего аккаунта `vika1610` уже была в начале курса. Кратко:

1. Если ещё не сделала: представиться git (один раз на компьютере):
   ```bash
   git config --global user.name "Твоё имя"
   ```
   ```bash
   git config --global user.email "почта-от-github"
   ```
2. На github.com: **New repository**, имя `vue-learning`, **без** README и `.gitignore`.
3. Связать и отправить:
   ```bash
   git remote add origin https://github.com/vika1610/vue-learning.git
   ```
   ```bash
   git push -u origin main
   ```
4. При первом `push` откроется окно входа в GitHub через браузер.

### Отдельный репозиторий для трекера?

Для **портфолио** лучше, чтобы трекер был **отдельным** репозиторием: `vika1610/habit-tracker`. Его ссылку удобно давать работодателю, и в нём только проект, без учебных задач. Варианты:
- скопировать папку `habit-tracker/app` в новую папку, сделать там `git init` и залить в новый репозиторий;
- или оставить всё в `vue-learning`: так проще, но ссылка будет на весь учебный репозиторий.

Если не уверена, как лучше, — спроси наставника перед началом.

# Занятие 2. Сборка и деплой

## Часть 4. `npm run build` — сборка

```bash
npm run build
```

Vite собирает проект для публикации (неделя 3, день 1):
- превращает `.vue` и `.ts` в обычный JavaScript;
- **склеивает** и **сжимает** файлы;
- ленивые страницы (неделя 5) выносит в **отдельные** файлы;
- кладёт всё в папку **`dist/`**.

```
dist/
├── index.html
└── assets/
    ├── index-a1b2c3.js       ← основной код
    ├── StatsPage-d4e5f6.js   ← ленивая страница + Chart.js
    └── index-g7h8i9.css
```

Странные буквы в именах — «отпечаток» содержимого. Поменяется код — поменяется имя, и браузер пользователя не возьмёт старую версию из кэша.

### ⚠️ Ошибки сборки

`npm run dev` прощает многое, а `build` — строже. Если сборка упала, прочитай ошибку: часто это неправильный путь импорта или (если в `build` включена проверка типов) ошибка TypeScript. Запусти `npm run type-check`.

### `npm run preview` — посмотреть собранное

```bash
npm run preview
```

Запускает локальный сервер **с папкой `dist`** — так сайт будет выглядеть после публикации. Проверь, что всё работает, **до** деплоя.

## Часть 5. Деплой на Netlify или Vercel

**Деплой** — публикация сайта в интернете. Netlify и Vercel — бесплатные для небольших проектов хостинги, которые сами собирают проект из GitHub.

Общая схема (у обоих похожа):

1. Зарегистрируйся через свой аккаунт GitHub.
2. **Add new site / New project** → **Import from GitHub** → выбери репозиторий.
3. Настройки сборки:
   | Поле | Значение |
   |---|---|
   | Base directory / Root directory | папка проекта, например `habit-tracker/app` (если трекер внутри `vue-learning`) |
   | Build command | `npm run build` |
   | Publish / Output directory | `dist` |
4. **Deploy** — через минуту получишь ссылку вида `habit-tracker-xxx.netlify.app`.

После этого **каждый `git push`** будет автоматически пересобирать и обновлять сайт. Это называется непрерывный деплой (CD).

### ⚠️ Регистрация и условия сервиса

Регистрацию и принятие условий использования на сайте хостинга делаешь **сама** — это твой аккаунт. Если что-то в настройках непонятно, пришли наставнику скриншот.

## Часть 6. ⚠️ Роутер на хостинге: ошибка 404 при обновлении

Помнишь неделю 5, день 1: `createWebHistory` требует, чтобы **сервер** на любой путь отдавал `index.html`? Вот здесь это и проявится.

Открой опубликованный сайт, перейди на «Все привычки» (`/habits`) — работает. А теперь **обнови страницу** — **404**!

Почему: при обновлении браузер просит у сервера файл `/habits`. Такого файла в `dist` нет — есть только `index.html`. Роутер Vue даже не успел запуститься.

Решение — сказать хостингу: «на любой путь отдавай `index.html`».

**Netlify** — файл `public/_redirects` (попадёт в `dist` при сборке):

```
/*    /index.html   200
```

**Vercel** — файл `vercel.json` в корне проекта:

```json
{
  "rewrites": [{ "source": "/(.*)", "destination": "/index.html" }]
}
```

Закоммить, `push`, дождись пересборки — и обнови `/habits` ещё раз.

### ⚠️ Данные у каждого свои

Привычки хранятся в `localStorage` **браузера**. На опубликованном сайте у тебя будет **пустой** список (другой адрес — другой `localStorage`), а у каждого посетителя — свой. Это нормально для учебного проекта. Хранить данные на сервере и синхронизировать между устройствами — тема для следующего проекта с бэкендом (Supabase, Firebase).

# Занятие 3. README

## Часть 7. Хороший README

`README.md` — первое, что видят на странице репозитория GitHub. Для портфолио он важнее, чем кажется: работодатель тратит на проект 1–2 минуты, и почти всё это время — на README.

### Что должно быть

````markdown
# Трекер привычек

Веб-приложение для отслеживания ежедневных привычек: отметки «сделано сегодня»,
серии дней подряд, статистика с графиком.

🔗 **Демо:** https://habit-tracker-xxx.netlify.app

![Главная страница](docs/screenshot-today.png)

## Возможности

- добавление, редактирование и удаление привычек
- отметка «сделано сегодня» и серия дней подряд 🔥
- категории и фильтры
- статистика с графиком за 14 дней
- тёмная тема, адаптивная вёрстка
- горячие клавиши: `n` — новая привычка, `Esc` — отмена

## Технологии

Vue 3 (Composition API, `<script setup>`), TypeScript, Vue Router, Pinia,
Vitest + Vue Test Utils, Chart.js, VueUse, Tailwind CSS / PrimeVue, Vite.

## Запуск

```bash
npm install
npm run dev      # разработка
npm run test     # тесты
npm run build    # сборка
```

## Что я изучила, делая этот проект

…
````

### Советы

- **Ссылка на демо — в самом начале.** Многие не будут ставить проект локально, а по ссылке зайдут;
- **скриншот** показывает проект за секунду (часть 8);
- раздел **«Что я изучила»** или **«Сложности и решения»** — хорошее место, чтобы показать мышление: «Серия дней считалась неправильно после полуночи — оказалось, `toISOString` переводит в UTC. Написала свою функцию даты и тест на этот случай». Это ценнее списка технологий;
- пиши **честно**: только то, что есть в проекте.
