# Занятие 1. Роутер в своём проекте

## Часть 1. Установка и подключение

В `vue-exercises` роутер был установлен за тебя. В своём проекте — сама:

```bash
cd habit-tracker/app
```
```bash
npm install vue-router
```

Пакет появится в `dependencies` в `package.json` (день 1 недели 3).

Роутер принято выносить в отдельный файл `src/router/index.js`:

```js
import { createRouter, createWebHistory } from 'vue-router'
import TodayPage from '../pages/TodayPage.vue'

export const router = createRouter({
  history: createWebHistory(),
  routes: [
    { path: '/', name: 'today', component: TodayPage },
    // остальные маршруты
  ],
})
```

А в `main.js` — подключить:

```js
import { createApp } from 'vue'
import App from './App.vue'
import { router } from './router/index.js'

createApp(App).use(router).mount('#app')
```

### `createWebHistory`, а не `hash`

В своём проекте нет меню задач, которое занимает адрес, поэтому — «красивые» адреса `/habits/42` (день 1, часть 4). Vite в разработке сам отдаёт `index.html` на любой путь. А при деплое на неделе 8 понадобится одна настройка хостинга — там и разберёмся.

## Часть 2. Разложить код по страницам

Сейчас всё живёт в `App.vue`: форма, список, сохранение. С роутером `App.vue` становится **рамкой**:

```vue
<!-- App.vue -->
<template>
  <AppNav />
  <main>
    <RouterView />
  </main>
</template>
```

А содержимое переезжает в страницы:

| Адрес | Страница | Что на ней (из SPEC) |
|---|---|---|
| `/` | `TodayPage` | привычки с отметкой «сделано», прогресс «3 из 5» |
| `/habits` | `HabitsPage` | список, форма добавления, редактирование, удаление |
| `/habits/:id` | `HabitPage` | одна привычка: название, категория, дата создания, история |
| `/stats` | `StatsPage` | пока просто: сколько привычек, сколько выполнено сегодня |
| `/:pathMatch(.*)*` | `NotFoundPage` | 404 |

Компоненты `HabitForm`, `HabitList`, `HabitItem` никуда не деваются: их используют **страницы**.

```
src/
├── App.vue                 ← рамка: меню + RouterView
├── router/index.js
├── pages/
│   ├── TodayPage.vue
│   ├── HabitsPage.vue
│   ├── HabitPage.vue
│   ├── StatsPage.vue
│   └── NotFoundPage.vue
├── components/             ← HabitForm, HabitList, HabitItem, AppNav, Base…
├── composables/
└── utils/
```

## Часть 3. ⚠️ Данные нужны нескольким страницам

Главная проблема дня. Массив привычек сейчас в `App.vue` и передаётся props. Но теперь между `App` и страницами стоит `RouterView`, а страниц четыре. Как им всем получить **один и тот же** массив?

### Вариант 1: композабл с общим состоянием

Вспомни: если `ref` объявить **вне** функции композабла, все вызовы получат **один и тот же** `ref` (ловушка дня 1 недели 4 — которая здесь становится решением!). А `useLocalStorage` уже даёт `ref`, который сохраняется.

```js
// composables/useHabits.js
import { useLocalStorage } from './useLocalStorage.js'

const habits = useLocalStorage('habit-tracker:habits', [])   // ← ВНЕ функции: один на всё приложение

export function useHabits() {
  function addHabit(data) { /* ... */ }
  function toggleToday(id) { /* ... */ }
  // ...
  return { habits, addHabit, toggleToday /* , ... */ }
}
```

```js
// в любой странице
const { habits, toggleToday } = useHabits()
```

Функции из `App.vue` (`addHabit`, `toggleToday`, `removeHabit`, `updateHabit`) переезжают в `useHabits`. Страницы вызывают их напрямую — без цепочек событий через `HabitList`!

⚠️ Если в твоём `useLocalStorage` есть `onMounted` / `onUnmounted` (для события `storage`), вызов **вне** компонента даст предупреждение. Тогда либо убери синхронизацию вкладок, либо вызови `useLocalStorage` в `useHabits` при первом вызове. Если запутаешься — спроси наставника.

### Вариант 2: `provide` / `inject`

`App.vue` делает `provide('habits', ...)`, страницы — `inject` (день 5 недели 3). Тоже работает.

### Что выбрать

**Вариант 1** — и проще, и ближе к тому, что будет на неделе 6: Pinia-стор — это, по сути, такой же «общий композабл», только с удобствами. Когда на неделе 6 ты переведёшь `useHabits` на Pinia, страницы почти не изменятся.

# Занятие 2. Остальные страницы

## Часть 4. Страница одной привычки `/habits/:id`

### Найти привычку

```js
const route = useRoute()
const { habits } = useHabits()

const habit = computed(() => habits.value.find((h) => h.id === route.params.id))
```

- `computed`, а не разовый поиск: если привычку отметят или переименуют, страница обновится, а при переходе на другую привычку — найдёт новую;
- `id` здесь — **строка** из `crypto.randomUUID()`, и `route.params.id` тоже строка, поэтому `===` работает без `Number()` (в отличие от блога с числовыми id, день 2).

### Привычка не найдена

`/habits/abc` совпадёт с маршрутом, но привычки нет: `habit.value` будет `undefined`. Покажи сообщение и ссылку на «Все привычки» (день 3, часть 5).

### Что показать

Из SPEC: название, категория, дата создания (`fromDateKey` + `toLocaleDateString` из дня 4 недели 4), история отметок. Серия дней — на неделе 6, пока можно «Выполнено раз: N».

История отметок — `v-for` по `doneDates`. Подумай: в каком порядке их показать? (Помнишь, строки `ГГГГ-ММ-ДД` сортируются как даты? И помнишь, что `sort` меняет массив?)

### Ссылка на страницу привычки

В `HabitItem` название привычки становится ссылкой:

```vue
<RouterLink :to="{ name: 'habit', params: { id: habit.id } }">{{ habit.title }}</RouterLink>
```

### «Статистика» — лениво

```js

```

На неделе 8 здесь будет график — тяжёлая библиотека. Ленивая загрузка с самого начала — правильно.

Пока на странице простые числа из `computed`: всего привычек, выполнено сегодня, процент. Пригодятся `filter`, `length` и `todayKey`.

### 404

`NotFoundPage` и маршрут `/:pathMatch(.*)*` — как в дне 3.

### Меню `AppNav`

Четыре `RouterLink` и стиль `router-link-exact-active` (день 1). ⚠️ Для «Все привычки» подумай: на странице `/habits/42` должна ли подсвечиваться ссылка `/habits`? Если да — нужен `router-link-active` (адрес **начинается** с `/habits`), а для «Сегодня» (`/`) — `exact`.

### Заголовок вкладки (бонус)

`meta: { title: 'Сегодня' }` у маршрутов и `router.afterEach` для `document.title` (день 4).

## Часть 6. 📜 Как это в Options API

Если бы страницы трекера были на Options API, общий `useHabits` подключался бы через `setup()` (день 1 недели 4):

```js
import { useHabits } from '../composables/useHabits.js'

export default {
  setup() {
    const { habits, toggleToday } = useHabits()
    return { habits, toggleToday }
  },
  computed: {
    habit() {
      return this.habits.find((h) => h.id === this.$route.params.id)
    },
  },
}
```

А в «чистом» Options API без композаблов общие данные обычно жили в **Vuex** — предшественнике Pinia. Если в рабочем проекте увидишь `this.$store`, `mapState`, `mapGetters` — это Vuex (или Pinia в стиле Options API). Как это устроено, — на неделе 6.
