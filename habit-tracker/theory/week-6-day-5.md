# Занятие 1. Категории и фильтр

## Разминка (10 мин): `filter` и `sort`

```js
const dates = ['2026-11-04', '2026-11-01', '2026-11-05', '2026-11-03']

dates.sort()                          // 1 — что станет с dates?
[...dates].sort().reverse()           // 2
dates.filter((d) => d >= '2026-11-03') // 3
```

<details>
<summary>Ответ</summary>

1. `['2026-11-01', '2026-11-03', '2026-11-04', '2026-11-05']` — и ⚠️ **исходный** массив изменился: `sort` меняет его на месте (день 3 недели 0). Строки `ГГГГ-ММ-ДД` сортируются как даты — вот зачем мы выбрали этот формат.
2. Новый массив от новых к старым: `['2026-11-05', '2026-11-04', '2026-11-03', '2026-11-01']`.
3. `['2026-11-03', '2026-11-04', '2026-11-05']` — массив уже отсортирован шагом 1 (шаг 2 работал с копией и его не тронул). Строки `ГГГГ-ММ-ДД` можно сравнивать `>=` прямо как даты.

Сегодня все три приёма понадобятся для серии дней.

</details>

## Часть 1. Категории как геттер

Список категорий — **вычисляется** из привычек: какие категории встречаются у существующих привычек.

```js
const categories = computed(() => [...new Set(habits.value.map((h) => h.category))])
```

Это вчерашний приём из магазина (`Set` + spread). Удалишь последнюю привычку из «Учёбы» — категория исчезнет из списка сама.

### Категории для формы

В `HabitForm` на неделе 4 список был захардкожен: `['Здоровье', 'Учёба', …]`. Теперь можно:
- оставить фиксированный список **плюс** добавить категории из стора (на случай, если пользователь ввёл свою);
- или разрешить вводить новую категорию в поле, а `<datalist>` подскажет существующие:

```vue
<input v-model="category" list="categories">
<datalist id="categories">
  <option v-for="c in store.categories" :key="c" :value="c" />
</datalist>
```

`<datalist>` — HTML-элемент: подсказки при вводе, но можно написать и своё. Удобно для категорий.

### Подсчёт по категориям (бонус)

Помнишь `reduce` с объектом-аккумулятором («листок для подсчёта», неделя 0)? `{ 'Здоровье': 3, 'Учёба': 1 }` — готовый геттер для статистики.

## Часть 2. Фильтр на странице «Все привычки»

Где хранить выбранную категорию — в сторе или в компоненте? Вспомни таблицу из дня 2: **выбор на одном экране — в компоненте**.

```js
// HabitsPage.vue
const store = useHabitsStore()
const { habits, categories } = storeToRefs(store)

const selected = ref('')   // '' — все

const visible = computed(() =>
  selected.value ? habits.value.filter((h) => h.category === selected.value) : habits.value,
)
```

### Фильтр в адресе (бонус)

А если хочется, чтобы фильтр сохранялся при перезагрузке и им можно было поделиться ссылкой? Тогда храни его в **query** адреса: `/habits?category=Здоровье` (неделя 5, день 2):

```js
const route = useRoute()
const router = useRouter()

const selected = computed({
  get: () => route.query.category ?? '',
  set: (value) => router.replace({ query: value ? { category: value } : {} }),
})
```

`computed` с `get` / `set` (неделя 1, день 4) + `v-model="selected"` на `<select>` — и фильтр живёт в адресе. `replace`, чтобы каждое переключение фильтра не засоряло историю «Назад».

# Занятие 2. Серия дней подряд

## Часть 3. Алгоритм серии

### Что считаем

Из SPEC: **серия** (streak) — сколько дней подряд **до сегодня включительно** привычка выполнена. Если сегодня ещё не отмечено — считаем **до вчера**: не обнулять серию утром только потому, что ещё не успела сделать.

| `doneDates` (сегодня 5 ноября) | Серия |
|---|---|
| `[]` | 0 |
| `['2026-11-05']` | 1 |
| `['2026-11-03', '2026-11-04', '2026-11-05']` | 3 |
| `['2026-11-03', '2026-11-04']` (сегодня не отмечено) | 2 — до вчера |
| `['2026-11-01', '2026-11-02', '2026-11-04', '2026-11-05']` | 2 — 3-го пропуск |
| `['2026-11-02', '2026-11-03']` (вчера и сегодня нет) | 0 — серия прервалась |

Эта таблица — готовые **тестовые случаи**. На неделе 7 ты напишешь по ним настоящие тесты.

### Идея: шагать назад по дням

Как человек считает серию по календарю? Начинает с сегодня и идёт **назад**, пока дни отмечены:

```
1. Начать с сегодня.
2. Если сегодня НЕ отмечено — начать со вчера (серия «до вчера»).
3. Пока текущий день есть в doneDates:
     прибавить 1 к серии,
     перейти на день назад.
4. Вернуть серию.
```

На JavaScript понадобится:
- «день назад» — `setDate(getDate() - 1)` (сегодняшняя разминка);
- «есть ли день» — `toDateKey(day)` и `includes`;
- «пока» — цикл `while`.

```js
function calcStreak(doneDates, today = new Date()) {
  let streak = 0
  const day = new Date(today)            // ⚠️ копия! setDate меняет объект
  // шаг 2: …
  // шаг 3: while (…) { … }
  return streak
}
```

Пропуски — твоя задача. 

### Почему отдельная функция, а не геттер сразу

`calcStreak(doneDates, today)` — **чистая функция** (неделя 1, день 4): результат зависит только от аргументов. Её:
- легко проверить в консоли с любыми датами;
- легко **протестировать** на неделе 7 (SPEC, неделя 7, день 3);
- легко использовать в геттере.

Положи её в `utils/streak.js` (или в `utils/date.js`).

Параметр `today` с значением по умолчанию — чтобы в тестах можно было подставить **любой** «сегодняшний» день, а не настоящий. Помнишь параметры по умолчанию из дня 1 недели 0?

### Геттер

```js
const streakOf = computed(() => (id) => {
  const habit = habits.value.find((h) => h.id === id)
  return habit ? calcStreak(habit.doneDates) : 0
})
```

Геттер с параметром (день 2), который вызывает чистую функцию.

## Часть 4. Подводные камни

### ⚠️ Бесконечный цикл

Если забыть сдвинуть день внутри `while`, условие никогда не станет ложным, и вкладка браузера **зависнет**. Если такое случилось — закрой вкладку. Перед запуском проверь глазами: меняется ли внутри цикла то, что проверяется в условии.

### ⚠️ Копия даты

```js
const day = today          // ✗ та же ссылка — setDate испортит переданную дату
const day = new Date(today) // ✓ копия
```

### ⚠️ Дубликаты в `doneDates`

Если из-за ошибки в `toggleToday` одна дата попала в массив дважды, алгоритм «шагать назад» этого не заметит — и правильно. А вот `doneDates.length` (сколько раз выполнено) станет неверным. Проверь свой `toggleToday`: не добавляет ли он дату повторно.

# Занятие 3. Процент выполнения и доводка

## Часть 5. Процент выполнения

Из SPEC: **выполненные дни / дни с `createdAt` по сегодня**.

```
процент = doneDates.length / (дней с создания включительно) × 100
```

«Дней с создания включительно» — сегодняшняя разминка, вопрос 2.

### ⚠️ Подводные камни

- **Привычку создали сегодня**: дней = 1, а не 0 — иначе деление на 0 (неделя 1, день 5);
- **Отметки до даты создания**: если вдруг есть, процент может превысить 100%. Можно ограничить: `Math.min(100, …)`;
- **Округление** — при показе: `Math.round(percent)` или `toFixed(0)`.

Это тоже хорошая чистая функция для `utils/` — и для тестов на неделе 7.

### Общий процент за сегодня

Для «Статистики»: сколько привычек выполнено **сегодня** из всех — `doneTodayCount / total × 100`. Не забудь про `total = 0`.

## Часть 7. 📜 Как это в Options API

Чистые функции `calcStreak` и процента — **одинаковы** в обоих стилях. А геттеры в options-сторе выглядели бы так:

```js
getters: {
  categories: (state) => [...new Set(state.habits.map((h) => h.category))],
  streakOf: (state) => (id) => {
    const habit = state.habits.find((h) => h.id === id)
    return habit ? calcStreak(habit.doneDates) : 0
  },
},
```

В компоненте на Options API фильтр — в `data` и `computed`:

```js
export default {
  data() {
    return { selected: '' }
  },
  computed: {
    ...mapState(useHabitsStore, ['habits', 'categories']),
    visible() {
      return this.selected ? this.habits.filter((h) => h.category === this.selected) : this.habits
    },
  },
}
```
