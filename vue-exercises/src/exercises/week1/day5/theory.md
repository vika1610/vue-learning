```js
const orders = [
  { id: 1, sum: 1200, paid: true },
  { id: 2, sum: 800, paid: false },
  { id: 3, sum: 2500, paid: true },
]

// 1
const { sum } = orders[2]

// 2
const paidTotal = orders
  .filter((o) => o.paid)
  .reduce((acc, o) => acc + o.sum, 0)
```

3. `ids` → `[1, 2, 3]`: деструктуризация прямо в параметре стрелки, как в твоей `toJSON`.

## Часть 1. Карта недели 1

За неделю ты прошла основу Vue. Всё вместе:

| День | Что узнала | Главная мысль |
|---|---|---|
| 1 | `.vue`-файл, `<script setup>`, `{{ }}` | шаблон описывает, как выглядит страница |
| 2 | директивы, `v-bind` / `:` | в кавычках у `:` — JavaScript |
| 3 | `ref`, `reactive`, `@click` | реактивность: Vue сам замечает изменения |
| 4 | `computed`, `:class`, `:style` | значения, которые вычисляются из других |

### Как всё связано

```
         ref / reactive  ← ИСХОДНЫЕ данные (то, что вводит или меняет пользователь)
               │
               ▼
           computed      ← ВЫЧИСЛЕННЫЕ данные (то, что получается из исходных)
               │
               ▼
 template: {{ }}, :attr, :class, :style   ← ПОКАЗ на странице
               ▲
               │
            @click       ← ДЕЙСТВИЯ пользователя меняют исходные данные
```

Это **главная схема любого Vue-компонента**. Пользователь что-то делает → меняются исходные данные → пересчитываются вычисленные → обновляется страница. Ты нигде не трогаешь DOM руками.

## Часть 2. Как спланировать мини-проект

Самая частая ошибка новичка — сразу начать писать шаблон. Лучше сначала **5 минут подумать на бумаге**. Вот рецепт из трёх вопросов.

### Вопрос 1. Что **вводит** пользователь? → `ref`

Это всё, что может измениться от действий пользователя: поля, выбранные кнопки, переключатели. Каждое — отдельный `ref` (или поле `reactive`).

### Вопрос 2. Что **получается** из введённого? → `computed`

Всё, что можно посчитать из данных первого шага. Никогда не храни такие значения в отдельных `ref`: иначе придётся вручную обновлять их при каждом изменении, и рано или поздно они «разъедутся».

### Вопрос 3. Что **показать** и **когда**? → шаблон и `:class`

Что выводится, при каких условиях что-то подсвечивается или меняется.

### Пример: «Расчёт стоимости поездки на такси»

Задача: пользователь вводит расстояние в километрах и выбирает тариф «эконом» (30 ₽/км) или «комфорт» (50 ₽/км). Показать стоимость, а если поездка дороже 2000 ₽, выделить цену оранжевым.

| Шаг | Ответ |
|---|---|
| вводит | `distance` (число), `tariff` (`'economy'` или `'comfort'`) |
| получается | `pricePerKm` (зависит от тарифа), `total` (расстояние × цена за км), `isExpensive` (`total > 2000`) |
| показать | поле расстояния, две кнопки тарифа (выбранная подсвечена), итог с классом `expensive` |

Дальше код пишется почти сам:

```js
const distance = ref(10)
const tariff = ref('economy')

const prices = { economy: 30, comfort: 50 }      // объект-словарь (день 4)
const pricePerKm = computed(() => prices[tariff.value])
const total = computed(() => distance.value * pricePerKm.value)
const isExpensive = computed(() => total.value > 2000)
```

```vue
<button :class="{ active: tariff === 'economy' }" @click="tariff = 'economy'">Эконом</button>
<button :class="{ active: tariff === 'comfort' }" @click="tariff = 'comfort'">Комфорт</button>
<p :class="{ expensive: isExpensive }">Итого: {{ total }} ₽</p>
```

> Сделай такую табличку **для калькулятора чаевых** до того, как начнёшь писать код. Это половина решения.

## Часть 3. ⚠️ Числа из полей ввода

В задаче три поля ввода. Здесь прячутся самые частые ошибки дня.

### Значение поля — строка

Всё, что пришло из `<input>`, по умолчанию — **строка**, даже в поле `type="number"`:

```js
'100' + 10    // '10010' — склеились строки 😱
'100' * 10    // 1000 — умножение превращает строку в число
'100' - 10    // 90
```

`+` с строкой **склеивает**, а `*`, `-`, `/` — превращают строку в число. Поэтому ошибка «на сложении» коварная: умножение работает, а сложение даёт мусор.

### Решение: `v-model.number`

```vue
<input type="number" v-model.number="distance">
```

Модификатор `.number` (подробно — неделя 2, день 3) говорит Vue: «превращай введённое в число». Это самый простой способ для сегодняшней задачи.

### ⚠️ Пустое поле

Если пользователь стёр всё из поля, `v-model.number` положит туда **пустую строку** `''`. А дальше:

```js
'' * 30       // 0 — ещё ничего
1000 / ''     // Infinity 😱 — деление на пустую строку = деление на 0
```

### ⚠️ Деление на ноль

```js
1000 / 0      // Infinity
0 / 0         // NaN
```

JavaScript не выбрасывает ошибку при делении на ноль, а тихо возвращает `Infinity` или `NaN`. На экране пользователь увидит «Infinity ₽» — некрасиво и непонятно.

Поэтому **перед делением проверяй делитель**. В задаче это пункт 5: если людей 0 или меньше — показать подсказку вместо суммы на человека.

```js
const perGuest = computed(() => guests.value > 0 ? total.value / guests.value : null)
```

`null` здесь значит «посчитать нельзя». В шаблоне это можно проверить тернарным оператором.

### ⚠️ `NaN` заразен

Если хоть одна зависимость `computed` стала `NaN`, все вычисления после неё тоже будут `NaN`:

```js
NaN + 10   // NaN
NaN * 2    // NaN
```

Если на экране появился `NaN` — иди по цепочке `computed` назад и ищи, где он родился. Удобнее всего во Vue DevTools: там видны значения всех `ref` и `computed`.

## Часть 4. Деньги на экране

### Функцию можно вызывать прямо в шаблоне

Помнишь `formatPrice` из недели 0? Её можно положить в `<script setup>` и вызывать в `{{ }}`:

```vue
<script setup>
function formatMoney(value) {
  return value.toLocaleString('ru-RU', { maximumFractionDigits: 0 }) + ' ₽'
}
</script>

<template>
  <p>Итого: {{ formatMoney(total) }}</p>
</template>
```

Это функция **с аргументом**, поэтому она — функция, а не `computed` (правило дня 4).

### Можно импортировать из другого файла

Если функция нужна в нескольких местах, её выносят в отдельный модуль и импортируют, как в дне 4 недели 0:

```js
// utils/format.js
export function formatMoney(value) { /* ... */ }
```

```vue
<script setup>
import { formatMoney } from './utils/format.js'
</script>
```

Импортированная функция тоже сразу доступна в шаблоне.

### ⚠️ Округлять — при показе, а не в расчётах

```js
// ✗ плохо: округлили слишком рано
const tip = computed(() => Math.round(bill.value * percent.value / 100))
const total = computed(() => bill.value + tip.value)

// ✓ хорошо: считаем точно, округляем только при выводе
const tip = computed(() => bill.value * percent.value / 100)
const total = computed(() => bill.value + tip.value)
// в шаблоне: {{ formatMoney(total) }}
```

Если округлять на каждом шаге, ошибки округления **накапливаются**. Помнишь `89.91000000000001` из дня 4 недели 0? Точные числа держим в `computed`, красивый вид — только при выводе.

# Занятие 3. 📜 Options API и итоги недели

## Часть 5. 📜 Весь компонент в Options API

За неделю ты по отдельности видела все опции. Теперь — один компонент целиком, чтобы увидеть, как они живут вместе. Возьмём такси из части 2.

**Composition API:**

```vue
<script setup>
import { ref, computed } from 'vue'

const distance = ref(10)
const tariff = ref('economy')

const prices = { economy: 30, comfort: 50 }
const total = computed(() => distance.value * prices[tariff.value])
const isExpensive = computed(() => total.value > 2000)

function reset() {
  distance.value = 10
  tariff.value = 'economy'
}
</script>
```

**Options API:**

```vue
<script>
const prices = { economy: 30, comfort: 50 }   // константа — можно вне компонента

export default {
  data() {
    return {
      distance: 10,
      tariff: 'economy',
    }
  },
  computed: {
    total() {
      return this.distance * prices[this.tariff]
    },
    isExpensive() {
      return this.total > 2000
    },
  },
  methods: {
    reset() {
      this.distance = 10
      this.tariff = 'economy'
    },
  },
}
</script>
```

Шаблон у обоих — одинаковый.

### Что заметно при сравнении

| | Composition API | Options API |
|---|---|---|
| Структура | код идёт сверху вниз, в любом порядке | разложен по «полочкам»: `data` → `computed` → `methods` |
| Реактивность | явно: `ref()`, `computed()` | неявно: всё из `data()` и `computed` |
| Доступ к данным | `x.value` | `this.x` |
| Импорты из `'vue'` | нужны | не нужны |
| Константы вроде `prices` | просто `const` в `<script setup>` | вне `export default` (или в `data`, если должны быть реактивными) |

### ⚠️ Константы вне компонента и в шаблоне

`prices`, объявленный **вне** `export default`, в Options API **недоступен в шаблоне** (шаблон видит только то, что есть у компонента: `data`, `computed`, `methods`…). В скрипте — пожалуйста, а `{{ prices.economy }}` не сработает.

В `<script setup>` такой проблемы нет: всё, что объявлено на верхнем уровне, видно в шаблоне. Это и есть главное свойство `setup`, которое ты разбирала на повторе.

### Порядок опций

Vue не важно, в каком порядке идут опции. Но в командах обычно договариваются о порядке, чтобы код было легко читать. Самый частый: `components`, `props`, `emits`, `data`, `computed`, `watch`, хуки (`mounted` и т. п.), `methods`. Если на работе есть принятый порядок — держись его.
