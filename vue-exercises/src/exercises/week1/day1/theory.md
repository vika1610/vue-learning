## Часть 1. Что такое Vue и зачем он нужен

### Вспомни, как ты делала страницу в неделе 0

В дне 5 ты выводила список пользователей так:

```js
container.textContent = 'Загрузка…'
const ul = document.createElement('ul')
for (const name of names) {
  const li = document.createElement('li')
  li.textContent = name
  ul.appendChild(li)
}
container.textContent = ''
container.appendChild(ul)
```

Ты **вручную** командуешь браузеру: «создай элемент, вставь текст, добавь туда, очисти здесь». Это называется **императивный** подход: описываешь, **как** изменить страницу, шаг за шагом.

А если данные поменялись, все шаги нужно повторить и не забыть ничего очистить. В большом приложении это быстро превращается в кашу.

### Как это делает Vue

Во Vue ты описываешь, **как страница должна выглядеть** при текущих данных, а Vue сам поддерживает её в этом состоянии:

```html
<ul>
  <li v-for="name in names">{{ name }}</li>
</ul>
```

`v-for` будет на неделе 2, сейчас важна идея. Здесь нет ни `createElement`, ни `appendChild`, ни очистки. Это **декларативный** подход: «вот шаблон, а вот данные, разберись сам».

| | Чистый JS (неделя 0) | Vue |
|---|---|---|
| Что ты пишешь | шаги: создай, вставь, удали | как должна выглядеть страница |
| Данные изменились | обновляешь страницу вручную | Vue обновляет сам |
| Безопасность текста | нужно помнить про `textContent` | `{{ }}` всегда безопасен |

### Две главные идеи Vue

1. **Декларативный рендеринг** — шаблон описывает, как данные превращаются в HTML.
2. **Реактивность** — Vue следит за данными и сам обновляет страницу, когда они меняются. Это тема дня 3.

## Часть 3. Однофайловый компонент (SFC)

### Компонент — это кусочек интерфейса

Страница во Vue собирается из **компонентов**, как из кирпичиков: шапка, карточка товара, кнопка, форма. Каждый компонент — это отдельный файл с расширением `.vue`.

Все твои задачи в `vue-exercises` — это компоненты: файлы `Exercise.vue`.

### Три части файла `.vue`

```vue
<script setup>
// 1. Логика: данные и функции на JavaScript
const city = 'Казань'
</script>

<template>
  <!-- 2. Разметка: HTML с особыми возможностями Vue -->
  <p>Я живу в городе {{ city }}</p>
</template>

<style scoped>
/* 3. Стили — только для этого компонента */
p { color: green; }
</style>
```

| Блок | Что внутри | Обязателен? |
|---|---|---|
| `<script setup>` | JavaScript: данные, функции, импорты | нет, но почти всегда есть |
| `<template>` | разметка | да |
| `<style scoped>` | CSS | нет |

Отсюда название **SFC** — Single File Component, «однофайловый компонент»: логика, разметка и стили одного кусочка интерфейса лежат вместе.

### `<script setup>`

Слово `setup` — это особый режим: всё, что ты **объявила** на верхнем уровне `<script setup>` (переменные, функции, импорты), **автоматически доступно** в `<template>`. Ничего экспортировать не нужно.

```vue
<script setup>
const pet = 'кот'
const legs = 4
function sound() {
  return 'мяу'
}
</script>

<template>
  <p>{{ pet }} говорит «{{ sound() }}», у него {{ legs }} лапы</p>
</template>
```

Сравни с модулями из дня 4: там ты писала `export`, чтобы отдать функцию наружу. В `<script setup>` Vue делает это сам — для шаблона.

### `scoped` в стилях

`<style scoped>` означает: стили действуют **только внутри этого компонента**. Если написать `p { color: green }`, позеленеют только абзацы этого компонента, а не все абзацы на странице. Без `scoped` стили стали бы глобальными.

### ⚠️ Подводные камни SFC

- `<template>` должен быть **один** на файл.
- Код в `<script setup>` — это обычный JavaScript-модуль. Работают `import`, `const`, функции, всё, что ты знаешь из недели 0.
- Комментарии в `<template>` пишутся как в HTML: `<!-- ... -->`, а не `//`.

# Занятие 2. Вывод данных и практика

## Часть 4. Интерполяция `{{ }}`

### Вывод данных в шаблоне

Двойные фигурные скобки — «окошко», через которое значение из `<script setup>` попадает на страницу:

```vue
<script setup>
const title = 'Мастер и Маргарита'
const year = 1967
</script>

<template>
  <h1>{{ title }}</h1>
  <p>Год: {{ year }}</p>
</template>
```

Их называют «усы» (mustache) — из-за формы 🙂

### Внутри `{{ }}` — любое выражение JS

```vue
<template>
  <p>{{ title.toUpperCase() }}</p>          <!-- МАСТЕР И МАРГАРИТА -->
  <p>Прошло лет: {{ 2026 - year }}</p>       <!-- арифметика -->
  <p>{{ year > 1950 ? 'новая' : 'старая' }}</p>  <!-- тернарный оператор -->
  <p>{{ `«${title}», ${year}` }}</p>         <!-- шаблонная строка -->
  <p>{{ title.length }} символов</p>         <!-- свойство -->
</template>
```

Всё, что ты знаешь из недели 0, работает и здесь: методы строк, тернарный оператор, шаблонные строки.

### ⚠️ Только выражения, не инструкции

**Выражение** — то, что даёт значение: `a + b`, `name.length`, `x > 0 ? 'да' : 'нет'`, вызов функции.
**Инструкция** — команда: `if`, `for`, `let x = 1`.

```vue
{{ year + 1 }}                  ✓ выражение
{{ year > 2000 ? 'да' : 'нет' }} ✓ выражение
{{ if (year > 2000) { 'да' } }}  ✗ ошибка: if — инструкция
{{ const x = 1 }}                ✗ ошибка: объявление — инструкция
```

Подсказка: если что-то можно поставить справа от `=` в `const result = ...`, это выражение и оно подойдёт для `{{ }}`.

Вот почему тернарный оператор из недели 0 так пригодится: это «`if` в виде выражения».

### ⚠️ Сложную логику — в `<script setup>`

```vue
<!-- плохо: шаблон трудно читать -->
<p>{{ title.split(' ').map((w) => w[0]).join('').toUpperCase() }}</p>

<!-- хорошо: логика в функции с понятным именем -->
<p>{{ initials() }}</p>
```

Правило: если выражение в `{{ }}` не помещается в голове с одного взгляда, вынеси его в функцию в `<script setup>`. На дне 4 для этого появится ещё и `computed`.

### `{{ }}` всегда безопасен

```vue
<script setup>
const evil = '<b>жирный</b>'
</script>

<template>
  <p>{{ evil }}</p>   <!-- покажет буквально: <b>жирный</b> -->
</template>
```

`{{ }}` работает как `textContent` из недели 0: выводит **текст**, а не HTML. Проблема с `innerHTML` из дня 5 во Vue решена за тебя.

### ⚠️ `{{ }}` работает только в тексте, не в атрибутах

```vue
<img src="{{ photoUrl }}">   ✗ не сработает: браузер получит буквально "{{ photoUrl }}"
```

Для атрибутов (`src`, `href`, `title`, `class`…) нужна директива `v-bind`. Это тема дня 2.

### ⚠️ Опечатка в имени переменной

```vue
<script setup>
const title = 'Книга'
</script>

<template>
  <p>{{ titel }}</p>   <!-- опечатка -->
</template>
```

Страница не упадёт, просто покажет пустоту, а в консоли браузера появится **предупреждение** вида *Property "titel" was accessed during render but is not defined*. Если что-то не выводится, первым делом открой консоль (F12).

### Что можно использовать в шаблоне

В `{{ }}` доступны:
- всё, что объявлено в `<script setup>`;
- некоторые встроенные объекты JS: `Math`, `Date`, `JSON`, `String`, `Number`, `Array`…

```vue
<p>{{ Math.round(4.7) }}</p>  ✓ 5
```

А вот `window`, `document`, `console` и твои глобальные переменные **недоступны**: шаблон нарочно изолирован. Если очень нужно, используй их через функцию в `<script setup>`.

## Часть 5. Как меняется страница

### Горячая перезагрузка

Когда ты сохраняешь `.vue`-файл, Vite (инструмент, который запускает проект по `npm run dev`) **сам** обновляет страницу в браузере. Перезагружать вручную не нужно. Это называется HMR (Hot Module Replacement).

Поэтому в практике задание «поменяй значения и посмотри» выглядит так: поменяй строку в коде → **Ctrl + S** → смотри в браузер.

### ⚠️ Обычные переменные — не реактивные

Попробуй (это небольшой забег вперёд):

```vue
<script setup>
let count = 0
setTimeout(() => {
  count = 10
  console.log('count теперь', count)
}, 2000)
</script>

<template>
  <p>{{ count }}</p>
</template>
```

Через 2 секунды в консоли будет `count теперь 10`, а на странице — **по-прежнему 0**. Vue не знает, что обычная переменная изменилась, и не перерисовывает шаблон.

Сегодня это не мешает: в задаче значения не меняются, пока страница открыта. А как сделать так, чтобы Vue следил за данными, ты узнаешь на дне 3 (`ref` и `reactive`). Это и есть та самая **реактивность**.

> Если поменять значение **в коде** и сохранить файл, страница обновится, но это заслуга горячей перезагрузки, а не реактивности. Vite просто перезапустил компонент с новым кодом.

# Занятие 3. Как было раньше: Options API

## Часть 6. 📜 Options API — «старый» стиль Vue

### Два стиля написания компонентов

У Vue есть **два способа** описать логику компонента. Шаблон (`<template>`) и стили в обоих одинаковые, отличается только `<script>`.

| | **Options API** | **Composition API** |
|---|---|---|
| Как выглядит | `export default { data(), methods, ... }` | `<script setup>` с обычными переменными и функциями |
| Когда появился | с самого начала, Vue 2 | Vue 3 (2020) |
| Где встречается | старые и многие рабочие проекты | новые проекты, документация по умолчанию |
| Поддерживается в Vue 3 | ✅ да, полностью | ✅ да |

В этом курсе основной стиль — Composition API (`<script setup>`). Но Options API **не устарел и не запрещён**: Vue 3 поддерживает его полностью, и в рабочих проектах он встречается очень часто, иногда оба стиля в одном проекте.

> В документации ru.vuejs.org слева вверху есть переключатель **«Options / Composition»**. Он меняет все примеры на сайте на нужный стиль. Очень удобно, чтобы читать про одну тему в обоих вариантах.

### Тот же компонент в двух стилях

**Composition API** (как в частях 3–4):

```vue
<script setup>
const city = 'Казань'
const legs = 4

function sound() {
  return 'мяу'
}
</script>

<template>
  <p>В городе {{ city }} кот говорит «{{ sound() }}», у него {{ legs }} лапы</p>
</template>
```

**Options API**:

```vue
<script>
export default {
  data() {
    return {
      city: 'Казань',
      legs: 4,
    }
  },
  methods: {
    sound() {
      return 'мяу'
    },
  },
}
</script>

<template>
  <p>В городе {{ city }} кот говорит «{{ sound() }}», у него {{ legs }} лапы</p>
</template>
```

Шаблон **один в один**. А в `<script>` вместо отдельных переменных и функций — **один объект** с «опциями», разложенными по полочкам: данные отдельно, функции отдельно. Отсюда и название: Options API, «API опций».

### Разбор по частям

**`<script>` без `setup`** и **`export default { ... }`**. Компонент — это объект, который модуль отдаёт по умолчанию. Помнишь `export default` из дня 4 недели 0? Здесь он обязателен: без него Vue не увидит компонент.

**`data()`** — **функция**, которая **возвращает объект** с данными компонента. Всё, что в этом объекте, доступно в шаблоне.

**`methods`** — объект с функциями компонента. Тоже доступны в шаблоне.

### Главное отличие: `this`

В Options API внутри методов к данным обращаются через **`this`**:

```js
export default {
  data() {
    return { name: 'Аня', age: 25 }
  },
  methods: {
    greeting() {
      return `Привет, ${this.name}!`   // ← this.name, а не просто name
    },
    nextYear() {
      return this.age + 1
    },
  },
}
```

`this` — это сам компонент. Vue собирает в него и данные из `data()`, и методы из `methods`. Это прямое применение темы `this` из дня 4 недели 0: «объект перед точкой». Vue вызывает метод как `компонент.greeting()`, поэтому `this` — компонент.

А **в шаблоне** `this` писать **не нужно**: `{{ name }}`, а не `{{ this.name }}`. В этом стили одинаковые.

### ⚠️ Подводный камень 1: стрелочные функции в `methods`

```js
methods: {
  greeting: () => `Привет, ${this.name}!`,  // ✗ this — не компонент!
}
```

У стрелок нет своего `this` (день 4 недели 0, часть 2). Здесь `this` будет `undefined`, и код упадёт. **Методы в Options API — только обычные функции.** Короткая запись `greeting() { ... }` — самый удобный вариант.

А вот **внутри** метода стрелки можно и нужно использовать, например в `map` или `setTimeout`: они возьмут `this` метода.

### ⚠️ Подводный камень 2: `data` — функция, а не объект

```js
data: { name: 'Аня' },          // ✗ так было можно в очень старом Vue 2, во Vue 3 — ошибка
data() { return { name: 'Аня' } }, // ✓
```

Почему функция? Если на странице **три** одинаковых компонента-карточки, у каждой должны быть **свои** данные. Функция `data()` вызывается для каждой карточки заново и создаёт **новый** объект. А если бы `data` был одним объектом, все три карточки делили бы **одну ссылку** на него: поменяла данные в одной — поменялось во всех. Помнишь ссылки из дня 2 недели 0? Вот где они пригодились.

Это та же идея, что и у `makeCounter`: каждый вызов функции создаёт свою независимую копию данных.

### ⚠️ Подводный камень 3: забытый `this.`

```js
methods: {
  greeting() {
    return `Привет, ${name}!`  // ✗ ищет переменную name, а её нет
  },
}
```

Ошибка из дня 4 недели 0, та же самая. Внутри методов **всё** из компонента — только через `this.`.

### Важное отличие: в Options API данные из `data()` реактивны сразу

Помнишь часть 5: обычная переменная в `<script setup>` **не** обновляет страницу, для этого нужен `ref` (день 3)?

В Options API всё, что вернул `data()`, Vue **сразу делает реактивным**. Если в методе написать `this.age = 30`, страница обновится сама, без всяких `ref`.

| | Composition API | Options API |
|---|---|---|
| Обычные данные | `const x = 1` — **не реактивные** | — |
| Реактивные данные | `const x = ref(1)` (день 3) | всё из `data()` — **реактивно сразу** |
| Изменить в скрипте | `x.value = 2` (день 3) | `this.x = 2` |

Это одна из причин, почему Options API считается проще для новичков: не надо думать, что реактивно, а что нет. Зато в большом компоненте логика одной фичи «размазана» по разным полочкам (`data`, `methods`, `computed`, `watch`…), и её трудно собрать вместе. Composition API решает именно эту проблему.

### Остальные «полочки» — превью на будущее

В Options API для каждой темы курса есть своя опция. Мы будем проходить их по ходу курса, а пока просто карта, чтобы узнавать их в рабочем коде:

| Опция | Что это | Аналог в `<script setup>` | Когда в курсе |
|---|---|---|---|
| `data()` | данные | `ref`, `reactive` | день 3 |
| `methods` | функции | обычные функции | сегодня |
| `computed` | вычисляемые значения | `computed()` | день 4 |
| `watch` | следить за изменениями | `watch()` | неделя 2 |
| `mounted()`, `unmounted()` | хуки жизненного цикла | `onMounted()`, `onUnmounted()` | неделя 2 |
| `props` | входные параметры | `defineProps()` | неделя 3 |
| `emits` | события компонента | `defineEmits()` | неделя 3 |
| `components` | подключить дочерние компоненты | просто `import` | неделя 3 |

> ⚠️ В Options API дочерние компоненты нужно не только импортировать, но и **зарегистрировать** в опции `components: { ProductCard }`. В `<script setup>` достаточно `import`. Частая ошибка при переписывании кода из одного стиля в другой.

### Как узнать стиль в рабочем коде

| Видишь в `.vue`-файле | Это |
|---|---|
| `<script setup>` | Composition API с «сахаром» `setup` (как у нас) |
| `<script>` + `export default {` + `data()` / `methods` | **Options API** |
| `export default {` + функция `setup() { ... return { ... } }` | Composition API без «сахара» — переходный вариант, тоже встречается |
| `export default defineComponent({ ... })` | обёртка для TypeScript; внутри может быть любой из стилей |
| `new Vue({ ... })` в `main.js`, `this.$set(...)` | это **Vue 2**, а не Vue 3. Синтаксис Options API почти тот же, но есть отличия |

Версию Vue в любом проекте можно узнать в `package.json`: строка `"vue": "^3..."` или `"^2..."`.
