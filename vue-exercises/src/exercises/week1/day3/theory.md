# Занятие 1. Как Vue замечает изменения и `ref`

## Разминка (10 мин): геттеры, сеттеры и Proxy

Это «обзорная» тема: писать такое руками во Vue почти не придётся. Но она объясняет, **как Vue узнаёт**, что данные изменились. Попробуй примеры в консоли браузера.

### Геттеры и сеттеры

У объекта бывают «умные» свойства: при чтении или записи вызывается **функция**.

```js
const thermometer = {
  _celsius: 20,
  get celsius() {
    console.log('кто-то читает температуру')
    return this._celsius
  },
  set celsius(value) {
    console.log('кто-то меняет температуру на', value)
    this._celsius = value
  },
}

thermometer.celsius        // в консоли: «кто-то читает температуру», результат 20
thermometer.celsius = 25   // в консоли: «кто-то меняет температуру на 25»
```

Снаружи `thermometer.celsius` выглядит как обычное свойство, но на самом деле на каждое обращение срабатывает функция. Объект «знает», когда его читают и когда меняют.

### Proxy — «охранник» для всего объекта

`Proxy` делает то же самое, но сразу для **всех** свойств объекта, даже тех, которых ещё нет:

```js
const original = { name: 'Аня', age: 25 }

const watched = new Proxy(original, {
  get(target, key) {
    console.log(`читают ${key}`)
    return target[key]
  },
  set(target, key, value) {
    console.log(`меняют ${key} на ${value}`)
    target[key] = value
    return true
  },
})

watched.name         // «читают name»
watched.age = 26     // «меняют age на 26»
watched.city = 'Сочи' // «меняют city на Сочи» — даже новое свойство
```

### Как это связано с Vue

Именно так Vue и устроен. Когда ты делаешь данные «реактивными», Vue оборачивает их в такого охранника:

- **при чтении** (например, шаблон выводит `{{ score }}`) Vue запоминает: «этот шаблон зависит от `score`»;
- **при записи** (`score` поменялся) Vue вспоминает, кто от него зависит, и **перерисовывает** именно эти места страницы.

Всё, что ты дальше прочитаешь про `ref` и `reactive`, — это способы попросить Vue «поставить охранника» на твои данные.

## Часть 1. Зачем нужна реактивность

Помнишь эксперимент из дня 1?

```vue
<script setup>
let score = 0
setTimeout(() => {
  score = 100
  console.log('score теперь', score)
}, 2000)
</script>

<template>
  <p>Очки: {{ score }}</p>
</template>
```

Через 2 секунды консоль пишет `100`, а на странице по-прежнему `0`. Теперь понятно почему: `score` — **обычная переменная**, у неё нет «охранника». Vue прочитал её один раз при отрисовке и больше не знает, что она изменилась.

> **Реактивность** — это когда Vue сам замечает изменение данных и сам обновляет страницу. Без реактивности пришлось бы вручную менять DOM, как ты делала в неделе 0 через `textContent`.

## Часть 2. `ref` — реактивная «коробка» для значения

### Создание

```vue
<script setup>
import { ref } from 'vue'

const score = ref(0)
</script>
```

- `ref` нужно **импортировать** из `'vue'` — это обычный модуль, как в дне 4 недели 0;
- `ref(0)` создаёт **реактивную коробку**, внутри которой лежит число `0`.

### `.value` — содержимое коробки

`ref` возвращает не само число, а **объект-обёртку**. Значение лежит в его свойстве `.value`:

```js
const score = ref(0)

console.log(score)        // RefImpl { ... } — коробка
console.log(score.value)  // 0 — содержимое

score.value = 10          // положили в коробку новое значение
score.value++             // и ещё увеличили — 11
```

Зачем коробка? Обычное число `0` нельзя «охранять»: это примитив, у него нет свойств, на которые можно повесить геттер и сеттер. А у объекта-коробки есть свойство `value` с геттером и сеттером внутри. Это прямо то, что ты видела в разминке.

### В шаблоне `.value` не нужен

```vue
<template>
  <p>Очки: {{ score }}</p>   <!-- ✓ не score.value -->
</template>
```

Vue в шаблоне **сам «распаковывает»** ref: увидел коробку, достал содержимое. Это сделано для удобства, ведь в шаблоне ref-ы встречаются постоянно.

| Где | Как писать |
|---|---|
| в `<script setup>` | `score.value` |
| в `<template>` | `score` |

Это правило — **ответ на один из вопросов недели**. Повтори его вслух 🙂

### Теперь страница обновляется

```vue
<script setup>
import { ref } from 'vue'

const score = ref(0)
setTimeout(() => {
  score.value = 100
}, 2000)
</script>

<template>
  <p>Очки: {{ score }}</p>
</template>
```

Через 2 секунды на странице сам по себе появится `100`. Ни `textContent`, ни `querySelector` — Vue всё сделал сам.

### ⚠️ `const` и ref — не противоречие

```js
const score = ref(0)
score.value = 100   // ✓ можно!
score = 100         // ✗ ошибка: score — const
```

`const` запрещает положить в переменную **другую коробку**. А менять **содержимое** коробки можно сколько угодно. Это ровно та же история, что с `const`-массивом из недели 0: ссылка постоянная, содержимое меняется. Поэтому ref-ы почти всегда объявляют через `const`.

### ref может хранить что угодно

```js
const name = ref('Аня')          // строку
const isOpen = ref(false)        // булево
const tags = ref(['js', 'vue'])  // массив
const user = ref({ age: 25 })    // объект

tags.value.push('css')           // меняем массив внутри коробки — реактивно
user.value.age = 26              // меняем поле объекта — тоже реактивно
```

Если внутри объект или массив, Vue делает реактивными и **их содержимое**, на любую глубину.

## Часть 3. Первые клики: `@click`

Чтобы данные менялись не по таймеру, а по кнопке, нужен **обработчик события**. Подробно события будут на неделе 2, сейчас — самый минимум.

### Синтаксис

```vue
<script setup>
import { ref } from 'vue'

const lives = ref(3)

function loseLife() {
  lives.value--
}
</script>

<template>
  <p>Жизни: {{ lives }}</p>
  <button @click="loseLife">Потерять жизнь</button>
</template>
```

- `@click` — это короткая запись директивы `v-on:click`, как `:` — короткая запись `v-bind`;
- в кавычках — **функция**, которую Vue вызовет при клике.

Сравни с неделей 0:

```js
// неделя 0, день 4
button.addEventListener('click', loseLife)
```

```vue
<!-- Vue -->
<button @click="loseLife">
```

Идея та же, но Vue сам находит кнопку и сам подписывается на событие.

### Короткие действия — прямо в шаблоне

```vue
<button @click="lives++">Добавить жизнь</button>
<button @click="lives = 3">Начать заново</button>
```

В шаблоне ref распаковывается, поэтому `lives++`, а не `lives.value++`. Для одной короткой операции это удобно, для чего-то длиннее — выноси в функцию.

### ⚠️ Знакомая ловушка: вызов вместо передачи?

В отличие от `addEventListener`, во Vue **обе записи работают**:

```vue
<button @click="loseLife">     ✓ Vue вызовет функцию при клике
<button @click="loseLife()">   ✓ тоже работает — Vue сам «завернёт» это в функцию
```

Vue понимает: раз это `@click`, код в кавычках нужно выполнить **при клике**, а не сразу. Вторая запись пригодится, когда нужно передать аргумент: `@click="addPoints(10)"`.

# Занятие 2. `reactive`, подводные камни и практика

## Часть 4. `reactive` — реактивный объект

### Создание

```vue
<script setup>
import { reactive } from 'vue'

const game = reactive({
  score: 0,
  lives: 3,
  player: 'Аня',
})

function hit() {
  game.lives--          // без .value!
  game.score += 10
}
</script>

<template>
  <p>{{ game.player }}: очки {{ game.score }}, жизни {{ game.lives }}</p>
  <button @click="hit">Удар</button>
</template>
```

`reactive` делает реактивным **сам объект**. Коробки нет, поэтому нет и `.value`: работаешь с полями как с обычным объектом. Под капотом это тот самый `Proxy` из разминки.

### `ref` и `reactive` рядом

| | `ref` | `reactive` |
|---|---|---|
| Что можно положить | **что угодно**: число, строку, массив, объект | **только объект** (или массив) |
| Доступ в скрипте | `x.value` | `obj.поле` |
| Доступ в шаблоне | `x` | `obj.поле` |
| Заменить целиком | `x.value = новое` ✓ | ✗ нельзя (см. ловушки) |

---

## Часть 5. Подводные камни

### ⚠️ 1. Забытый `.value` в скрипте

```js
const score = ref(0)

function add() {
  score++          // ✗ TypeError: Assignment to constant variable
}
```

`score++` пытается изменить **саму переменную** (коробку), а она `const`. Нужно `score.value++`.

А если объявить через `let`, будет ещё хуже — **без ошибки**:

```js
let score = ref(0)
score++   // score стал NaN — коробку превратили в число, реактивность потеряна
```

Поэтому ref-ы объявляй **только через `const`**: тогда забытый `.value` сразу даст понятную ошибку.

### ⚠️ 2. `.value` в шаблоне

```vue
<p>{{ score.value }}</p>   <!-- ✗ на странице пусто -->
```

В шаблоне Vue **уже** распаковал ref: `score` здесь — это число `0`. А у числа нет поля `value`, поэтому `0.value` даёт `undefined`, и на странице пусто, без ошибки. Запомни правило: **в шаблоне — без `.value`**.

### ⚠️ 3. `reactive` с примитивом

```js
const count = reactive(0)   // ✗ не работает: предупреждение в консоли, реактивности нет
```

`reactive` умеет работать только с объектами. Для числа, строки, булева — только `ref`.

### ⚠️ 4. Замена `reactive` целиком

```js
let game = reactive({ score: 0 })

function restart() {
  game = reactive({ score: 0 })   // ✗ шаблон по-прежнему смотрит на СТАРЫЙ объект
}
```

Шаблон «подписан» на первый объект. Новая переменная с новым объектом ему неизвестна. Правильно — менять **поля**, а не весь объект:

```js
const game = reactive({ score: 0, lives: 3 })

function restart() {
  game.score = 0
  game.lives = 3
}
```

(Или `Object.assign(game, { score: 0, lives: 3 })` — помнишь, `Object.assign` меняет первый аргумент? Здесь это как раз то, что нужно.)

У `ref` такой проблемы нет: `state.value = { score: 0 }` — коробка та же, поменялось содержимое.

### ⚠️ 5. Деструктуризация `reactive` ломает реактивность

```js
const game = reactive({ score: 0, lives: 3 })

const { score } = game   // ✗ score — просто число 0, без «охранника»

score++                  // game.score не изменится, страница тоже
```

Деструктуризация (день 3 недели 0) **копирует значения** в новые переменные. Число копируется как примитив — связь с объектом теряется. Работай через `game.score`.

> На неделе 6 (Pinia) эта же проблема всплывёт снова, и там для неё есть специальное решение. Запомни уже сейчас: **«деструктуризация реактивного объекта = потеря реактивности»**.

### ⚠️ 6. `console.log` показывает «странные» объекты

```js
console.log(ref(5))           // RefImpl { _value: 5, ... }
console.log(reactive({ a: 1 })) // Proxy(Object) { a: 1 }
```

Это нормально: ты видишь коробку и охранника. Чтобы посмотреть содержимое, логируй `x.value` или конкретные поля. А удобнее всего смотреть данные компонента во **Vue DevTools**: там они показаны как есть и меняются в реальном времени.

### ⚠️ 7. Изменения вне реактивного объекта не видны

```js
const original = { score: 0 }
const game = reactive(original)

original.score = 100   // ✗ меняем мимо охранника — страница не узнает
game.score = 100       // ✓ через охранника
```

Работай всегда с тем, что вернул `reactive`, а исходный объект забудь.

## Часть 6. Что выбрать: `ref` или `reactive`

Официальная документация Vue советует: **по умолчанию используй `ref`**.

- `ref` работает с любыми типами;
- его можно заменять целиком;
- деструктуризация и передача в функции менее опасны.

`reactive` удобен, когда есть **группа связанных полей** (например, форма с пятью полями на неделе 2), и не хочется писать `.value` пять раз.

На практике в коде встречается и то и другое, поэтому важно понимать оба.

# Занятие 3. 📜 Options API

## Часть 7. 📜 Реактивность в Options API

### Всё из `data()` реактивно сразу

Помнишь из дня 1: в Options API данные из `data()` **сразу реактивны**? Теперь понятно, что это значит: Vue сам оборачивает возвращённый объект в `reactive` (того самого «охранника»). Поэтому ни `ref`, ни `reactive` импортировать не нужно.

**Composition API:**

```vue
<script setup>
import { ref } from 'vue'

const lives = ref(3)

function loseLife() {
  lives.value--
}
</script>

<template>
  <p>Жизни: {{ lives }}</p>
  <button @click="loseLife">Потерять жизнь</button>
</template>
```

**Options API:**

```vue
<script>
export default {
  data() {
    return {
      lives: 3,
    }
  },
  methods: {
    loseLife() {
      this.lives--
    },
  },
}
</script>

<template>
  <p>Жизни: {{ lives }}</p>
  <button @click="loseLife">Потерять жизнь</button>
</template>
```

| | Composition API | Options API |
|---|---|---|
| Сделать реактивным | `ref(3)` / `reactive({...})` | положить в `data()` |
| Изменить в скрипте | `lives.value--` | `this.lives--` |
| В шаблоне | `lives` | `lives` |
| Импорт из `'vue'` | нужен | не нужен |

Шаблон опять **не меняется**: и `{{ lives }}`, и `@click="loseLife"`, и `@click="lives++"` работают одинаково.

### `this` вместо `.value`

В Options API нет `.value`. Его роль играет `this.`: «возьми данные компонента». Это значит, что ошибки похожи:

| Composition API | Options API |
|---|---|
| забыла `.value` → ошибка или потеря реактивности | забыла `this.` → `ReferenceError` |

### ⚠️ Подводные камни Options API

**1. Свойство, которого не было в `data()`, не реактивно** (точнее, может не отобразиться в шаблоне):

```js
data() {
  return { lives: 3 }
},
methods: {
  start() {
    this.score = 0   // ⚠️ score не объявлен в data() — так делать не нужно
  },
},
```

Правило: **все данные компонента заранее объявляй в `data()`**, даже если в начале там `null` или `0`. Так их видно в одном месте, и Vue про них знает с самого начала.

**2. Стрелочные функции в `methods`** — уже знакомая ловушка из дня 1: у стрелки нет своего `this`, поэтому `this.lives--` упадёт.

**3. `setTimeout` внутри метода**: вот тут стрелка как раз **нужна**:

```js
methods: {
  healLater() {
    setTimeout(() => {
      this.lives++   // ✓ стрелка взяла this метода
    }, 1000)

    setTimeout(function () {
      this.lives++   // ✗ у обычной функции свой this — не компонент
    }, 1000)
  },
},
```

Это прямо пример из дня 4 недели 0 про `timer.start()` и `setInterval`. Там это было теорией, а здесь встречается в реальном коде.

### Как это выглядит в рабочем коде

Если в рабочем проекте увидишь в одном компоненте `data()`, а в другом — `ref()`, это нормально: Vue 3 поддерживает оба стиля. Иногда в Options API-компоненте встречается функция `setup()` с `ref` внутри — это переходный вариант, о нём будет на неделе 4.

## Шпаргалка

| Тема | Запомнить |
|---|---|
| Реактивность | Vue сам замечает изменения данных и обновляет страницу |
| Как замечает | «охранник» — геттеры/сеттеры и `Proxy` |
| `ref(значение)` | реактивная коробка для **любого** значения |
| `.value` | в скрипте — да, в шаблоне — нет |
| `const x = ref()` | можно: меняется содержимое, а не коробка |
| `reactive({...})` | реактивный объект, без `.value`; **только объекты** |
| Заменить `reactive` целиком | ✗ меняй поля |
| Деструктуризация `reactive` | ✗ теряет реактивность |
| По умолчанию | `ref` |
| `@click="fn"` | вызвать функцию при клике (`v-on:click`) |
| `@click="x++"` | короткое действие прямо в шаблоне |
| 📜 Options API | всё из `data()` реактивно; в методах `this.x` вместо `x.value` |
