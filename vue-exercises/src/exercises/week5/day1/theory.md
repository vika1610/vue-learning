# Занятие 1. Зачем роутер и как его создать

## Разминка (10 мин): URL, query string, History API

Разберём адрес по частям:

```
https://shop.ru:443/catalog/shoes?color=red&size=38#reviews
└─┬─┘   └──┬──┘└┬┘└─────┬─────┘└─────────┬────────┘└──┬──┘
протокол  домен порт    путь         параметры      якорь
                                   (query string)  (hash)
```

В браузере есть объекты для работы с адресом:

```js
location.pathname   // '/catalog/shoes'
location.search     // '?color=red&size=38'
location.hash       // '#reviews'

new URLSearchParams(location.search).get('color')   // 'red'
```

А **History API** позволяет менять адрес **без перезагрузки** страницы:

```js
history.pushState({}, '', '/about')   // адрес стал /about, страница НЕ перезагрузилась
history.back()                        // как кнопка «Назад»
```

Вопросы:
1. Что вернёт `new URLSearchParams('?page=2&sort=price').get('sort')`?
2. Чем `history.pushState(...)` отличается от `location.href = '/about'`?

<details>
<summary>Ответ</summary>

1. `'price'`.
2. `location.href = '/about'` — **полная загрузка** новой страницы с сервера: всё состояние пропадает. `pushState` только **меняет адрес** в строке браузера, а страница остаётся та же. Именно на этом построен роутер.

Кстати, меню `vue-exercises` читает `?ex=week5/day1` через `URLSearchParams` — ты могла это видеть в служебном `App.vue`.

</details>

## Часть 1. Зачем роутер

### Одностраничное приложение

Vue-приложение — это **одна** HTML-страница (`index.html` с `<div id="app">`, день 1 недели 3). Но пользователю хочется, чтобы были «страницы»: Главная, Каталог, Корзина. И чтобы:
- у каждой был свой **адрес** — можно сохранить в закладки и отправить другу;
- работали кнопки браузера **«Назад»** и **«Вперёд»**;
- переход был **мгновенным**, без перезагрузки и без потери данных.

**Роутер** (маршрутизатор) делает это: смотрит на адрес и решает, **какой компонент** показать. При клике по ссылке он меняет адрес через History API и подменяет компонент, а страница не перезагружается.

```
адрес          роутер            показать
/          ──►         ──►   HomePage.vue
/about     ──►  таблица ──►   AboutPage.vue
/contacts  ──►         ──►   ContactsPage.vue
```

Официальный роутер для Vue — **Vue Router**. В `vue-exercises` он уже установлен (`npm install vue-router` сделали за тебя), но **не подключён** — это сегодня твоя задача.

## Часть 2. Создание роутера

### Страницы — это обычные компоненты

```vue
<!-- pages/HomePage.vue -->
<template>
  <h1>Главная</h1>
  <p>Добро пожаловать!</p>
</template>
```

Никакой особой разметки: страница — обычный `.vue`-компонент. Их принято класть в папку `pages/` (или `views/`) и называть с суффиксом `Page` / `View`.

### Таблица маршрутов и роутер

```js
import { createRouter, createWebHashHistory } from 'vue-router'
import HomePage from './pages/HomePage.vue'
import CatalogPage from './pages/CatalogPage.vue'

const router = createRouter({
  history: createWebHashHistory(),
  routes: [
    { path: '/', component: HomePage },
    { path: '/catalog', component: CatalogPage },
  ],
})
```

- `routes` — **таблица**: массив объектов «путь → компонент»;
- `history` — как хранить адрес (часть 4);
- `createRouter` возвращает объект роутера.

### Подключить к приложению

Роутер — **плагин** Vue (день 1 недели 3: «между `createApp` и `mount` подключают плагины»):

```js
app.use(router)
```

В своём проекте это пишут в `main.js`:

```js
const app = createApp(App)
app.use(router)
app.mount('#app')
```

### Как это в `vue-exercises`

Каждая задача — отдельное мини-приложение, поэтому роутер подключается **не в `main.js`**, а в `setup.js` рядом с задачей. Служебный код меню вызывает твою функцию `install(app)` **до** `mount`:

```js
// week5/day1/setup.js
export function install(app) {
  // здесь ты создаёшь роутер и делаешь app.use(router)
}
```

Результат тот же, что `app.use(router)` в `main.js`.

## Часть 3. `RouterView` и `RouterLink`

После `app.use(router)` в **любом** шаблоне доступны два компонента — импортировать их не нужно.

### `RouterView` — «окно» для текущей страницы

```vue
<!-- корневой компонент (в задаче — Exercise.vue) -->
<template>
  <header>Мой сайт</header>
  <RouterView />
  <footer>© 2026</footer>
</template>
```

На месте `<RouterView />` роутер покажет компонент, который соответствует текущему адресу. Шапка и подвал остаются на месте, меняется только середина.

Корневой компонент становится **рамкой** (layout) приложения. Похоже на `<slot />` из дня 4 недели 3: «дырка», куда подставляется содержимое.

### `RouterLink` — ссылка без перезагрузки

```vue
<nav>
  <RouterLink to="/">Главная</RouterLink>
  <RouterLink to="/catalog">Каталог</RouterLink>
</nav>
```

В браузере `RouterLink` превратится в обычный `<a href="…">`, но при клике **не** перезагрузит страницу: роутер перехватит клик, поменяет адрес через History API и подменит компонент в `RouterView`.

### ⚠️⚠️ `<a href>` вместо `RouterLink`

```vue
<a href="/catalog">Каталог</a>              ✗ полная перезагрузка страницы
<RouterLink to="/catalog">Каталог</RouterLink>  ✓
```

Обычная ссылка уведёт браузер на сервер за **новой** страницей. Всё состояние приложения (введённое в формы, загруженные данные) пропадёт, а загрузка будет медленной. Это ответ на вопрос недели «Чем `RouterLink` лучше обычной ссылки `<a>`?».

Обычная `<a>` нужна только для **внешних** сайтов: `<a href="https://vuejs.org">`.

# Занятие 2. Детали и практика

## Часть 4. Режимы истории: `hash` и `web`

### `createWebHistory` — «красивые» адреса

```
https://shop.ru/catalog
```

Адреса как у обычного сайта. Но есть условие: **сервер** должен на **любой** путь отдавать `index.html`. Иначе, если пользователь обновит страницу на `/catalog`, сервер поищет файл `catalog` и ответит 404. Vite в разработке это умеет сам, а при деплое (неделя 8) нужно настроить хостинг.

### `createWebHashHistory` — адреса с `#`

```
https://shop.ru/#/catalog
```

Путь живёт **после `#`**. Браузер никогда не отправляет на сервер то, что после `#`, поэтому сервер всегда отдаёт `index.html`. Работает без всякой настройки, но адреса выглядят хуже.

| | `createWebHistory` | `createWebHashHistory` |
|---|---|---|
| Адрес | `/catalog` | `/#/catalog` |
| Настройка сервера | нужна | не нужна |
| Где используют | почти все реальные проекты | простые хостинги, встраивание в чужую страницу |

### ⚠️ В `vue-exercises` — только `createWebHashHistory`

Меню задач хранит выбранную задачу в `?ex=week5/day1`. Если твой роутер начнёт менять **путь** (`createWebHistory`), он сломает этот адрес. С `createWebHashHistory` твой роутер меняет только часть после `#`:

```
http://localhost:5173/?ex=week5/day1#/catalog
                      └── меню ───┘└─ роутер ─┘
```

В своём проекте трекера (день 5) будешь использовать `createWebHistory`.

## Часть 5. Активная ссылка

Хорошее меню показывает, на какой ты странице. `RouterLink` сам добавляет классы активной ссылке:

| Класс | Когда |
|---|---|
| `router-link-active` | текущий адрес **начинается** с `to` ссылки |
| `router-link-exact-active` | текущий адрес **точно совпадает** с `to` |

```css
.router-link-exact-active {
  font-weight: bold;
  color: #42b883;
}
```

### ⚠️ «Главная» всегда активна

Адрес `/catalog` **начинается** с `/`. Поэтому у ссылки «Главная» (`to="/"`) класс `router-link-active` будет на **любой** странице. Для меню обычно используют **`router-link-exact-active`**. Это вопрос из подсказок к задаче.

## Часть 6. Подводные камни

### ⚠️ Забыла `app.use(router)`

`RouterView` и `RouterLink` станут «неизвестными тегами». В консоли: *Failed to resolve component: RouterView*. На странице ничего не появится.

### ⚠️ Адреса в `to` и `path` должны совпадать

```js
{ path: '/contacts', component: ContactsPage }
```

```vue
<RouterLink to="/contact">Контакты</RouterLink>   ✗ опечатка — /contact ≠ /contacts
```

В консоли будет предупреждение *No match found for location with path "/contact"*, а в `RouterView` — пусто. Страницу 404 сделаем на дне 3.

### ⚠️ Путь — с `/` в начале

```vue
<RouterLink to="catalog">        ⚠️ относительный путь — может уйти не туда
<RouterLink to="/catalog">       ✓
```

### ⚠️ Импорты страниц в `setup.js`

Путь к страницам — относительно `setup.js`: `'./pages/HomePage.vue'`. Папку `pages/` создай рядом с `setup.js` и `Exercise.vue`.

### Как проверить, что всё работает

1. Кликни по ссылкам — адрес меняется, содержимое меняется, страница **не мигает** (нет перезагрузки).
2. Нажми «Назад» в браузере — вернулась предыдущая страница.
3. Обнови страницу на `#/about` — открылась «О проекте», а не главная.
4. Во Vue DevTools появилась вкладка **Routes** — там видна таблица маршрутов.

# Занятие 3. 📜 Options API

## Часть 7. 📜 Роутер в Options API

### Подключение и шаблон — без изменений

`createRouter`, таблица маршрутов, `app.use(router)`, `<RouterView>`, `<RouterLink>` — **одинаковые** для обоих стилей. Роутер подключается к **приложению**, а не к компоненту.

### `this.$route` и `this.$router`

После `app.use(router)` у **каждого** компонента на Options API появляются два свойства:

| Свойство | Что это | Пример |
|---|---|---|
| `this.$route` | **текущий маршрут**: где мы сейчас | `this.$route.path` → `'/catalog'` |
| `this.$router` | **сам роутер**: пульт управления переходами | `this.$router.push('/')` |

Мнемоника: **`$route` — «где я», `$router` — «куда пойти»**. Одна буква разницы — частая путаница!

```vue
<script>
export default {
  computed: {
    isHome() {
      return this.$route.path === '/'
    },
  },
  methods: {
    goHome() {
      this.$router.push('/')
    },
  },
}
</script>

<template>
  <p v-if="!isHome">
    <button @click="goHome">На главную</button>
  </p>
  <p>Вы на странице: {{ $route.path }}</p>
</template>
```

В шаблоне — `$route` и `$router` без `this`, как и всё остальное.

### В Composition API — `useRoute` и `useRouter`

В `<script setup>` нет `this`, поэтому вместо `this.$route` и `this.$router` используют композаблы — подробно завтра и послезавтра:

```js
import { useRoute, useRouter } from 'vue-router'

const route = useRoute()     // = this.$route
const router = useRouter()   // = this.$router
```

Обрати внимание: это **композаблы** из библиотеки (имена с `use`!) — та же идея, что твои `useFetch` и `useLocalStorage`.

### ⚠️ `<router-link>` в рабочем коде

В Options API-проектах и в старой документации часто пишут теги в **kebab-case**: `<router-link to="/">` и `<router-view />`. Это то же самое, что `<RouterLink>` и `<RouterView>`. Vue понимает оба написания.
