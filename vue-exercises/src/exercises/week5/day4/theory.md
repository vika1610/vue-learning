# Занятие 1. Ленивая загрузка и навигационные хуки

## Разминка (10 мин): динамический `import()`

Обычный `import` (день 4 недели 0) пишется вверху файла и загружает модуль **сразу**:

```js
import { heavyChart } from './chart.js'
```

**Динамический** `import()` — это **функция**, которая загружает модуль **когда её вызвали** и возвращает **промис**:

```js
button.addEventListener('click', async () => {
  const module = await import('./chart.js')
  module.heavyChart()
})
```

Вопросы:
1. Что вернёт `import('./chart.js')` без `await`?
2. Когда браузер скачает файл `chart.js` — при открытии страницы или при клике?

<details>
<summary>Ответ</summary>

1. **Промис** (как `fetch`) — модуль загружается асинхронно.
2. **При клике.** Пока кнопку не нажали, файл не скачивается. Если её не нажмут никогда — файл не скачается вовсе.

Это и есть идея ленивой загрузки: не грузить то, что может не понадобиться.

</details>

## Часть 1. Ленивая загрузка страниц

### Проблема

```js
import HomePage from './pages/HomePage.vue'
import ProfilePage from './pages/ProfilePage.vue'
import StatsPage from './pages/StatsPage.vue'     // с тяжёлыми графиками
```

Все страницы загружаются **сразу** при открытии сайта, даже если пользователь никогда не зайдёт в «Статистику». В большом приложении это мегабайты лишнего кода и медленный первый показ.

### Решение: компонент через функцию

```js
const routes = [
  { path: '/', component: HomePage },                                // сразу
  { path: '/stats', component: () => import('./pages/StatsPage.vue') }, // лениво
]
```

Вместо компонента — **функция**, которая его импортирует. Роутер вызовет её **только при первом переходе** на `/stats`. При сборке (`npm run build`, неделя 8) Vite вынесет `StatsPage` в **отдельный файл**.

Это ответ на вопрос недели «Зачем нужна ленивая загрузка страниц?»: первая загрузка быстрее, а редкие страницы грузятся, только когда нужны.

### Как увидеть

1. DevTools (F12) → вкладка **Network** (Сеть).
2. Открой главную. Очисти список кнопкой 🚫.
3. Перейди на ленивую страницу — в списке появится новый запрос с её файлом.

### ⚠️ Импорт без стрелки — это не ленивая загрузка

```js
{ path: '/stats', component: import('./pages/StatsPage.vue') }       ✗ загрузится сразу, а component — промис
{ path: '/stats', component: () => import('./pages/StatsPage.vue') } ✓ функция — вызовут потом
```

Та же ловушка, что `addEventListener('click', fn())` из недели 0: со скобками вызывается **сразу**, а нужно **передать функцию**.

### Какие страницы делать ленивыми

- главную (первую, что видит пользователь) — обычным импортом;
- остальные — обычно лениво, особенно тяжёлые и редкие (статистика, настройки, админка).

## Часть 2. Навигационные хуки

**Навигационный хук** (navigation guard, «охранник навигации») — функция, которую роутер вызывает **перед каждым переходом**. Она может:
- **разрешить** переход;
- **отменить** его;
- **перенаправить** на другую страницу.

Это ответ на вопрос недели «Что такое navigation guard?».

### `router.beforeEach`

```js
router.beforeEach((to, from) => {
  console.log(`переход: ${from.path} → ${to.path}`)
})
```

- `to` — **куда** идём (объект маршрута, как `useRoute()`: `path`, `params`, `query`, `meta`…);
- `from` — **откуда**.

Хук вешается на **сам роутер** — сразу после `createRouter`, до `app.use(router)`.

### Что возвращает хук

| Вернуть | Результат |
|---|---|
| ничего (`undefined`) или `true` | переход разрешён |
| `false` | переход отменён, остаёмся где были |
| адрес или объект маршрута | **перенаправить** туда |

```js
router.beforeEach((to) => {
  if (to.path === '/secret') {
    return '/'                 // перенаправить на главную
  }
})
```

### ⚠️ Старый способ: `next()`

В старом коде и Vue Router 3 (для Vue 2) хук получал третий аргумент `next` и **обязательно** должен был его вызвать:

```js
router.beforeEach((to, from, next) => {   // старый стиль
  if (...) next('/login')
  else next()
})
```

Если `next()` забыть — навигация «зависает». Современный способ — **возвращать** значение, как в таблице выше. Но `next` встречается в рабочем коде, поэтому полезно его узнавать.

### `afterEach` — после перехода

```js
router.afterEach((to) => {
  document.title = to.meta.title ?? 'Мой сайт'
})
```

Ничего не может отменить — просто реагирует. Удобно для заголовка вкладки и аналитики.

## Часть 3. `meta` — свои данные маршрута

У маршрута можно хранить **любые** свои данные в поле `meta`:

```js
const routes = [
  { path: '/', component: HomePage, meta: { title: 'Главная' } },
  {
    path: '/settings',
    component: () => import('./pages/SettingsPage.vue'),
    meta: { title: 'Настройки', requiresAuth: true },
  },
]
```

Роутер сам `meta` **не читает** — это просто «наклейки» на маршрут. Читает их **твой** хук:

```js
router.beforeEach((to) => {
  if (to.meta.requiresAuth && !isLoggedIn()) {
    return '/login'
  }
})
```

Так правило «закрытая страница» описывается **в одном месте** — в хуке, а в таблице маршрутов остаётся только наклейка `requiresAuth: true`. Новая закрытая страница — просто ещё одна наклейка.

### Вложенные маршруты наследуют `meta`

Если у родителя `requiresAuth: true`, то и все его `children` тоже требуют входа: `to.meta` собирает `meta` всей цепочки.

# Занятие 2. Закрытая страница и практика

## Часть 4. Фейковый вход

Настоящий вход — с паролем и сервером — это отдельная большая тема (и её делают на бэкенде). В задаче вход **фейковый**: кнопка «Войти» просто запоминает, что пользователь «вошёл».

### Где хранить «вошёл или нет»

Это состояние нужно **трём** местам сразу:
- навигационному хуку (пускать или нет);
- странице «Вход» (запомнить, что вошли);
- меню (показать «Выйти»).

Они не связаны как родитель и ребёнок, а хук — вообще не компонент. Значит, состояние должно жить **вне** компонентов, в отдельном модуле. Помнишь «самодельный стор» из дня 1 недели 4: `ref`, объявленный **вне** функции, общий для всех?

```js
// auth.js — общий модуль
import { ref } from 'vue'

export const isLoggedIn = ref(false)
```

Любой файл, который импортирует `isLoggedIn`, получит **один и тот же** `ref`. Модуль выполняется один раз (день 4 недели 0), поэтому `ref` создаётся один раз.

> На неделе 6 для такого общего состояния будет Pinia. А сегодня — простой модуль: так виднее, как это устроено.

### Переживать перезагрузку

Чтобы вход не сбрасывался при перезагрузке, начальное значение берут из `localStorage`, а при входе и выходе — записывают. Подсказка 3 в `hints.md` показывает, как это выглядит. Или можно использовать твой `useLocalStorage`, если перенести его в `vue-exercises`.

### ⚠️ Это не безопасность

Фейковый вход в браузере защищает «от случайного захода», но не от злоумышленника: любой может открыть DevTools и поменять `localStorage`. Настоящую защиту данных делают **на сервере**. Роутерный хук только решает, какую страницу **показать**.

## Часть 5. Вернуть туда, куда хотел

Пользователь открыл `/profile`, его перенаправили на `/login`. Он вошёл… и попал на главную. Неудобно: он хотел в профиль!

### Запомнить адрес в query

```js
router.beforeEach((to) => {
  if (to.meta.requiresAuth && !isLoggedIn.value) {
    return { path: '/login', query: { redirect: to.fullPath } }
  }
})
```

Адрес станет `/login?redirect=/profile`. Помнишь query из разминки дня 1?

### После входа — туда

```js
// pages/LoginPage.vue
const route = useRoute()
const router = useRouter()

function onLogin() {
  login()
  router.replace(route.query.redirect ?? '/')
}
```

- `route.query.redirect` — куда хотели (или главная, если ничего);
- `replace`, а не `push` — помнишь вчерашний пример? Возвращаться «Назад» на страницу входа незачем.

### Выход

После выхода, если пользователь **на закрытой странице**, хук сам не сработает: перехода-то не было. Нужно уйти вручную:

```js
function onLogout() {
  logout()
  if (route.meta.requiresAuth) router.push('/')
}
```

## Часть 6. Подводные камни

### ⚠️⚠️ Бесконечный редирект

```js
{ path: '/login', component: LoginPage, meta: { requiresAuth: true } }   // ✗
```

Неавторизованного пользователя перенаправляем на `/login` → `/login` требует входа → снова на `/login` → … Vue Router заметит цикл и выдаст ошибку. Страница входа, конечно, должна быть **открытой**.

### ⚠️ Хук читает `.value`

```js
if (to.meta.requiresAuth && !isLoggedIn) { ... }   // ✗ isLoggedIn — ref-объект, всегда truthy
if (to.meta.requiresAuth && !isLoggedIn.value) { ... }  // ✓
```

Хук — обычный JavaScript, а не шаблон: `ref` здесь сам не распакуется.

### ⚠️ Залогиненный на странице входа

Если пользователь **уже** вошёл и открыл `/login`, логично перенаправить его на главную. Это ещё одно правило в том же хуке — попробуй добавить сама.

### Хук внутри компонента: «вы уверены, что хотите уйти?»

Бывают хуки и **в компонентах**. Самый полезный — предупредить о несохранённой форме:

```js
import { onBeforeRouteLeave } from 'vue-router'

onBeforeRouteLeave(() => {
  if (hasUnsavedChanges.value) {
    return confirm('Есть несохранённые изменения. Уйти?')
  }
})
```

Вернул `false` (пользователь нажал «Отмена») — переход отменён.

# Занятие 3. 📜 Options API и итоги недели

## Часть 7. 📜 Хуки навигации в Options API

### Глобальные хуки — без изменений

`router.beforeEach`, `afterEach`, `meta`, ленивая загрузка — всё это настройки **роутера**, а не компонента. Они одинаковы для обоих стилей.

### Хуки внутри компонента — опции

| Composition API | Options API | Когда |
|---|---|---|
| — | `beforeRouteEnter(to, from)` | перед входом на страницу (компонента ещё нет, `this` недоступен!) |
| `onBeforeRouteUpdate` | `beforeRouteUpdate(to, from)` | тот же компонент, другие параметры (`/posts/2` → `/posts/3`) |
| `onBeforeRouteLeave` | `beforeRouteLeave(to, from)` | перед уходом со страницы |

```js
export default {
  data() {
    return { hasUnsavedChanges: false }
  },
  beforeRouteLeave() {
    if (this.hasUnsavedChanges) {
      return confirm('Есть несохранённые изменения. Уйти?')
    }
  },
}
```

### ⚠️ `beforeRouteEnter` — без `this`

```js
beforeRouteEnter(to, from) {
  console.log(this.title)   // ✗ компонент ещё не создан
},
```

У `beforeRouteEnter` нет аналога в `<script setup>`: там весь код и так выполняется при создании компонента. В рабочем коде `beforeRouteEnter` иногда используют для загрузки данных **до** показа страницы.

### `beforeRouteUpdate` вместо `watch` на `$route`

Помнишь вчерашнюю проблему «тот же компонент — другой `id`»? В Options API её решают ещё и так:

```js
beforeRouteUpdate(to) {
  this.load(to.params.id)
},
```

Это альтернатива `watch: { '$route.params.id': ... }`.

### Общий модуль `auth.js` в Options API

```js
import { isLoggedIn, logout } from '../auth.js'

export default {
  computed: {
    loggedIn() {
      return isLoggedIn.value   // ⚠️ в computed Options API ref НЕ распаковывается сам
    },
  },
  methods: {
    onLogout() {
      logout()
      if (this.$route.meta.requiresAuth) this.$router.push('/')
    },
  },
}
```

⚠️ Импортированный `ref` в Options API **не виден** ни в шаблоне, ни через `this`: он не часть компонента (как константа `prices` из дня 5 недели 1). Его нужно читать через `.value` в `computed` (как выше) или вернуть из `setup()` — тогда он станет частью компонента и распакуется сам.

## Шпаргалка

| Тема | Запомнить |
|---|---|
| `import('./x.js')` | динамический импорт, возвращает промис |

| `router.beforeEach((to, from) => ...)` | перед каждым переходом |
| Вернуть | ничего / `true` — пустить; `false` — отменить; адрес — перенаправить |
| `next()` | старый стиль — узнавать, но не писать |
| `router.afterEach` | после перехода: заголовок вкладки |
| `meta: { requiresAuth: true }` | наклейка; читает твой хук |
| Общее состояние | `ref` в отдельном модуле `auth.js` |
| `?redirect=` | вернуть после входа через `router.replace` |
| Бесконечный редирект | `/login` должна быть открытой |
| В хуке | `isLoggedIn.value`, не `isLoggedIn` |
| `onBeforeRouteLeave` | «Есть несохранённые изменения» |
| 📜 Options API | `beforeRouteEnter` (без `this`), `beforeRouteUpdate`, `beforeRouteLeave`; импортированный `ref` — через `.value` |
