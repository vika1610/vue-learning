# Занятие 1. Жизненный цикл

## Разминка (10 мин): `setTimeout` и `setInterval`

```js
const timeoutId = setTimeout(() => console.log('один раз через 2 с'), 2000)
const intervalId = setInterval(() => console.log('каждую секунду'), 1000)

clearTimeout(timeoutId)    // отменить таймаут, если ещё не сработал
clearInterval(intervalId)  // остановить интервал
```

- `setTimeout` — **один раз** через указанное время;
- `setInterval` — **повторять** с указанным промежутком, пока не остановят;
- оба возвращают **id**, по которому их можно остановить.

Вопросы:

1. Что будет, если дважды подряд выполнить `setInterval(tick, 1000)` и сохранить id только последнего?
2. Как из 125 секунд получить строку `'02:05'`?

<details>
<summary>Ответ</summary>

1. Запустятся **два** интервала, `tick` будет вызываться дважды в секунду. А остановить ты сможешь только второй: id первого потерян, он будет тикать вечно (до перезагрузки страницы). Это главная ловушка таймеров.
2. Минуты — `Math.floor(125 / 60)` → `2`, секунды — `125 % 60` → `5` (`%` — остаток от деления). Ведущий ноль — `String(5).padStart(2, '0')` → `'05'`. Вместе: `` `${String(m).padStart(2, '0')}:${String(s).padStart(2, '0')}` ``.

</details>

## Часть 1. Жизнь компонента

У каждого компонента есть **жизненный цикл**: он создаётся, появляется на странице, обновляется и в конце концов удаляется.

```
  создание         появился на странице        обновления              удаление
     │                     │                   (много раз)                │
     ▼                     ▼                       ▼                      ▼
<script setup>  ──►   onMounted   ──►   onBeforeUpdate / onUpdated  ──►  onUnmounted
выполняется                                                         (onBeforeUnmount — перед)
```

**Хук жизненного цикла** — функция, которую Vue вызывает в определённый момент жизни компонента. Ты передаёшь в хук свою функцию: «когда наступит этот момент — сделай вот это».

Когда компонент **удаляется** со страницы?
- его убрали через `v-if` (условие стало ложным);
- пользователь ушёл на другую страницу приложения (неделя 5, роутер);
- в нашем `vue-exercises` — по кнопке **«⏏ Размонтировать»** вверху страницы задачи.

### Где здесь `<script setup>`

Код в `<script setup>` выполняется **один раз, при создании** компонента, ещё **до** того, как он появился на странице. Поэтому всё, что ты писала до сих пор (`ref`, `computed`, восстановление черновика), выполнялось именно в этот момент.

## Часть 2. `onMounted` — компонент появился на странице

```vue
<script setup>
import { onMounted } from 'vue'

console.log('1. script setup: компонент создаётся')

onMounted(() => {
  console.log('3. onMounted: компонент на странице')
})

console.log('2. script setup: всё ещё создаётся')
</script>
```

В консоли будет `1`, `2`, `3`. Функцию внутри `onMounted` Vue вызовет **позже**, когда разметка компонента уже будет в DOM.

### Для чего `onMounted`

- **работа с DOM**: поставить фокус в поле, измерить размер элемента, подключить стороннюю библиотеку, которой нужен готовый элемент (графики на неделе 8);
- **подписка на глобальные события**: `window.addEventListener('resize', ...)`, `document.addEventListener('keydown', ...)`;
- **загрузка данных**: часто пишут в `onMounted` (хотя можно и прямо в `<script setup>`).

```vue
<script setup>
import { ref, onMounted } from 'vue'

const width = ref(window.innerWidth)

function onResize() {
  width.value = window.innerWidth
}

onMounted(() => {
  window.addEventListener('resize', onResize)
})
</script>

<template>
  <p>Ширина окна: {{ width }} px</p>
</template>
```

Поменяй ширину окна браузера — число будет обновляться.

### ⚠️ До `onMounted` DOM-элементов компонента ещё нет

```vue
<script setup>
document.querySelector('.title').textContent = 'Привет'   // ✗ null — разметка ещё не создана
</script>
```

Код `<script setup>` выполняется **до** отрисовки. Если что-то нужно сделать с готовой разметкой — только в `onMounted`. (А во Vue почти всегда лучше вообще не трогать DOM руками, а менять данные.)

### ⚠️ Хуки регистрируются сразу, а не «потом»

```js
setTimeout(() => {
  onMounted(() => { ... })   // ✗ слишком поздно — Vue предупредит, хук не сработает
}, 100)
```

Вызывать `onMounted` и другие хуки нужно **прямо** в `<script setup>`, на верхнем уровне. Не внутри `setTimeout`, не после `await`, не внутри обработчика клика.

## Часть 3. `onUnmounted` — уборка перед уходом

### Проблема

В примере с шириной окна мы подписались на `resize`. Что будет, когда компонент удалят со страницы?

**Ничего не изменится**: обработчик останется висеть на `window`. Компонента уже нет, а функция `onResize` продолжает вызываться при каждом изменении окна. Это называют **утечкой**: ненужная работа, которая копится. Если компонент создаётся и удаляется много раз, обработчиков станет много.

С `setInterval` ещё хуже: таймер будет тикать вечно и тратить ресурсы.

### Решение: убрать за собой

```vue
<script setup>
import { ref, onMounted, onUnmounted } from 'vue'

const width = ref(window.innerWidth)

function onResize() {
  width.value = window.innerWidth
}

onMounted(() => {
  window.addEventListener('resize', onResize)
})

onUnmounted(() => {
  window.removeEventListener('resize', onResize)   // та же функция, что добавляли
})
</script>
```

**Правило парности**: всё, что компонент «включил» снаружи себя, он должен «выключить» в `onUnmounted`.

| Включили | Выключить |
|---|---|
| `setInterval` | `clearInterval(id)` |
| `setTimeout` (если ещё может сработать) | `clearTimeout(id)` |
| `window.addEventListener(...)` | `window.removeEventListener(...)` |
| `document.addEventListener(...)` | `document.removeEventListener(...)` |

### ⚠️ Что убирать **не** нужно

- обработчики в шаблоне (`@click`, `@input`) — Vue снимет их сам;
- `watch`, `watchEffect`, `computed` — Vue остановит их сам.

Убирать нужно только то, что ты подключила **вручную**, мимо Vue.

### ⚠️ `removeEventListener` нужна та же функция

```js
onMounted(() => window.addEventListener('resize', () => { ... }))
onUnmounted(() => window.removeEventListener('resize', () => { ... }))   // ✗ это другая функция!
```

Две одинаковые на вид стрелки — **разные** функции (как два одинаковых объекта не равны через `===`). Поэтому обработчик выносят в функцию с именем, как `onResize` выше. Эта ловушка была в конспекте дня 4 недели 0.

### Как проверить уборку в `vue-exercises`

Ссылка «← Все задачи» **перезагружает** страницу, а при перезагрузке `onUnmounted` вообще не вызывается: страница просто исчезает целиком вместе со всеми таймерами. Поэтому для проверки вверху страницы задачи есть кнопка **«⏏ Размонтировать»**: она удаляет компонент без перезагрузки, как сделал бы `v-if` или переход по роутеру.

Порядок проверки:
1. добавь `console.log` в «тик» таймера или в обработчик;
2. запусти;
3. нажми «⏏ Размонтировать»;
4. смотри в консоль: если сообщения **продолжают** идти — уборки нет.

# Занятие 2. Таймеры во Vue и практика

## Часть 4. Таймер во Vue

Разберём на примере **секундомера**, который считает **вверх** (в задаче будет обратный отсчёт — это уже твоя работа).

```vue
<script setup>
import { ref, computed, onUnmounted } from 'vue'

const seconds = ref(0)                 // ← одно число — источник правды
let intervalId = null                  // ← id таймера, на странице не нужен
const isRunning = ref(false)           // ← а это нужно в шаблоне

const display = computed(() => {
  const m = String(Math.floor(seconds.value / 60)).padStart(2, '0')
  const s = String(seconds.value % 60).padStart(2, '0')
  return `${m}:${s}`
})

function start() {
  if (intervalId !== null) return      // ⚠️ защита от двойного запуска
  isRunning.value = true
  intervalId = setInterval(() => {
    seconds.value++
  }, 1000)
}

function stop() {
  clearInterval(intervalId)
  intervalId = null
  isRunning.value = false
}

onUnmounted(stop)                       // уборка при удалении
</script>

<template>
  <p class="time">{{ display }}</p>
  <button @click="start" :disabled="isRunning">Старт</button>
  <button @click="stop">Стоп</button>
</template>
```

### Разбор решений

**Одно число — источник правды.** Храним **только** количество секунд. Минуты и секунды для показа — `computed`. Если бы хранили минуты и секунды отдельно, пришлось бы вручную «переносить» 60 секунд в минуту. Это правило дня 5 недели 1: что получается из данных — `computed`.

**`intervalId` — обычная переменная, не `ref`.** Его не показывают на странице, и при его изменении ничего перерисовывать не нужно. `ref` для таких «служебных» значений не нужен.

**`isRunning` — `ref`.** Он **нужен в шаблоне** (`:disabled`), значит должен быть реактивным.

**Защита от двойного запуска.** Без `if (intervalId !== null) return` два клика по «Старт» запустят два интервала, и секунды побегут вдвое быстрее, а один интервал станет неостанавливаемым (разминка, вопрос 1). `:disabled` на кнопке — дополнительная защита «для глаз».

**`intervalId = null` после остановки.** Иначе защита в `start` решит, что таймер ещё идёт, и больше не запустит его.

**`onUnmounted(stop)`.** В хук можно передать готовую функцию, а не только стрелку. Остановка и уборка — одно и то же действие.

### ⚠️ `setInterval` не точный

`setInterval(fn, 1000)` не гарантирует **ровно** 1000 мс. Если вкладка в фоне, браузер может замедлить таймеры до раза в секунду и реже. Для учебного Pomodoro это не важно. В «настоящих» таймерах время считают от `Date.now()` при старте, но это уже усложнение.

### Изменить заголовок вкладки

Бонус в задаче — показать оставшееся время в названии вкладки. Это **побочный эффект** при изменении данных, значит `watch` или `watchEffect` (вчерашний день):

```js
watchEffect(() => {
  document.title = `⏱ ${display.value}`
})
```

И не забудь вернуть заголовок обратно в `onUnmounted`: это тоже «включили — выключить».

## Часть 5. Другие хуки

| Хук | Когда | Для чего |
|---|---|---|
| `onBeforeMount` | прямо перед появлением на странице | редко нужен |
| `onMounted` | появился на странице | DOM, подписки, библиотеки |
| `onBeforeUpdate` | перед перерисовкой после изменения данных | редко |
| `onUpdated` | после перерисовки | редко, осторожно: легко устроить бесконечный цикл |
| `onBeforeUnmount` | перед удалением, компонент ещё на странице | уборка, если нужен доступ к DOM |
| `onUnmounted` | после удаления | уборка |

На практике 90 % случаев — это **`onMounted`** и **`onUnmounted`**. Остальные полезно узнавать в чужом коде.

### ⚠️ Не делай в `onUpdated` того, что меняет данные

```js
onUpdated(() => {
  count.value++   // ✗ изменение → перерисовка → onUpdated → изменение → …
})
```

# Занятие 3. 📜 Options API и итоги недели

## Часть 6. 📜 Хуки в Options API

В Options API хуки — это **опции** компонента с особыми именами:

| Composition API | Options API | Когда |
|---|---|---|
| код в `<script setup>` | `beforeCreate()`, `created()` | при создании |
| `onBeforeMount` | `beforeMount()` | перед появлением |
| `onMounted` | `mounted()` | появился на странице |
| `onBeforeUpdate` | `beforeUpdate()` | перед перерисовкой |
| `onUpdated` | `updated()` | после перерисовки |
| `onBeforeUnmount` | `beforeUnmount()` | перед удалением |
| `onUnmounted` | `unmounted()` | после удаления |

### Секундомер в Options API

```vue
<script>
export default {
  data() {
    return {
      seconds: 0,
      isRunning: false,
    }
  },
  computed: {
    display() {
      const m = String(Math.floor(this.seconds / 60)).padStart(2, '0')
      const s = String(this.seconds % 60).padStart(2, '0')
      return `${m}:${s}`
    },
  },
  created() {
    this.intervalId = null   // служебное поле, не в data — не реактивное
  },
  mounted() {
    console.log('секундомер на странице')
  },
  unmounted() {
    this.stop()
  },
  methods: {
    start() {
      if (this.intervalId !== null) return
      this.isRunning = true
      this.intervalId = setInterval(() => {
        this.seconds++              // стрелка — берёт this метода
      }, 1000)
    },
    stop() {
      clearInterval(this.intervalId)
      this.intervalId = null
      this.isRunning = false
    },
  },
}
</script>
```

### Что заметно

**`created` вместо кода в `<script setup>`.** Код, который в Composition API просто пишется сверху, в Options API кладут в `created()` (помнишь вчерашнее восстановление черновика?).

**Служебное поле `this.intervalId`.** Его нет в `data()`, потому что реактивность не нужна. В Options API такие поля часто заводят прямо на `this` в `created`. В Composition API это обычная переменная `let intervalId`.

**Стрелка в `setInterval`.** Обязательно стрелка: обычная `function` потеряла бы `this`, и `this.seconds++` сломался бы. Это ловушка из дня 4 недели 0, и здесь она встречается чаще всего.

**Хуки — обычные функции.** Как `methods` и `computed`: `mounted() {}`, а не `mounted: () => {}`.

### ⚠️ В рабочем коде Vue 2 названия были другими

Если в чужом коде встретишь `beforeDestroy` и `destroyed`, это названия из **Vue 2**. Во Vue 3 они переименованы в `beforeUnmount` и `unmounted`. На твоей работе Vue 3, поэтому там должны быть новые имена.

## Шпаргалка

| Тема | Запомнить |
|---|---|
| `<script setup>` | выполняется при создании, до появления на странице |
| `onMounted(fn)` | компонент на странице: DOM, подписки, библиотеки |
| `onUnmounted(fn)` | уборка: таймеры, `addEventListener` на `window` / `document` |
| Правило парности | включила вручную — выключи в `onUnmounted` |
| Обработчики шаблона, `watch` | Vue убирает сам |
| `removeEventListener` | та же функция по имени, не новая стрелка |
| Хуки | регистрировать сразу, на верхнем уровне, не после `await` |
| Таймер | одно число в `ref` + `computed` для показа |
| `intervalId` | обычная переменная; `null` после остановки |
| Двойной старт | `if (intervalId !== null) return` |
| Проверить уборку | кнопка «⏏ Размонтировать», а не «← Все задачи» |
| 📜 Options API | `created`, `mounted`, `unmounted`; служебное поле — `this.x` в `created`; стрелка в `setInterval` |
