# Занятие 1. Условная отрисовка

## Разминка (10 мин): truthy / falsy и уникальные id

### Truthy и falsy

В условиях (`if`, тернарный оператор, `v-if`) JavaScript превращает любое значение в `true` или `false`. Значения, которые превращаются в `false`, называют **falsy**. Их всего несколько — запомни список:

```js
false, 0, -0, '', null, undefined, NaN
```

**Всё остальное — truthy**, даже то, что «выглядит пустым». Ответь, что выведет каждая строка:

```js
Boolean('')        // ?
Boolean(' ')       // ?
Boolean('0')       // ?
Boolean([])        // ?
Boolean({})        // ?
Boolean(0)         // ?
```

### Уникальные id

У каждого элемента списка должен быть свой, **неповторяющийся** идентификатор. Какой из способов надёжнее?

```js
// а) номер по порядку
let nextId = 1
const a = { id: nextId++, text: 'Купить хлеб' }

// б) текущее время
const b = { id: Date.now(), text: 'Купить молоко' }

// в) встроенный генератор
const c = { id: crypto.randomUUID(), text: 'Купить сыр' }
```

<details>
<summary>Ответ</summary>

- `''` → `false`, `' '` → **`true`** (там пробел!), `'0'` → **`true`** (это строка, а не число), `[]` → **`true`**, `{}` → **`true`**, `0` → `false`.
- ⚠️ Пустой массив и пустой объект — **truthy**. Поэтому `if (tasks)` не проверяет, что задачи есть. Нужно `if (tasks.length)`.

Про id:
- а) работает, пока счётчик живёт в одном месте (вспомни `makeIdGenerator`). После перезагрузки страницы начнётся снова с 1;
- б) если создать два элемента в одну миллисекунду (например, в цикле), id совпадут;
- в) самый надёжный: случайная строка вида `'3b241101-e2bb-4255-8caf-4136c566a962'`, совпадение практически невозможно. Пригодится в проекте на неделе 4.

</details>

## Часть 1. `v-if`, `v-else-if`, `v-else`

### Показать или не показать

```vue
<script setup>
import { ref } from 'vue'

const isLoggedIn = ref(false)
</script>

<template>
  <p v-if="isLoggedIn">Добро пожаловать!</p>
  <button @click="isLoggedIn = !isLoggedIn">Войти / выйти</button>
</template>
```

`v-if="условие"`: если условие truthy — элемент **есть** на странице, если falsy — его **нет вообще**. Не «спрятан», а именно отсутствует в DOM.

Это вместо того, что в неделе 0 делалось руками через `createElement` и `remove`.

### `v-else` — иначе

```vue
<p v-if="isLoggedIn">Добро пожаловать!</p>
<p v-else>Пожалуйста, войдите</p>
```

### `v-else-if` — несколько вариантов

```vue
<script setup>
import { ref } from 'vue'

const stock = ref(3)
</script>

<template>
  <p v-if="stock === 0">Нет в наличии</p>
  <p v-else-if="stock < 5">Осталось мало: {{ stock }} шт.</p>
  <p v-else>В наличии</p>
</template>
```

Работает как `if … else if … else` в JS: проверяется сверху вниз, показывается **первый** подходящий вариант.

### ⚠️ `v-else` должен стоять **сразу** после `v-if`

```vue
<p v-if="isLoggedIn">Привет!</p>
<hr>                        <!-- ✗ любой элемент между ними ломает связку -->
<p v-else>Войдите</p>       <!-- Vue выдаст предупреждение: v-else без v-if -->
```

`v-if`, `v-else-if` и `v-else` — **соседи**, без чужих элементов между ними. Комментарии `<!-- -->` между ними допустимы.

### ⚠️ Проверка пустого массива

```vue
<ul v-if="tasks">...</ul>              ✗ пустой массив [] — truthy, условие всегда верно
<ul v-if="tasks.length">...</ul>       ✓ 0 — falsy
<ul v-if="tasks.length > 0">...</ul>   ✓ то же, явнее
```

Это прямое применение разминки. Именно эта проверка понадобится в задаче для «Список пуст».

### Сложные условия — в `computed`

```vue
<p v-if="user && user.isAdmin && !user.isBlocked && items.length > 0">...</p>
```

Такое трудно читать. Вынеси в `computed` с понятным именем:

```js
const canEdit = computed(() => user.value && user.value.isAdmin && !user.value.isBlocked)
```

```vue
<p v-if="canEdit && items.length">...</p>
```

## Часть 2. `v-show` — спрятать, не удаляя

```vue
<p v-show="isOpen">Подробное описание товара…</p>
```

Внешне похоже на `v-if`: элемент виден или нет. Но работает иначе.

| | `v-if` | `v-show` |
|---|---|---|
| Как скрывает | **удаляет** элемент из DOM | оставляет в DOM, ставит `style="display: none"` |
| Первая отрисовка, если условие `false` | элемента нет совсем | элемент создаётся, но скрыт |
| Переключение | дорогое: создать или удалить заново | дешёвое: поменять один стиль |
| `v-else` | ✓ работает | ✗ не поддерживается |

### Когда что

- **`v-show`** — если элемент переключают **часто** (выпадающее меню, подсказка по кнопке, вкладки);
- **`v-if`** — если условие **редко меняется** или элемент тяжёлый (большой блок, который может вообще не понадобиться), а также когда нужен `v-else`.

Это ответ на вопрос недели «Чем `v-if` отличается от `v-show`?».

### Посмотреть разницу своими глазами

В задаче есть пункт: сделать подсказку через `v-show`, потом через `v-if`, и посмотреть во вкладке **Elements** (F12). С `v-show` элемент останется в коде страницы с `display: none`. С `v-if` вместо него будет только пустой комментарий `<!--v-if-->`: это метка, где элемент появится.

## Часть 3. `<template>` — группа без лишней обёртки

Что если по одному условию нужно показать **несколько** элементов?

```vue
<!-- можно обернуть в div… -->
<div v-if="showDetails">
  <h3>Детали</h3>
  <p>Вес: 200 г</p>
  <p>Цвет: синий</p>
</div>

<!-- …а можно без лишнего div -->
<template v-if="showDetails">
  <h3>Детали</h3>
  <p>Вес: 200 г</p>
  <p>Цвет: синий</p>
</template>
```

`<template>` с директивой — **невидимая обёртка**: в DOM попадут только три элемента внутри, без самого `<template>`. Удобно, когда лишний `div` ломает вёрстку (например, внутри списка `<ul>` или таблицы).

⚠️ `v-show` на `<template>` **не работает**: `v-show` меняет стиль элемента, а у невидимой обёртки нет стиля. Для `<template>` — только `v-if`.

# Занятие 2. Списки

## Часть 4. `v-for` — повторить элемент для каждого элемента массива

### Основной синтаксис

```vue
<script setup>
import { ref } from 'vue'

const fruits = ref(['яблоко', 'банан', 'вишня'])
</script>

<template>
  <ul>
    <li v-for="fruit in fruits">{{ fruit }}</li>
  </ul>
</template>
```

Получится три `<li>`. `v-for="fruit in fruits"` читается как «**для каждого** `fruit` **из** `fruits`». Похоже на `for (const fruit of fruits)` из недели 0, только в шаблоне.

Сравни с днём 5 недели 0, где ты вручную создавала `<li>` в цикле через `createElement`. Здесь то же самое — одной строкой, и при изменении массива Vue сам обновит список.

### Массив объектов

```vue
<script setup>
import { ref } from 'vue'

const movies = ref([
  { id: 1, title: 'Интерстеллар', year: 2014 },
  { id: 2, title: 'Начало', year: 2010 },
  { id: 3, title: 'Дюна', year: 2021 },
])
</script>

<template>
  <ul>
    <li v-for="movie in movies" :key="movie.id">
      {{ movie.title }} ({{ movie.year }})
    </li>
  </ul>
</template>
```

Внутри элемента с `v-for` доступна переменная `movie` — текущий фильм. Ей можно пользоваться и в `{{ }}`, и в `:атрибутах`, и в `:class`:

```vue
<li v-for="movie in movies" :key="movie.id" :class="{ new: movie.year > 2020 }">
```

### Индекс

Второй переменной можно получить **номер** элемента (с нуля):

```vue
<li v-for="(movie, index) in movies" :key="movie.id">
  {{ index + 1 }}. {{ movie.title }}
</li>
```

Как в `map((movie, index) => ...)`.

### Деструктуризация

```vue
<li v-for="{ id, title } in movies" :key="id">{{ title }}</li>
```

Работает, как деструктуризация в параметрах из дня 3 недели 0.

### Перебор чисел

```vue
<span v-for="n in 5" :key="n">⭐</span>   <!-- 5 звёздочек, n от 1 до 5 -->
```

⚠️ Числа начинаются с **1**, а не с 0.

### Изменение массива — реактивно

```js
movies.value.push({ id: 4, title: 'Оппенгеймер', year: 2023 })   // список сам обновится
movies.value = movies.value.filter((m) => m.year > 2012)          // тоже
```

Методы, которые меняют массив (`push`, `splice`, `sort`…), и замена массива целиком — Vue замечает и то и другое. Таблица «какие методы меняют массив» из дня 3 недели 0 здесь снова пригодится.

## Часть 5. `key` — зачем он нужен

### Что делает `key`

Когда массив меняется, Vue не перерисовывает весь список с нуля: это было бы медленно. Он **сопоставляет** старые и новые элементы и меняет только то, что нужно.

Чтобы понять, какой `<li>` какому элементу массива соответствует, Vue нужен **уникальный и постоянный** признак. Это и есть `key`.

```vue
<li v-for="movie in movies" :key="movie.id">
```

Аналогия: в классе у каждого ученика есть номер в журнале. Если ученики пересядут, учитель всё равно узнает, кто есть кто. А если опознавать «по парте», после пересадки всё перепутается.

Это ответ на вопрос недели «Зачем нужен `key` в `v-for`?».

### ⚠️⚠️ Индекс в роли `key` — плохая идея

```vue
<li v-for="(task, index) in tasks" :key="index">   ✗ работает, но опасно
<li v-for="task in tasks" :key="task.id">         ✓
```

Индекс — это «номер парты», а не «номер ученика». Если удалить первый элемент, все остальные **сдвинутся**, и их индексы изменятся. Vue решит, что изменилось содержимое элементов, а не что один удалили. Последствия:

- если у элемента есть своё состояние (галочка в чекбоксе, текст в поле ввода), оно может «перескочить» на соседний элемент;
- анимации (неделя 8) будут работать неправильно.

Индекс в роли `key` допустим, **только** если список никогда не меняется: не сортируется, не фильтруется, элементы не удаляются и не добавляются в середину.

### ⚠️ `key` должен быть уникальным

```js
const tasks = [
  { id: 1, text: 'А' },
  { id: 1, text: 'Б' },   // ✗ повтор id
]
```

Vue предупредит в консоли: *Duplicate keys detected*. Список может отрисоваться неправильно. Отсюда разминка про уникальные id.

### Не забывай двоеточие

```vue
<li v-for="m in movies" key="m.id">    ✗ у всех key = строка "m.id" — одинаковый!
<li v-for="m in movies" :key="m.id">   ✓
```

Ловушка дня 2: без `:` в кавычках — просто строка.

## Часть 6. Подводные камни списков

### ⚠️ `v-if` и `v-for` на одном элементе

```vue
<li v-for="task in tasks" v-if="!task.done" :key="task.id">   ✗
```

Так делать **нельзя**. Во Vue 3 `v-if` выполняется **раньше** `v-for`, поэтому переменной `task` ещё нет, и будет ошибка. Даже если бы работало, код сложно читать.

Два правильных способа:

**1. Отфильтровать заранее в `computed`** — самый частый и лучший вариант:

```js
const activeTasks = computed(() => tasks.value.filter((t) => !t.done))
```

```vue
<li v-for="task in activeTasks" :key="task.id">{{ task.text }}</li>
```

**2. `<template>` с `v-for`, а `v-if` — внутри:**

```vue
<template v-for="task in tasks" :key="task.id">
  <li v-if="!task.done">{{ task.text }}</li>
</template>
```

### ⚠️ Список пуст — показать сообщение

```vue
<ul v-if="tasks.length">
  <li v-for="task in tasks" :key="task.id">{{ task.text }}</li>
</ul>
<p v-else>Список пуст</p>
```

`v-if` на `<ul>`, `v-for` на `<li>` — **разные** элементы, так что ловушка выше не срабатывает. И `v-else` стоит сразу после `<ul>`.

### ⚠️ Сортировка в шаблоне меняет исходный массив

```vue
<li v-for="m in movies.sort((a, b) => a.year - b.year)" :key="m.id">   ✗
```

`sort` меняет исходный массив (день 3 недели 0). Изменение реактивного массива вызывает перерисовку, которая снова сортирует… Vue предупредит о бесконечном цикле. Правильно — **копия в `computed`**:

```js
const sortedMovies = computed(() => [...movies.value].sort((a, b) => a.year - b.year))
```

Ровно как ты делала в `sortByPrice`.

# Занятие 3. 📜 Options API

## Часть 7. 📜 Условия и списки в Options API

### Шаблон не меняется

`v-if`, `v-else`, `v-show`, `v-for`, `:key`, `<template>` — всё это шаблон. В Options API синтаксис **точно такой же**. Отличается только то, где лежат данные и как к ним обращаться в скрипте.

**Composition API:**

```vue
<script setup>
import { ref, computed } from 'vue'

const movies = ref([
  { id: 1, title: 'Интерстеллар', watched: true },
  { id: 2, title: 'Начало', watched: false },
])
const toWatch = computed(() => movies.value.filter((m) => !m.watched))

function addMovie(title) {
  movies.value.push({ id: crypto.randomUUID(), title, watched: false })
}
</script>
```

**Options API:**

```vue
<script>
export default {
  data() {
    return {
      movies: [
        { id: 1, title: 'Интерстеллар', watched: true },
        { id: 2, title: 'Начало', watched: false },
      ],
    }
  },
  computed: {
    toWatch() {
      return this.movies.filter((m) => !m.watched)
    },
  },
  methods: {
    addMovie(title) {
      this.movies.push({ id: crypto.randomUUID(), title, watched: false })
    },
  },
}
</script>
```

Шаблон для обоих:

```vue
<ul v-if="toWatch.length">
  <li v-for="movie in toWatch" :key="movie.id">{{ movie.title }}</li>
</ul>
<p v-else>Всё посмотрено!</p>
```

### Что заметно

| | Composition API | Options API |
|---|---|---|
| Массив | `ref([...])` | поле в `data()` |
| Изменить | `movies.value.push(...)` | `this.movies.push(...)` |
| Отфильтровать | `computed(() => movies.value.filter(...))` | опция `computed: { toWatch() { return this.movies.filter(...) } }` |

### ⚠️ Стрелка внутри метода — можно и нужно

```js
computed: {
  toWatch() {                                  // ← сам computed: обычная функция
    return this.movies.filter((m) => !m.watched)  // ← внутри: стрелка в filter — ✓
  },
},
```

Правило из дня 1 работает и здесь: **сами** опции (`toWatch`, `addMovie`) — обычные функции, а **внутри** них стрелки (в `filter`, `map`, `setTimeout`) — пожалуйста. Стрелка в `filter` возьмёт `this` у `toWatch`, хотя здесь `this` внутри стрелки и не нужен.

### Где в рабочем коде хранят «показать или скрыть»

В Options API флаги видимости обычно лежат в `data()`:

```js
data() {
  return {
    isMenuOpen: false,
    showDetails: false,
  }
},
methods: {
  toggleMenu() {
    this.isMenuOpen = !this.isMenuOpen
  },
},
```

```vue
<nav v-show="isMenuOpen">...</nav>
```

Если в рабочем коде встретишь `v-if` вместе с `v-for` на одном элементе, знай: это пришло из Vue 2. Там порядок был обратный (`v-for` выполнялся раньше), и такой код работал. Во Vue 3 его нужно переписать через `computed` или `<template>`.

| Тема | Запомнить |
|---|---|
| Falsy | `false`, `0`, `-0`, `''`, `null`, `undefined`, `NaN` — остальное truthy |
| `[]` и `{}` | truthy! Пустоту массива проверяй через `.length` |
| `v-if` | элемента нет в DOM, если условие falsy |
| `v-else-if` / `v-else` | сразу после `v-if`, без элементов между |
| `v-show` | элемент в DOM, но `display: none`; для частых переключений |
| `<template v-if>` | группа без лишней обёртки; `v-show` на нём не работает |
| `v-for="x in list"` | повторить для каждого элемента |
| `(x, index) in list` | с номером, с нуля |
| `n in 5` | числа с 1 до 5 |
| `:key="x.id"` | уникальный и постоянный; **не** индекс |
| `v-if` + `v-for` на одном элементе | ✗ — фильтр в `computed` или `<template>` |
| Сортировка для показа | копия в `computed`: `[...arr].sort()` |
| 📜 Options API | шаблон тот же; массив в `data()`, фильтр в опции `computed`, `this.` |
