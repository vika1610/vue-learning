# Занятие 1. Наблюдатели

## Разминка (10 мин): регулярные выражения и `localStorage`

### Регулярные выражения (обзор)

**Регулярное выражение** — шаблон для поиска в строке. Пишется между слешами `/.../`. Метод `test` отвечает: подходит строка или нет.

```js
/\d/.test('abc1')        // true — есть цифра (\d — любая цифра)
/\d/.test('abc')         // false
/^\d{6}$/.test('123456') // true — ровно 6 цифр от начала (^) до конца ($)
/^\d{6}$/.test('12345a') // false
```

Самые полезные кусочки:

| Шаблон | Значит |
|---|---|
| `\d` | любая цифра |
| `\s` | пробел, таб, перенос |
| `\S` | всё, **кроме** пробельных |
| `+` | «один или больше» предыдущего |
| `{6}` | ровно 6 раз |
| `^` / `$` | начало / конец строки |
| `[a-z]` | любая буква от a до z |

Глубоко регулярки учить не нужно: для форм хватает нескольких готовых шаблонов.

### `localStorage` — память браузера

```js
localStorage.setItem('theme', 'dark')   // сохранить (только строки!)
localStorage.getItem('theme')           // 'dark'
localStorage.getItem('nope')            // null — такого ключа нет
localStorage.removeItem('theme')        // удалить
```

Данные живут **после перезагрузки** страницы и даже после закрытия браузера.

Вопросы:
1. Что вернёт `/^\S+@\S+$/.test('anna@mail.ru')`? А `'anna mail.ru'`?
2. Что окажется в `localStorage` после `localStorage.setItem('user', { name: 'Аня' })`?

<details>
<summary>Ответ</summary>

1. `true` и `false`. Шаблон: «несколько непробельных символов, `@`, ещё несколько непробельных». Во второй строке нет `@`.
2. Строка `'[object Object]'` 😱 — объект превратился в бесполезную строку. Объекты сохраняют через `JSON.stringify`, а читают через `JSON.parse` (день 5 недели 0). А раз `JSON.parse` может упасть на испорченной строке — пригодится твоя `parseJSONSafe`.

Посмотреть, что лежит в `localStorage`: DevTools (F12) → вкладка **Application** → **Local Storage**.

</details>

## Часть 1. `computed` или `watch`?

Оба реагируют на изменения данных. Но задачи у них разные.

| | `computed` | `watch` |
|---|---|---|
| Для чего | **получить значение** из других данных | **сделать что-то**, когда данные изменились |
| Что возвращает | значение (используется в шаблоне) | ничего |
| Побочные эффекты | ✗ нельзя (должен быть «чистым», день 4 недели 1) | ✓ для этого и нужен |
| Примеры | полное имя, сумма, отфильтрованный список, текст ошибки | сохранить в `localStorage`, загрузить данные с сервера, поменять `document.title`, написать в консоль |

Мнемоника: **`computed` — «вычисли», `watch` — «последи и сделай»**.

Это ответ на вопрос недели «Чем `watch` отличается от `computed`?».

### Правило

Сначала спроси себя: «Мне нужно **значение**?» Если да — `computed`. И только если нужно **действие** в ответ на изменение — `watch`.

Частая ошибка новичка — делать через `watch` то, что должно быть `computed`:

```js
// ✗ плохо: вручную поддерживаем вычисляемое значение
const fullName = ref('')
watch([firstName, lastName], () => {
  fullName.value = `${firstName.value} ${lastName.value}`
})

// ✓ хорошо
const fullName = computed(() => `${firstName.value} ${lastName.value}`)
```

## Часть 2. `watch`

### Синтаксис

```vue
<script setup>
import { ref, watch } from 'vue'

const search = ref('')

watch(search, (newValue, oldValue) => {
  console.log(`запрос изменился: «${oldValue}» → «${newValue}»`)
})
</script>

<template>
  <input v-model="search" placeholder="Поиск">
</template>
```

- первый аргумент — **что** наблюдать (**источник**);
- второй — функция, которую Vue вызовет **после** каждого изменения. Она получает **новое** и **старое** значение.

Введи в поле «кот» — в консоли появятся три строки: `«» → «к»`, `«к» → «ко»`, `«ко» → «кот»`.

### Что можно наблюдать

```js
const count = ref(0)
const user = reactive({ name: 'Аня', age: 25 })

watch(count, ...)                          // ✓ ref
watch(user, ...)                           // ✓ весь reactive-объект
watch(() => user.age, ...)                 // ✓ одно поле — через функцию-«геттер»
watch([count, () => user.age], ...)        // ✓ несколько источников массивом
```

### ⚠️⚠️ Поле объекта — только через функцию

```js
watch(user.age, (n) => console.log(n))       // ✗ Vue предупредит: invalid watch source
watch(() => user.age, (n) => console.log(n)) // ✓
```

`user.age` — это просто **число** `25` в момент вызова `watch`. Следить за числом нельзя, у него нет «охранника». А функция `() => user.age` каждый раз **заново читает** поле через реактивный объект, и Vue видит, что она от него зависит.

Та же идея, что «деструктуризация `reactive` теряет реактивность» (день 3 недели 1): как только ты достала примитив из реактивного объекта, связь пропала.

### ⚠️ Бесконечный цикл

```js
watch(count, () => {
  count.value++   // ✗ изменение count → снова watch → снова изменение → …
})
```

Наблюдатель не должен менять **свой же** источник. Vue остановит цикл и предупредит в консоли, но лучше так не писать.

## Часть 3. Опции `deep` и `immediate`

Третьим аргументом `watch` принимает объект с настройками.

### `deep` — следить за вложенными изменениями

```js
const settings = ref({ theme: 'light', fontSize: 16 })

watch(settings, () => console.log('настройки изменились'))
settings.value.fontSize = 18   // ✗ watch НЕ сработает

watch(settings, () => console.log('настройки изменились'), { deep: true })
settings.value.fontSize = 18   // ✓ сработает
```

Если наблюдать `ref` с объектом **без** `deep`, Vue заметит только **замену** объекта целиком (`settings.value = {...}`), но не изменение его полей.

А `reactive`-объект Vue наблюдает **глубоко автоматически**:

```js
const form = reactive({ name: '', email: '' })
watch(form, () => console.log('форма изменилась'))   // глубоко по умолчанию
form.name = 'Аня'   // ✓ сработает
```

Тем не менее `{ deep: true }` для формы полезно писать явно: так сразу видно, что наблюдатель реагирует на любое поле.

### ⚠️ С `deep` старое и новое значение — один и тот же объект

```js
watch(settings, (newVal, oldVal) => {
  console.log(newVal === oldVal)   // true!
}, { deep: true })
```

Когда меняется **поле**, объект остаётся тем же (ссылки, день 2 недели 0). Поэтому «старого» объекта нет. Если нужно сравнение, наблюдай конкретное поле через функцию.

### `immediate` — сработать сразу

По умолчанию `watch` **ленивый**: он молчит, пока данные не изменятся. Но иногда нужно выполнить действие и **сразу при создании** компонента:

```js
watch(userId, (id) => {
  loadProfile(id)          // загрузить профиль
}, { immediate: true })    // и сразу при старте, и при каждой смене id
```

На неделе 5 (блог, `/posts/:id`) это понадобится обязательно.

## Часть 4. `watchEffect` — наблюдатель «сам разберусь»

```js
import { ref, watchEffect } from 'vue'

const search = ref('')
const page = ref(1)

watchEffect(() => {
  console.log(`ищем «${search.value}», страница ${page.value}`)
})
```

`watchEffect` **сам находит** зависимости: какие реактивные данные функция прочитала, за теми и следит. Как `computed`, только для действий, а не для значений.

| | `watch` | `watchEffect` |
|---|---|---|
| Источник | указываешь явно | находится сам |
| Первый запуск | только при изменении (или `immediate`) | **сразу** |
| Новое / старое значение | есть | нет |
| Когда удобнее | нужно знать, что именно и как изменилось; нужно старое значение | «при любом изменении того, что внутри, — сделай вот это» |

### ⚠️ `watchEffect` следит только за тем, что **прочитал**

```js
watchEffect(() => {
  if (enabled.value) {
    console.log(text.value)   // text читается, только если enabled === true
  }
})
```

Пока `enabled` ложно, `text.value` **не читается**, и `watchEffect` за ним не следит. Обычно это то, что нужно, но иногда приводит к удивлению: «почему не срабатывает?»

### Остановить наблюдатель

И `watch`, и `watchEffect` возвращают функцию остановки:

```js
const stop = watch(search, ...)
stop()   // больше не следим
```

Обычно это не нужно: Vue сам останавливает наблюдатели, когда компонент удаляется со страницы.

# Занятие 2. Валидация и черновик

Задача сегодня большая. Сначала разберём два приёма на **другом** примере — форме отзыва о товаре: имя, оценка от 1 до 5 и текст отзыва.

## Часть 5. Валидация формы

### Ошибки — это `computed`

Текст ошибки **вычисляется** из данных формы, значит это `computed`, а не `watch` и не отдельные `ref`:

```js
const review = reactive({ author: '', rating: 0, text: '' })

const errors = computed(() => ({
  author: review.author.length < 2 ? 'Имя — минимум 2 символа' : '',
  rating: review.rating < 1 ? 'Поставьте оценку' : '',
  text: review.text.length < 10 ? 'Отзыв — минимум 10 символов' : '',
}))

const isValid = computed(() => Object.values(errors.value).every((e) => e === ''))
```

- для каждого поля — строка ошибки или пустая строка `''`;
- `Object.values` (день 2 недели 0) даёт массив всех ошибок;
- `every` (день 3 недели 0): «все ли ошибки пустые?»

В шаблоне:

```vue
<input v-model.trim="review.author">
<p class="error" v-if="errors.author">{{ errors.author }}</p>

<button :disabled="!isValid">Отправить</button>
```

`v-if="errors.author"` — пустая строка falsy, поэтому абзац с ошибкой появится, только если ошибка есть.

### ⚠️ Не ругаться сразу при открытии формы

С кодом выше пользователь открывает страницу, ещё ничего не ввёл — а под полями уже три красные ошибки. Неприятно.

Нормальное поведение: показывать ошибку поля, только когда пользователь **с ним поработал** или **попытался отправить**. Для этого заведи объект «тронутых» полей:

```js
const touched = reactive({ author: false, rating: false, text: false })
const triedSubmit = ref(false)

function showError(field) {
  return (touched[field] || triedSubmit.value) && errors.value[field]
}
```

```vue
<input v-model.trim="review.author" @blur="touched.author = true">
<p class="error" v-if="showError('author')">{{ errors.author }}</p>
```

- `@blur` — событие «поле потеряло фокус» (вчерашний день): пользователь ушёл из поля;
- `showError` — функция с аргументом, поэтому функция, а не `computed`.

> Ещё вариант — `v-model.lazy` (вчерашний день): данные обновляются только при уходе из поля. Но тогда и ошибка пропадает только после ухода, что тоже не всегда удобно.

### Регулярки для проверок

```js
/\d/.test(review.text)          // есть ли цифра
/^\S+@\S+\.\S+$/.test(email)    // похоже ли на email: что-то @ что-то . что-то
```

Шаблон для email — **упрощённый**: он отсеет явные опечатки, но не проверит, существует ли адрес. Для учебной формы этого достаточно.

## Часть 6. Черновик в `localStorage`

### Сохранить при любом изменении → `watch`

Сохранение — это **действие** в ответ на изменение, значит `watch`:

```js
const DRAFT_KEY = 'review-draft'

watch(review, () => {
  localStorage.setItem(DRAFT_KEY, JSON.stringify(review))
}, { deep: true })
```

### Восстановить при открытии

```js
const saved = parseJSONSafe(localStorage.getItem(DRAFT_KEY), null)
if (saved) {
  Object.assign(review, saved)
}
```

- `getItem` вернёт `null`, если черновика нет. `JSON.parse(null)` даёт `null`, а испорченную строку поймает твоя `parseJSONSafe` (её можно скопировать из недели 0);
- `Object.assign(review, saved)` **заполняет поля** существующего реактивного объекта. Не замена объекта целиком — помнишь ловушку 4 из дня 3 недели 1?

Этот код пишется прямо в `<script setup>`, сверху вниз: он выполнится один раз, при создании компонента.

### ⚠️ Не всё нужно сохранять

Если в форме есть пароль, его **нельзя** класть в `localStorage`: любой, кто откроет DevTools на этом компьютере, его увидит. Удобный приём — деструктуризация с остатком (день 3 недели 0):

```js
watch(account, () => {
  const { password, ...safe } = account   // safe — всё, кроме password
  localStorage.setItem(KEY, JSON.stringify(safe))
}, { deep: true })
```

### Очистить черновик

```js
function clearDraft() {
  localStorage.removeItem(DRAFT_KEY)
  Object.assign(review, { author: '', rating: 0, text: '' })
}
```

⚠️ Порядок важен: если сначала очистить поля, `watch` тут же сохранит пустую форму. В этом случае неважно, но в общем случае помни, что `watch` сработает на любое изменение формы.

### Тот же черновик через `watchEffect`

```js
watchEffect(() => {
  localStorage.setItem(DRAFT_KEY, JSON.stringify(review))
})
```

`JSON.stringify` **читает все поля** `review`, поэтому `watchEffect` следит за каждым из них. Короче, но менее явно: по коду не сразу видно, за чем именно идёт наблюдение. Это и есть бонус-задание: попробуй оба варианта и сравни.

# Занятие 3. 📜 Options API

## Часть 7. 📜 Наблюдатели в Options API

### Опция `watch`

**Composition API:**

```js
const search = ref('')

watch(search, (newValue, oldValue) => {
  console.log(newValue, oldValue)
})
```

**Options API:**

```js
export default {
  data() {
    return { search: '' }
  },
  watch: {
    search(newValue, oldValue) {
      console.log(newValue, oldValue)
    },
  },
}
```

Ключ в опции `watch` — **имя** того, за чем следим (поле `data` или `computed`), значение — функция-обработчик.

### `deep` и `immediate` в Options API

Если нужны опции, вместо функции пишут объект с `handler`:

```js
watch: {
  review: {
    handler() {
      localStorage.setItem('review-draft', JSON.stringify(this.review))
    },
    deep: true,
    immediate: false,
  },
},
```

### ⚠️ В Options API `deep` нужен и для объектов из `data()`

В Composition API `reactive`-объект наблюдается глубоко автоматически. А в Options API наблюдение за полем `data()` с объектом **по умолчанию не глубокое**: изменение `this.review.text` не вызовет обработчик без `deep: true`. Частая ошибка при переписывании с одного стиля на другой.

### Следить за вложенным полем — строкой с точкой

```js
watch: {
  'review.rating'(newRating) {
    console.log('новая оценка', newRating)
  },
},
```

Путь к полю пишется **строкой в кавычках** — аналог `watch(() => review.rating, ...)` из Composition API.

### Валидация в Options API

```js
export default {
  data() {
    return {
      review: { author: '', rating: 0, text: '' },
      touched: { author: false, rating: false, text: false },
      triedSubmit: false,
    }
  },
  computed: {
    errors() {
      return {
        author: this.review.author.length < 2 ? 'Имя — минимум 2 символа' : '',
        rating: this.review.rating < 1 ? 'Поставьте оценку' : '',
        text: this.review.text.length < 10 ? 'Отзыв — минимум 10 символов' : '',
      }
    },
    isValid() {
      return Object.values(this.errors).every((e) => e === '')
    },
  },
  methods: {
    showError(field) {
      return (this.touched[field] || this.triedSubmit) && this.errors[field]
    },
  },
}
```

### Восстановить черновик — где?

В `<script setup>` код восстановления просто пишется сверху. В Options API «код, который выполняется при создании компонента», кладут в специальный **хук** `created()`:

```js
export default {
  data() { /* ... */ },
  created() {
    const saved = localStorage.getItem('review-draft')
    if (saved) Object.assign(this.review, JSON.parse(saved))
  },
}
```

Хуки жизненного цикла — тема **завтрашнего** дня. Сегодня достаточно знать, что `created` — «когда компонент создан».

### `watchEffect` в Options API

Отдельной опции нет. В рабочем коде иногда встречается `this.$watch(...)` внутри хуков — это «программный» вариант той же опции `watch`.

## Шпаргалка

| Тема | Запомнить |
|---|---|
| `computed` или `watch` | вычисли значение / последи и сделай действие |
| `watch(src, (n, o) => ...)` | вызывается после изменения источника |
| Источник | `ref`, `reactive`, `() => obj.field`, массив источников |
| Поле объекта | только через функцию `() => obj.field` |
| `{ deep: true }` | вложенные изменения `ref` с объектом; у `reactive` — автоматически |
| `{ immediate: true }` | сработать и сразу при создании |
| `watchEffect(() => ...)` | зависимости сам; запускается сразу; нет старого значения |
| Бесконечный цикл | не меняй источник внутри его же `watch` |
| Ошибки формы | `computed`-объект; показывать после `@blur` или попытки отправки |
| Черновик | `watch` + `JSON.stringify` → `localStorage`; восстановить через `Object.assign` |
| Пароли | не сохранять: `const { password, ...safe } = form` |
| 📜 Options API | опция `watch: { field(n, o) {} }`; `{ handler, deep, immediate }`; `'a.b'` для поля; `deep` нужен для объектов |
