## Часть 1. npm и `package.json`

### Что такое npm

**npm** — менеджер пакетов для JavaScript. **Пакет** — чужой код, который можно подключить к своему проекту: Vue, роутер, библиотека для графиков, Vitest для тестов. Пакеты лежат в общем хранилище в интернете (npmjs.com), а npm их скачивает.

Ты уже пользовалась npm: `npm install`, `npm test`, `npm run dev`. Теперь разберёмся, что за этим стоит.

### `package.json` — паспорт проекта

В корне каждого проекта лежит `package.json`. Открой тот, что в `week-00-js`:

```json
{
  "name": "week-00-js",
  "type": "module",
  "scripts": {
    "test": "vitest run",
    "test:day1": "vitest run day-1"
  },
  "devDependencies": {
    "vitest": "^5.0.3"
  }
}
```

| Поле | Что значит |
|---|---|
| `name` | имя проекта |
| `type: "module"` | файлы `.js` — ES-модули (можно `import` / `export`) |
| `scripts` | короткие команды: `npm run test:day1` запустит `vitest run day-1` |
| `dependencies` | пакеты, нужные **приложению** для работы (Vue, роутер) |
| `devDependencies` | пакеты, нужные только **при разработке** (Vite, Vitest) |

### Версии: что значит `^5.0.3`

Версия из трёх чисел: **мажорная.минорная.патч**.

- **патч** (`5.0.3 → 5.0.4`) — исправления ошибок;
- **минорная** (`5.0 → 5.1`) — новые возможности без поломок;
- **мажорная** (`5 → 6`) — могут быть **несовместимые** изменения.

`^5.0.3` значит «любая 5.x.x не ниже 5.0.3». Мажорную версию npm сам не поднимет: это защита от поломок.

### `node_modules` и `package-lock.json`

- **`npm install`** читает `package.json`, скачивает все пакеты (и пакеты, нужные этим пакетам) в папку **`node_modules`**;
- **`package-lock.json`** — точный список **всех** установленных версий. Благодаря ему у всех разработчиков проекта ставятся одинаковые версии.

### ⚠️ `node_modules` не коммитят

Папка `node_modules` огромная (десятки и сотни мегабайт) и легко восстанавливается командой `npm install`. Поэтому её **не** добавляют в git: в `.gitignore` она уже записана. А вот `package.json` и `package-lock.json` коммитят **обязательно**.

### Главные команды

| Команда | Что делает |
|---|---|
| `npm install` | установить всё из `package.json` |
| `npm install pinia` | добавить пакет в `dependencies` |
| `npm install -D vitest` | добавить пакет в `devDependencies` |
| `npm run dev` | запустить команду `dev` из `scripts` |
| `npm test` | сокращение для `npm run test` |

### ⚠️ Команды — из папки с `package.json`

Помнишь ошибку с `serve:day4` в неделе 0? npm ищет `package.json` **в текущей папке**. Если ты в другом месте, будет `Missing script` или `Could not read package.json`. Первым делом проверь, в какой ты папке: `pwd` в Git Bash.

## Часть 2. Что такое Vite

**Vite** (читается «вит», с французского — «быстрый») — инструмент, который:

1. **в разработке** (`npm run dev`) запускает локальный сервер, понимает `.vue`-файлы, импорты пакетов без `./`, и мгновенно обновляет страницу при сохранении (горячая перезагрузка, день 1 недели 1);
2. **для публикации** (`npm run build`) собирает весь проект в несколько маленьких оптимизированных файлов в папке `dist` (неделя 8, деплой).

Браузер сам по себе **не понимает** `.vue`-файлы. Vite «на лету» превращает их в обычный JavaScript, который браузер умеет выполнять.

> Ты уже работала с Vite: `vue-exercises` и команды `serve:day4` / `serve:day5` в неделе 0 — это он.

### `npm create vue@latest`

Официальный способ создать Vue-проект. Команда задаёт вопросы и создаёт готовый каркас с Vite и Vue. Подробные шаги — в [task.md](task.md).

## Часть 3. Что лежит в проекте

После создания проект выглядит примерно так:

```
shop/
├── index.html            ← единственная HTML-страница
├── package.json          ← паспорт проекта
├── vite.config.js        ← настройки Vite
├── public/               ← файлы «как есть»: favicon, картинки
│   └── favicon.ico
└── src/                  ← ВЕСЬ твой код
    ├── main.js           ← точка входа: создаёт приложение
    ├── App.vue           ← корневой компонент
    ├── assets/           ← стили, картинки, которые импортируются в код
    │   └── main.css
    └── components/       ← остальные компоненты
        └── HelloWorld.vue
```

### `index.html`

```html
<body>
  <div id="app"></div>
  <script type="module" src="/src/main.js"></script>
</body>
```

Почти пустая страница: один `div` с `id="app"` и подключение `main.js`. Всё остальное нарисует Vue. Такое приложение называют **SPA** — Single Page Application, «одностраничное приложение».

### `public/` или `src/assets/`

- **`public/`** — файлы копируются как есть, доступны по адресу от корня: `public/logo.png` → `<img src="/logo.png">`;
- **`src/assets/`** — файлы, которые **импортируются** в код. Vite их обрабатывает и оптимизирует.

Для начала достаточно: картинки для карточек товаров можно брать по ссылке из интернета или положить в `public/`.

## Часть 4. `main.js` — точка входа

```js
import './assets/main.css'

import { createApp } from 'vue'
import App from './App.vue'

createApp(App).mount('#app')
```

Разберём:

1. `import './assets/main.css'` — подключить общие стили. Да, CSS можно импортировать, это умеет Vite;
2. `import { createApp } from 'vue'` — функция, создающая приложение;
3. `import App from './App.vue'` — корневой компонент. Экспорт **по умолчанию**: без фигурных скобок (неделя 0, день 4);
4. `createApp(App)` — создать приложение, где главный компонент — `App`;
5. `.mount('#app')` — «вмонтировать» приложение в элемент `<div id="app">` из `index.html`.

```
index.html             main.js                 App.vue
<div id="app">  ◄──── createApp(App)  ◄────── <template>…</template>
                       .mount('#app')
```

### ⚠️ `mount` в элемент, которого нет

```js
createApp(App).mount('#root')   // ✗ в index.html id="app", а не "root"
```

Страница будет пустой, а в консоли — предупреждение *Failed to mount app: mount target selector "#root" returned null*. Это ровно ловушка `querySelector` → `null` из дня 4 недели 0.

### Подключение плагинов

Между `createApp` и `mount` подключают **плагины** — роутер, Pinia:

```js
const app = createApp(App)
app.use(router)   // неделя 5
app.use(pinia)    // неделя 6
app.mount('#app')
```

Это ровно то, что в `vue-exercises` делал служебный код, а в неделях 5–6 ты делала бы в `setup.js`. В своём проекте ты будешь писать это сама.

### Как это было в `vue-exercises`

Помнишь кнопку «⏏ Размонтировать»? Она вызывала `app.unmount()` — обратное к `mount`. А каждая задача создавалась своим `createApp(Exercise)`. Теперь ты знаешь, как устроено меню изнутри.

### Импорт компонента в компонент

```vue
<!-- App.vue -->
<script setup>
import ProductCard from './components/ProductCard.vue'
</script>

<template>
  <ProductCard />
</template>
```

В `<script setup>` достаточно **импортировать** компонент — и его можно использовать в шаблоне как тег. Подробно — завтра.

### ⚠️ Имена компонентов — с большой буквы и из двух слов

- файл и тег: `ProductCard.vue` → `<ProductCard />` (PascalCase — каждое слово с большой буквы);
- имя лучше **из двух и более слов**: `Header` может совпасть с HTML-тегом `<header>`, а `AppHeader` — нет.

## Часть 5. 📜 Как это в Options API

### `main.js` — одинаковый

Точка входа **не зависит** от стиля компонентов: `createApp(App).mount('#app')` одинаков для Options API и Composition API. Даже если все компоненты проекта на Options API, `main.js` выглядит так же.

### Корневой компонент на Options API

```vue
<script>
export default {
  data() {
    return { shopName: 'Мой магазин' }
  },
}
</script>

<template>
  <h1>{{ shopName }}</h1>
</template>
```

### ⚠️ Подключение дочерних компонентов: импорт + регистрация

В `<script setup>` достаточно импорта. В Options API компонент нужно ещё и **зарегистрировать** в опции `components`:

```vue
<script>
import ProductCard from './components/ProductCard.vue'

export default {
  components: {
    ProductCard,      // сокращение от ProductCard: ProductCard (день 2 недели 0)
  },
  data() {
    return { /* ... */ }
  },
}
</script>

<template>
  <ProductCard />
</template>
```

Если забыть `components`, в консоли будет предупреждение *Failed to resolve component: ProductCard*, а на странице — пустота (точнее, неизвестный HTML-тег). Это одна из самых частых ошибок при работе с Options API.

### `name` компонента

В Options API у компонента часто есть опция `name`:

```js
export default {
  name: 'ProductCard',
  // ...
}
```

Она нужна для отладки (так компонент подписан во Vue DevTools) и в некоторых особых случаях. В `<script setup>` имя берётся из имени файла автоматически.

### Как узнать стиль в рабочем проекте

Открой несколько `.vue`-файлов рабочего проекта и посмотри, что после `<script`: ` setup>` или просто `>` с `export default`. В Vue 3.5-проекте могут встречаться оба. Посмотри и `main.js`: там будет `createApp(App)`, а между ним и `mount` — какие плагины подключены (`.use(router)`, `.use(pinia)` или что-то своё). Это хорошая карта того, что используется в проекте.
