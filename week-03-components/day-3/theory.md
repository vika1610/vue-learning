# Занятие 1. События компонента

## Разминка (10 мин): callback-функции и паттерн «событие»

**Callback** — функция, которую передают другой функции, чтобы та вызвала её **потом**, когда что-то случится.

```js
function askName(onAnswer) {
  const name = 'Аня'          // представим, что пользователь ввёл имя
  onAnswer(name)              // «сообщаем» о результате
}

askName((name) => console.log(`Привет, ${name}!`))
```

`addEventListener` из дня 4 недели 0 — тоже callback: «когда будет клик, вызови эту функцию».

Вопрос: кто решает, **что делать** с именем — `askName` или тот, кто её вызвал?

<details>
<summary>Ответ</summary>

Тот, кто вызвал. `askName` только сообщает: «вот имя». А что с ним делать — поздороваться, сохранить, отправить на сервер — решает вызывающий код, передавая свою функцию.

Это и есть паттерн «событие»: кто-то **сообщает**, что что-то произошло, а **решает**, что делать, другой. Сегодня компоненты научатся так же сообщать родителю о событиях.

</details>

## Часть 1. Данные вниз, события вверх

Вчера: родитель передаёт данные ребёнку через **props**. Ребёнок их **не меняет**.

Но как быть, если в ребёнке есть кнопка «Удалить»? Данные (массив) — у родителя, а кнопка — у ребёнка. Ребёнок не может удалить сам: это не его данные.

Решение — ребёнок **сообщает** родителю: «меня попросили удалить». А родитель, хозяин данных, сам удаляет.

```
                    App.vue (хозяин данных)
                    ▲              │
    событие remove  │              │  props: text, done
    («удали меня»)  │              ▼
                    ShoppingItem (только показывает и сообщает)
```

**Props вниз, события вверх.** Это главное правило связи компонентов, и ответ на вопрос недели «Как данные идут от родителя к ребёнку и обратно?».

## Часть 2. `defineEmits` и `emit`

### В ребёнке: объявить и отправить

```vue
<!-- TodoItem.vue -->
<script setup>
defineProps({
  text: String,
  done: Boolean,
})

const emit = defineEmits(['toggle', 'remove'])
</script>

<template>
  <li :class="{ done }">
    <input type="checkbox" :checked="done" @change="emit('toggle')">
    {{ text }}
    <button @click="emit('remove')">✕</button>
  </li>
</template>
```

- `defineEmits` — макрос, импортировать не нужно (как `defineProps`);
- в массиве — **названия** событий, которые компонент умеет отправлять;
- `emit('remove')` — **отправить** событие с именем `remove`.

В шаблоне можно писать и короче, через встроенную `$emit`:

```vue
<button @click="$emit('remove')">✕</button>
```

### В родителе: слушать

События компонента слушают **так же**, как события DOM — через `@`:

```vue
<!-- App.vue -->
<script setup>
import { ref } from 'vue'
import TodoItem from './components/TodoItem.vue'

const todos = ref([
  { id: 1, text: 'Позвонить маме', done: false },
  { id: 2, text: 'Купить хлеб', done: true },
])

function removeTodo(id) {
  todos.value = todos.value.filter((t) => t.id !== id)
}
</script>

<template>
  <ul>
    <TodoItem
      v-for="todo in todos"
      :key="todo.id"
      :text="todo.text"
      :done="todo.done"
      @toggle="todo.done = !todo.done"
      @remove="removeTodo(todo.id)"
    />
  </ul>
</template>
```

`@remove="removeTodo(todo.id)"` — «когда этот `TodoItem` сообщит `remove`, удали задачу с его `id`». Родитель знает `todo.id` из `v-for`, поэтому ребёнку даже не нужно его передавать.

### Это похоже на `@click`

| | Событие DOM | Событие компонента |
|---|---|---|
| Кто отправляет | браузер | твой компонент через `emit` |
| Как слушать | `@click="..."` | `@remove="..."` |
| Как назвать | заранее определены (`click`, `input`) | придумываешь сама |

## Часть 3. Данные вместе с событием

Иногда ребёнок должен не только сообщить «что-то случилось», но и передать **данные**:

```vue
<!-- RatingPicker.vue -->
<script setup>
const emit = defineEmits(['select'])
</script>

<template>
  <button v-for="n in 5" :key="n" @click="emit('select', n)">{{ n }} ⭐</button>
</template>
```

`emit('select', n)` — второй и следующие аргументы `emit` передаются **в обработчик** родителя:

```vue
<!-- родитель -->
<script setup>
import { ref } from 'vue'
const rating = ref(0)

function onSelect(stars) {
  rating.value = stars
}
</script>

<template>
  <RatingPicker @select="onSelect" />
  <p>Оценка: {{ rating }}</p>
</template>
```

- если обработчик указан **по имени** (`@select="onSelect"`), данные придут в аргументы функции;
- в выражении данные доступны через **`$event`**: `@select="rating = $event"`.

Помнишь `$event` из дня 2 недели 2? Для событий компонента `$event` — это **первый аргумент**, переданный в `emit`, а не объект события DOM.

### Несколько значений

```js
emit('move', fromIndex, toIndex)
```

```js
function onMove(from, to) { /* ... */ }
```

Если значений много, удобнее передать **один объект**: `emit('update', { title, price })`.

# Занятие 2. Правила и практика

## Часть 4. Кто владеет данными

Главный вопрос при проектировании компонентов: **где живут данные?**

**Правило: данные живут в самом нижнем компоненте, которому они нужны целиком, — обычно в общем родителе тех, кто их использует.**

Примеры:

| Данные | Кому нужны | Где живут |
|---|---|---|
| список задач | списку, счётчику «осталось», форме добавления | в их общем родителе |
| текст в поле «новая задача» | только форме добавления | в самой форме |
| «раскрыта ли подсказка» у одной задачи | только этой задаче | в ней самой |

Если данные нужны только одному компоненту, им незачем жить в родителе. Если двум соседям — они живут у общего родителя, а соседи получают props и шлют события.

> А что если данные нужны **многим** компонентам далеко друг от друга? Таскать props через десять уровней неудобно. Для этого будут `provide` / `inject` (послезавтра) и Pinia (неделя 6).

## Часть 5. Подводные камни

### ⚠️ Имя события: как назвать

```js
defineEmits(['remove', 'toggle', 'add-item'])
```

- называй событие **глаголом или фактом** о том, что случилось: `remove`, `toggle`, `select`, `submit`;
- для имени из нескольких слов в шаблоне принято `kebab-case`: `@add-item`. В скрипте можно `emit('addItem')` — Vue переведёт сам, как с props.

### ⚠️ Не объявить событие

```js
const emit = defineEmits(['remove'])
emit('toggle')   // ⚠️ toggle не объявлен
```

Событие всё равно дойдёт до родителя, но Vue предупредит в консоли. Объявление в `defineEmits` — это **документация**: по нему сразу видно, что умеет сообщать компонент. Плюс без объявления событие может «продублироваться» как обычное событие DOM (подробнее — день 5 про наследование атрибутов).

### ⚠️ Событие и одноимённое событие DOM

Если назвать своё событие `click` и не объявить его в `defineEmits`, родитель получит **и** твоё событие, **и** настоящий клик по корневому элементу — обработчик сработает дважды. Объявляй события и давай им понятные имена.

### ⚠️ События не всплывают через компоненты

```
App ← слушает @remove
└── TodoList
    └── TodoItem → emit('remove')
```

Событие компонента получает **только прямой родитель** (`TodoList`). До `App` оно само не дойдёт, в отличие от всплытия событий DOM (разминка дня 2 недели 2). Если нужно передать выше, `TodoList` должен поймать и отправить своё событие:

```vue
<!-- TodoList.vue -->
<TodoItem ... @remove="emit('remove', todo.id)" />
```

### ⚠️ Ребёнок меняет данные родителя через props-объект

```js
// TodoItem.vue
const props = defineProps({ todo: Object })
function toggle() {
  props.todo.done = !props.todo.done   // ⚠️ работает, но нарушает правило
}
```

Вчера мы это разбирали: объект передан по ссылке, Vue не помешает. Но тогда хозяин данных не знает, кто и когда их поменял. **Правильно — `emit('toggle')`**, и родитель меняет сам.

# Занятие 3. 📜 Options API

## Часть 6. 📜 События в Options API

### Опция `emits` и `this.$emit`

**Composition API:**

```vue
<script setup>
defineProps({ text: String })
const emit = defineEmits(['remove', 'rename'])

function rename() {
  emit('rename', 'Новое название')
}
</script>

<template>
  <span>{{ text }}</span>
  <button @click="emit('remove')">✕</button>
  <button @click="rename">✎</button>
</template>
```

**Options API:**

```vue
<script>
export default {
  props: { text: String },
  emits: ['remove', 'rename'],
  methods: {
    rename() {
      this.$emit('rename', 'Новое название')
    },
  },
}
</script>

<template>
  <span>{{ text }}</span>
  <button @click="$emit('remove')">✕</button>
  <button @click="rename">✎</button>
</template>
```

| | Composition API | Options API |
|---|---|---|
| Объявить | `const emit = defineEmits([...])` | опция `emits: [...]` |
| Отправить в скрипте | `emit('rename', data)` | `this.$emit('rename', data)` |
| Отправить в шаблоне | `emit(...)` или `$emit(...)` | `$emit(...)` |
| Слушать в родителе | `@rename="..."` | `@rename="..."` — то же |

### ⚠️ `emits` в Options API — необязательная, но важная опция

Во Vue 2 опции `emits` не было вообще: события просто отправлялись через `this.$emit`. Во Vue 3 её добавили. В рабочем коде можно встретить компоненты **без** `emits` — они работают, но с предупреждениями и риском двойного срабатывания (часть 5). Если правишь такой компонент, добавь `emits`.

### Родитель в Options API

```vue
<script>
import TodoItem from './TodoItem.vue'

export default {
  components: { TodoItem },
  data() {
    return {
      todos: [{ id: 1, text: 'Позвонить маме', done: false }],
    }
  },
  methods: {
    removeTodo(id) {
      this.todos = this.todos.filter((t) => t.id !== id)
    },
  },
}
</script>

<template>
  <TodoItem
    v-for="todo in todos"
    :key="todo.id"
    :text="todo.text"
    @remove="removeTodo(todo.id)"
  />
</template>
```

### ⚠️ `$emit` внутри стрелки в `methods`

```js
methods: {
  later() {
    setTimeout(() => this.$emit('done'), 1000)        // ✓ стрелка — this компонента
    setTimeout(function () { this.$emit('done') }, 1000) // ✗ this потерян
  },
},
```

Та же ловушка, что и с данными: `this.$emit` — это метод компонента, ему нужен правильный `this`.

## Шпаргалка

| Тема | Запомнить |
|---|---|
| Правило | props вниз, события вверх |
| `const emit = defineEmits(['a', 'b'])` | объявить события; импорт не нужен |
| `emit('remove')` | отправить событие |

| `$event` | первый аргумент `emit` |

| Где данные | у общего родителя тех, кому нужны |
| Менять данные родителя | только через событие, не через props-объект |
