# Занятие 1. Атрибуты и `provide` / `inject`

## Разминка (5 мин): `export default` и именованный `export`

В одном файле `utils.js`:

```js
export default function formatPrice(price) { /* ... */ }
export const CURRENCY = '₽'
export function formatDate(date) { /* ... */ }
```

Как импортировать все три в другой файл одной строкой?

<details>
<summary>Ответ</summary>

```js
import formatPrice, { CURRENCY, formatDate } from './utils.js'
```

`default` — без скобок и с любым именем, именованные — в скобках с точными именами. Обычно `default` экспортируют «главное» (у `.vue`-файла это сам компонент), а именованные — вспомогательные функции и константы.

</details>

## Часть 1. Наследование атрибутов

### Что происходит с атрибутами, которые не props

```vue
<!-- BaseButton.vue -->
<script setup>
defineProps({ variant: String })
</script>

<template>
  <button class="btn">
    <slot />
  </button>
</template>
```

```vue
<!-- родитель -->
<BaseButton variant="primary" type="submit" disabled title="Сохранить">
  Сохранить
</BaseButton>
```

`variant` объявлен как prop — он уходит в props. А `type`, `disabled`, `title` **не объявлены**. Что с ними будет?

Vue **автоматически** добавит их на **корневой элемент** компонента:

```html
<button class="btn" type="submit" disabled title="Сохранить">Сохранить</button>
```

Это и называется **наследование атрибутов** (fallthrough attributes). Благодаря ему твой `BaseButton` ведёт себя как обычная кнопка: можно ставить любые атрибуты, и они «проваливаются» на `<button>`.

### `class` и `style` склеиваются

```vue
<BaseButton class="wide">Купить</BaseButton>
```

```html
<button class="btn wide">Купить</button>
```

Класс родителя **добавится** к классу ребёнка, а не заменит его. Так же со `style`.

### Обработчики событий тоже проваливаются

```vue
<BaseButton @click="buy">Купить</BaseButton>
```

Если `click` **не** объявлен в `defineEmits`, обработчик повесится на `<button>` как обычный обработчик DOM. Поэтому `@click` на `BaseButton` «просто работает», хотя ты нигде не писала `emit('click')`.

⚠️ А если **объявить** `click` в `defineEmits`, но не отправлять его — клик перестанет работать: Vue будет ждать `emit('click')` от компонента. Это ловушка из дня 3: объявляй только те события, которые действительно отправляешь сама.

## Часть 2. `inheritAttrs` и `$attrs`

### Когда атрибуты должны попасть не на корень

```vue
<!-- FieldText.vue -->
<template>
  <label class="field">          ← корень
    <span>{{ label }}</span>
    <input v-model="model">      ← а placeholder нужен сюда!
  </label>
</template>
```

```vue
<FieldText v-model="city" label="Город" placeholder="Казань" />
```

`placeholder` провалится на `<label>`, где он бесполезен. Нужно отключить автоматическое наследование и передать атрибуты **вручную** куда нужно:

```vue
<script setup>
defineOptions({ inheritAttrs: false })
defineProps({ label: String })
const model = defineModel()
</script>

<template>
  <label class="field">
    <span>{{ label }}</span>
    <input v-model="model" v-bind="$attrs">
  </label>
</template>
```

- `defineOptions({ inheritAttrs: false })` — «не вешай атрибуты на корень сам»;
- `$attrs` — объект со всеми **не-props** атрибутами, которые передал родитель;
- `v-bind="$attrs"` — повесить их все на нужный элемент (`v-bind` без аргумента, день 2 недели 1).

Если `$attrs` нужен в скрипте, есть `useAttrs()` из `'vue'`.

### ⚠️ Несколько корневых элементов

```vue
<template>
  <label>…</label>
  <p class="hint">…</p>
</template>
```

Если в шаблоне **два и больше** корневых элементов, Vue не знает, куда вешать атрибуты, и выдаст предупреждение: *Extraneous non-props attributes were passed…* Решения: обернуть всё в один элемент или явно указать `v-bind="$attrs"` на нужном.

## Часть 3. `provide` / `inject` — данные «через этажи»

### Проблема: «пробрасывание props»

```
App            ← знает валюту '₽'
└── ShopPage
    └── ProductList
        └── ProductCard     ← нужна валюта
```

Чтобы передать валюту из `App` в `ProductCard`, пришлось бы объявить prop `currency` в `ShopPage` и `ProductList`, хотя им самим она не нужна. Это называют **prop drilling** — «сверление props». Утомительно и засоряет компоненты.

### Решение: `provide` и `inject`

```vue
<!-- App.vue (предок) -->
<script setup>
import { provide } from 'vue'

provide('currency', '₽')
</script>
```

```vue
<!-- ProductCard.vue (потомок на любом уровне) -->
<script setup>
import { inject } from 'vue'

const currency = inject('currency')
</script>

<template>
  <p>{{ price }} {{ currency }}</p>
</template>
```

- `provide('ключ', значение)` — предок **предоставляет** значение всем потомкам;
- `inject('ключ')` — любой потомок **получает** его, сколько бы этажей ни было между ними.

Промежуточные компоненты ничего об этом не знают.

### Реактивное значение

Если передать `ref`, потомки увидят изменения:

```js
// App.vue
const theme = ref('light')
provide('theme', theme)
```

```js
// глубоко внизу
const theme = inject('theme')   // это тот же ref
```

```vue
<div :class="theme">...</div>
```

### Значение по умолчанию

```js
const currency = inject('currency', '₽')   // если никто не предоставил — '₽'
```

### ⚠️ Правила хорошего тона

- **Менять** данные из `inject` в потомке не стоит: хозяин — предок. Если потомок должен что-то изменить, предок предоставляет **функцию** для этого:
  ```js
  provide('theme', { theme, toggleTheme })
  ```
- `provide` / `inject` — для **общих настроек**: тема, валюта, язык, текущий пользователь. Для обычной передачи данных ребёнку — по-прежнему props: они явные, и по коду видно, откуда что пришло.
- Для **общего состояния всего приложения** (корзина, список привычек) на неделе 6 будет Pinia: она удобнее `provide` / `inject` для таких задач.

### Шаг 4. Пиши снизу вверх

Сначала самый простой «лист» (`ShoppingItem`) с захардкоженными props, проверь. Потом родителя, который передаёт настоящие данные. Потом форму.

### Базовые компоненты

`BaseButton`, `BaseInput`, `BaseModal` — «базовые» компоненты: они ничего не знают о покупках, это просто красивые кнопки и поля. Их переиспользуют по всему приложению. Принято называть их с префиксом `Base` (или `App`, `Ui`) и класть в `components/` или `components/base/`.

### ⚠️ Когда компонент — лишний

Не нужно делать компонент из каждого `<p>`. Хорошие признаки, что кусок стоит вынести:
- он **повторяется** (карточка, строка списка);
- у него есть **своё** состояние или логика (форма с полем);
- родитель стал **слишком длинным** и его трудно читать.

# Занятие 3. 📜 Options API и итоги недели

## Часть 5. 📜 Атрибуты и `provide` / `inject` в Options API

### `inheritAttrs` и `$attrs`

**Composition API:**

```vue
<script setup>
defineOptions({ inheritAttrs: false })
</script>

<template>
  <input v-bind="$attrs">
</template>
```

**Options API:**

```vue
<script>
export default {
  inheritAttrs: false,
}
</script>

<template>
  <input v-bind="$attrs">
</template>
```

`inheritAttrs` — обычная опция компонента. `defineOptions` в `<script setup>` нужен именно для таких опций, которым нет отдельного макроса. В скрипте Options API атрибуты доступны как `this.$attrs`.

### `provide` и `inject`

**Composition API:**

```js
// предок
provide('currency', '₽')
// потомок
const currency = inject('currency')
```

**Options API:**

```js
// предок
export default {
  provide: {
    currency: '₽',
  },
}

// потомок
export default {
  inject: ['currency'],
  // теперь доступно this.currency и {{ currency }} в шаблоне
}
```

### ⚠️ `provide` с данными компонента — функция

Если нужно предоставить что-то из `data()`, `provide` пишут **функцией**, чтобы был доступ к `this`:

```js
export default {
  data() {
    return { theme: 'light' }
  },
  provide() {
    return {
      theme: this.theme,   // ⚠️ НЕ реактивно — потомки получат 'light' навсегда
    }
  },
}
```

⚠️ В Options API значение из `data`, переданное так, **не будет реактивным**. Чтобы потомки видели изменения, используют `computed` из `'vue'`:

```js
import { computed } from 'vue'

export default {
  data() {
    return { theme: 'light' }
  },
  provide() {
    return {
      theme: computed(() => this.theme),   // ✓ реактивно
    }
  },
}
```

Это одно из мест, где Options API сложнее Composition API. Если в рабочем коде «тема не обновляется у потомков» — проверь именно это.

### `inject` со значением по умолчанию

```js
inject: {
  currency: { default: '₽' },
},
```
